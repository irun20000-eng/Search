# n8n으로 첫 자동화 워크플로우 만들기

> 이 가이드는 n8n을 한 번도 안 써 본 사람이 계정 만들기부터 **직접 돌아가는 워크플로우 하나**를 완성하기까지를 따라가게 만든 것이다. 약 40분.

## 이 가이드로 만들 것

**"정해진 시간마다 자동으로 실행돼서, 데이터를 가져와 원하는 모양으로 바꾸는"** 워크플로우 하나를 만든다.

구조는 세 덩어리다. 이 세 덩어리는 앞으로 만들 거의 모든 자동화의 뼈대가 된다.

```
[트리거]  →  [가공]  →  [출력]
언제 돌지    데이터를    어디에
정한다       손본다      내보낼지
```

이 가이드를 끝내면 다음을 할 수 있다.

- 트리거를 골라 워크플로우를 **원하는 시점에** 돌린다
- 노드 사이를 흐르는 **데이터 모양(JSON)** 을 읽는다
- 실행 결과를 보고 **어디서 틀어졌는지** 짚는다

반대로 이 가이드가 다루지 않는 것: AI 에이전트 노드, 외부 서비스 인증(OAuth) 연결, 자체 서버 설치. 그건 아래 "다음으로 할 것"에서 이어진다.

## 사전 준비물

| 항목 | 설명 |
|---|---|
| 이메일 계정 | n8n Cloud 가입용 |
| 웹 브라우저 | 크롬·엣지·사파리 아무거나 |
| 시간 | 약 40분 |

설치할 것은 없다. **n8n Cloud로 시작하는 것을 권한다.** n8n Cloud는 n8n 쪽에서 인프라를 전부 관리해 주는 완전 관리형 서비스다[1].

무료 체험 조건은 이렇다 — **2026-08-08 확인** 기준이다[6][7].

| 항목 | 내용 |
|---|---|
| 기간 | **14일** |
| 신용카드 | **불필요** |
| 쓸 수 있는 기능 | Pro 플랜 기능 (컴퓨팅은 Starter 수준) |
| **실행 횟수** | **1,000회** — 이 숫자를 기억해 둬라 |
| 만료 | 자동 만료, 별도 취소 불필요 |

**실행 1,000회 제한이 이 가이드에서 실질적으로 중요하다.** 뒤에서 스케줄 트리거를 다루는데, 5분마다 도는 워크플로우를 켜 두고 잊으면 며칠 만에 체험분이 사라진다. 6단계에서 다시 짚는다.

자체 서버(셀프 호스팅) 설치는 도커 등을 다뤄야 해서 첫 단추로는 부담이 크다[9]. 지금은 **자동화 개념을 익히는 게 목적**이니 설치는 나중으로 미룬다.

## 1단계 — 계정 만들고 캔버스 열기

**할 일**
1. n8n Cloud에 가입한다. 이메일 인증을 마치면 작업 공간이 만들어진다.
2. 새 워크플로우를 만든다. 빈 캔버스가 열린다.

**화면에서 확인할 것**
가운데가 텅 빈 캔버스이고, 노드를 추가하는 **+ 버튼**이 보인다[1]. 이 + 가 모든 것의 시작점이다.

**막히면**
가입 직후 작업 공간 준비에 몇십 초 걸릴 수 있다. 화면이 비어 보이면 새로고침한다.

> **버전에 따라 버튼 위치·이름이 다를 수 있다.** n8n은 업데이트가 잦다. 이 가이드는 "무엇을 하는 버튼인지"를 기준으로 썼으니, 라벨이 조금 달라도 역할이 같은 것을 찾으면 된다.

## 2단계 — ★트리거 고르기 (가장 중요한 선택)★

**할 일**
+ 를 눌러 첫 노드를 추가한다. 첫 노드는 반드시 **트리거**여야 한다.

트리거는 워크플로우의 시작 노드로, **언제 그리고 어떻게** 워크플로우가 실행될지를 정의한다[1].

트리거 종류는 여러 가지다 — 수동 실행, 스케줄, Webhook, Form, 앱 이벤트 등이 있다[2][3][4][8]. **이 가이드에서는 이 중 셋만 다룬다.** 나머지는 인증이나 외부 연동이 필요해 첫 연습에는 적합하지 않다.

| 트리거 | 언제 도는가 | 첫 연습에 |
|---|---|---|
| **수동 실행** | 내가 버튼을 누를 때. 주로 테스트·개발용이다[2] | ◎ 가장 적합 |
| **스케줄** | 정해진 간격·시각마다 반복[3] | ○ 6단계에서 |
| **앱 이벤트** | 연결한 외부 앱에서 특정 사건이 일어날 때[8] | △ 인증 필요 |

**지금은 수동 실행 트리거를 고른다.** 이유는 명확하다 — 스케줄로 걸어 두면 결과를 보려고 기다려야 하지만, 수동은 누를 때마다 즉시 돈다. **배우는 동안에는 피드백이 빠른 쪽이 압도적으로 유리하다.**

> **Webhook 트리거는 이 가이드 범위 밖이지만 알아 둘 값어치가 있다.** 워크플로우에 고유 URL이 생기고, 외부에서 그 주소로 요청이 오는 즉시 실행된다[4]. 실시간 연동에서 가장 많이 쓰인다. "다음으로 할 것"에서 이어진다.

**화면에서 확인할 것**
캔버스에 노드 하나가 놓이고, 실행 버튼이 활성화된다.

**막히면**
트리거가 아닌 일반 노드를 먼저 놓으면 워크플로우가 실행되지 않는다. 첫 노드가 트리거인지부터 확인한다.

## 3단계 — ★데이터의 모양과 실행 단위 이해하기★

여기가 이 가이드에서 가장 중요한 단계다. **대부분의 초보자가 여기를 건너뛰고 나중에 막힌다.**

**할 일**
1. 트리거 뒤에 데이터를 만들어 내는 노드를 하나 붙인다. 값을 직접 지정하는 노드(Set/Edit Fields 계열)가 연습에 좋다.
2. 필드를 두어 개 만든다. 예: `name` = `홍길동`, `score` = `90`.
3. 워크플로우를 실행한다.

**화면에서 확인할 것**
노드를 클릭하면 **입력(왼쪽) / 출력(오른쪽)** 패널이 보인다. 출력 쪽에 방금 만든 값이 나타나고, 표 보기와 JSON 보기를 전환할 수 있다.

**JSON 보기로 한 번 바꿔서 꼭 확인해라.** 대략 이런 모양이다.

```json
[
  { "name": "홍길동", "score": 90 }
]
```

바깥이 **대괄호(배열)** 라는 점이 핵심이다. n8n에서 노드끼리 주고받는 단위는 값 하나가 아니라 **아이템의 배열**이다.

**여기서 흔한 오해 하나를 미리 짚어 둔다.** "아이템이 3개면 뒤 노드가 무조건 3번 돈다"고 알기 쉬운데 **그렇지 않다. 노드와 설정에 따라 다르다.**

| 모드 | 동작 |
|---|---|
| Code 노드 **기본값** — `Run Once for All Items` | 아이템이 10개여도 **코드는 1회** 실행된다. `$input.all()` 로 전체를 받는다[5] |
| `Run Once for Each Item` 로 바꾸면 | 아이템마다 **따로** 실행된다. `$input.item` 으로 현재 항목을 받는다[5] |

정렬·필터·그룹·비교처럼 **항목끼리 견줘야 하는 일은 전체 모드**가 맞고, 항목이 서로 완전히 독립일 때는 개별 모드가 맞다[5].

**왜 이걸 먼저 보게 하는가** — 나중에 만나는 에러 상당수는 복잡한 기능 때문이 아니라 **데이터 모양과 실행 단위가 예상과 달라서** 생긴다. "왜 한 번만 돌지?" "왜 여러 번 돌지?"의 답은 대개 이 표에 있다.

**막히면**
출력 패널이 비어 있으면 아직 실행하지 않은 것이다. 실행부터 한다.

## 4단계 — 노드 이어 붙이고 값 가져다 쓰기

**할 일**
1. 노드를 하나 더 붙인다.
2. 새 노드의 입력값에 **앞 노드의 결과를 끌어다 쓴다.** 왼쪽 입력 패널의 필드를 오른쪽 입력칸으로 드래그하면 참조 식이 자동으로 들어간다.
3. 실행한다.

**화면에서 확인할 것**
직접 타이핑한 고정값이 아니라 **앞 노드에서 온 값**이 결과에 찍히는지 본다. 이게 되면 노드 연결의 기본을 익힌 것이다.

**막히면**
값이 안 나오고 참조식이 글자 그대로 보이면, 그 칸이 "고정값 모드"일 수 있다. 칸 옆의 고정/표현식 전환을 확인한다.

## 5단계 — 실행 기록으로 디버깅하기

**할 일**
일부러 틀리게 만들어 본다. 없는 필드 이름을 참조하도록 바꾸고 실행한다.

**화면에서 확인할 것**
- 실패한 노드에 **빨간 표시**가 뜬다
- 그 노드를 열면 입력에는 무엇이 들어왔고 출력이 왜 비었는지 보인다
- 실행 기록(Executions)에 이번 실행이 남는다

**이 습관 하나가 앞으로 시간을 가장 많이 아껴 준다.** 워크플로우가 안 돌 때 처음부터 다시 만들지 말고, **실패한 노드의 입력 패널부터 열어 본다.** 열에 아홉은 "들어온 데이터 모양이 예상과 다름"이다.

**막히면**
실행 기록을 지우지 마라. 실패한 실행은 나중에 다시 열어 볼 수 있다.

## 6단계 — 스케줄로 바꿔서 진짜 자동화 만들기

**할 일**
1. 트리거를 수동 실행에서 **스케줄**로 바꾼다. 스케줄 트리거는 정해진 간격·시각마다 워크플로우를 돌린다[3].
2. 주기를 정한다. 연습이면 짧게 두고 확인한 뒤 늘린다.
3. 워크플로우를 **활성화(Active)** 한다.

> **확인하고 나면 바로 주기를 늘려라.** 5분 주기는 하루 288회를 쓴다. 무료 체험 한도 **1,000회**[6] 기준으로 나흘이 채 안 돼 바닥난다.

**화면에서 확인할 것**
활성화 스위치가 켜져야 스케줄이 실제로 돈다. **꺼져 있으면 시간이 돼도 돌지 않는다.** 잠시 뒤 실행 기록에 자동 실행이 쌓이는지 확인한다.

**막히면**
- 활성화했는데 안 돈다 → 저장했는지 확인한다. 저장하지 않은 변경은 반영되지 않는다.
- 너무 자주 돈다 → 연습용 짧은 주기를 그대로 두면 실행 횟수를 금방 소진한다. 확인했으면 **바로 늘려라.**

여기까지 오면 세 덩어리(트리거 → 가공 → 출력)를 다 만져 본 것이다.

## 흔히 막히는 지점

**1. 첫 노드를 트리거로 안 놓음**
가장 흔하다. 워크플로우는 트리거에서 시작한다[1]. 일반 노드를 먼저 놓으면 실행 자체가 안 된다.

**2. 실행 단위를 잘못 짐작함**
노드 간 전달 단위는 **배열**인데, 그 배열을 뒤 노드가 통째로 한 번에 받는지 하나씩 나눠 받는지는 **노드와 설정에 달렸다**(3단계 표 참고). Code 노드 기본값은 전체를 한 번에 받는 쪽이다[5]. 실행 전에 **아이템 개수**와 **그 노드의 실행 모드**를 함께 확인하는 습관을 들인다.

**3. 활성화를 안 해서 스케줄이 안 돎**
저장 ≠ 활성화다. 둘 다 해야 한다.

**4. 템플릿을 그대로 가져와 쓰다 고치지 못함**
템플릿은 동작은 하지만 **왜 그렇게 생겼는지 모르면 고칠 수가 없다.** 예제로 시작하는 건 좋지만[10], 최소 한 번은 빈 캔버스에서 직접 조립해 봐야 한다.

**5. 연습용 짧은 주기를 방치**
무료 체험의 실행 한도는 **1,000회**다[6]. 5분마다 도는 워크플로우는 하루 288회를 쓰므로 **나흘이 채 안 돼 체험분이 바닥난다.** 동작을 확인했으면 즉시 주기를 늘리거나 비활성화한다.

## 다음으로 할 것

1. **외부 서비스 하나 연결하기** — 구글 시트나 슬랙 같은 걸 붙여 본다. 여기서 인증(자격 증명) 개념을 처음 만난다.
2. **Webhook 트리거 써 보기** — 워크플로우에 고유 URL이 생기고, 외부에서 그 주소로 요청이 오면 즉시 실행된다[4]. 다른 서비스와 실시간으로 붙일 때의 출발점이다.
3. **분기 넣기** — 조건에 따라 다른 길로 보내는 IF 노드를 써 본다.
4. **AI 노드 붙이기** — 데이터 흐름이 손에 익은 다음에 붙여야 한다. 순서를 바꾸면 두 배로 헤맨다.
5. **자체 서버 설치 검토** — 데이터를 내부에 둬야 하거나 실행량이 많아지면 그때 고민한다[9].
