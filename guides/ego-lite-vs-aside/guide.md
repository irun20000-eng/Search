# ego lite와 Aside 비교해 고르기 — 사용법, 장단점, 상황별 추천

> 이 가이드는 **AI 에이전트에게 내 로그인된 브라우저를 맡기는 두 도구, ego lite와 Aside를 각각 설치해 첫 작업을 시켜 보고, 같은 일을 양쪽에 맡겨 비교한 뒤 내 상황에 맞는 쪽을 고르는 것**까지 다룬다. 약 70분. 마지막 절에 「하나만 고른다면」에 대한 이 가이드의 답을 적었다.

## 이 가이드로 만들 것

- 두 도구를 설치하고 각각 **첫 작업 한 건**을 끝낸 상태
- 같은 일을 양쪽에 시켜 보고 적은 **나만의 비교 메모** 한 장
- 아래 「장단 비교표」와 「상황별 추천」을 내 조건에 대 본 **선택 결론**

한 문장으로 먼저 정리하면 이렇다. **Aside는 에이전트가 브라우저 안에 들어 있고, ego lite는 브라우저가 에이전트 바깥에 있다**[17]. Aside는 브라우저 자체에 에이전트를 넣어 말로 시키면 사이트를 직접 조작한다[7][21]. ego lite는 자체 AI가 없다. Claude Code·Codex·Cursor 같은 에이전트 CLI가 `ego-browser`라는 연결 계층을 통해 브라우저를 부린다[1][4].

| 구분 | ego lite | Aside |
|---|---|---|
| 만든 곳 | citrolabs. 크로미엄 기반이라고 소개된다[1][5] | Y Combinator 투자를 받은 스타트업[12] |
| 에이전트 | 없음 — 내 에이전트 CLI를 가져온다[1][4] | 브라우저에 내장. CLI·MCP로 외부 에이전트에 빌려줄 수도 있다[13][14] |
| 운영체제 | macOS(애플 실리콘·인텔)·Windows. 리눅스는 로드맵[1] | macOS 15.0 이상·Windows[8][9] |
| 계정 | 필요 없음[17] | 필요함[9][17] |
| 돈 | 무료[1][5] | Free 0달러(월 500 크레딧)·Pro 월 20달러·Max 월 200달러[10] |
| 공개 범위 | 저장소는 MIT, 브라우저 앱은 별도 무료 내려받기[1] | 비공개[17] |

## 사전 준비물

| 항목 | 설명 |
|---|---|
| PC | macOS 또는 Windows. 두 도구 모두 확인한 자료에 리눅스 지원은 없다[1][8][9] |
| 크롬 프로필 | 두 도구 모두 첫 실행 때 크롬 데이터를 가져올 수 있다[1][8][21]. 가져올 프로필을 미리 정해 둔다 |
| 에이전트 CLI | ego lite를 쓰려면 Claude Code·Codex·Cursor 같은 에이전트가 있어야 한다[1]. 자체 AI가 없어서다[4] |
| AI 구독(선택) | Aside는 이미 내는 ChatGPT·클로드 구독을 연결해 쓸 수 있고, 한 국내 사용기에 따르면 그러면 Aside 크레딧이 줄지 않는다[11][22] |

> **먼저 마음에 둘 것.** 두 도구 모두 **내 실제 로그인 상태**를 에이전트에게 넘긴다[1][7]. 편리함의 대가로 노출되는 범위가 넓다. 그래서 처음 써 볼 때는 은행·결제·업무 관리자 계정이 아니라 **잃어도 되는 계정만 로그인한 프로필**로 시작하는 편이 안전하다. 한 실사용 리뷰도 ego lite를 「인턴에게 넘겨도 되는 로그인만 남긴 전용 프로필」에서 쓰라고 권했다[3].

## 1단계 — 내 조건 점검표 만들기

**할 일**
1. 메모장에 아래 다섯 줄을 적고 각 줄에 내 답을 쓴다.
2. 답이 「예」인 줄이 어느 쪽 칸에 몰리는지 본다. 결론은 마지막 절에서 다시 맞춰 본다.

| 질문 | 「예」라면 기우는 쪽 | 근거 |
|---|---|---|
| Claude Code·Codex·Cursor를 이미 매일 쓰는가 | ego lite | 에이전트 CLI를 부르는 구조[1] |
| 터미널 없이 브라우저에 말로만 시키고 싶은가 | Aside | 자체 에이전트 내장[7] |
| 매일 같은 시각에 도는 반복 작업이 있는가 | Aside | 루틴 예약[11][22] |
| (에이전트 CLI를 이미 쓰면서) 브라우저 쪽 가입과 결제는 늘리고 싶지 않은가 | ego lite | 브라우저는 무료·계정 불필요[1][17]. 에이전트 CLI의 계정·요금은 따로다[4] |
| 리눅스나 서버(CI)에서 돌려야 하는가 | 둘 다 아니다 | 리눅스는 ego 로드맵[1], Aside는 맥·윈도우 앱[8][9] |

**화면에서 확인할 것**
다섯 줄 모두에 「예」나 「아니요」가 적혀 있어야 한다. 「잘 모르겠다」가 남은 줄은 2·3단계에서 직접 써 보고 채운다.

**막히면**
「둘 다 아니다」 줄이 「예」라면 이 가이드의 두 도구는 맞지 않을 수 있다. ego lite 리뷰 하나는 Windows·리눅스·CI에는 아직 맞는 선택이 아니라고 결론을 냈다[3]. 다만 그 리뷰는 9월 것이고, 지금 README는 Windows를 지원 목록에 올렸다[1]. 날짜를 같이 본다.

## 2단계 — ego lite 설치하고 첫 작업 시키기

**할 일**
1. 설치 방법 세 가지 중 하나를 고른다[1].
   - **앱 직접 받기**: README의 다운로드 링크나 공식 사이트에서 macOS(애플 실리콘·인텔)용 DMG 또는 Windows용 EXE를 받는다.
   - **스킬부터 깔기**: 터미널에서 아래 한 줄을 실행한다. 그 뒤 에이전트가 처음 브라우저 일을 할 때 앱 설치를 안내한다.
   - **에이전트에게 맡기기**: 에이전트에게 저장소 주소를 주고 설치해 달라고 한다. macOS에서는 설치 스크립트가 DMG를 받아 응용 프로그램 폴더에 넣고, 격리(quarantine) 속성을 지워 게이트키퍼 차단을 푼다[2].
2. 앱을 처음 열면 **크롬 데이터를 옮길지** 하나만 묻는다. 「예」를 고르면 로그인·쿠키·확장 프로그램·북마크를 이어받는다[1][2].
3. 온보딩이 끝나면 `ego-browser` 명령이 PATH에 등록된다. macOS는 보통 `~/.local/bin` 이다[2].
4. 에이전트에서 스킬을 불러 첫 일을 시킨다. 처음에는 **읽기만 하는 일**로 고른다.

```bash
# 「스킬부터 깔기」를 고른 경우만 — 앱을 직접 받았다면 앱이 스킬을 깔아 준다 [1]
npx skills add citrolabs/ego-lite        # ego-browser 스킬 설치 [1]
command -v ego-browser                   # 명령이 PATH에 있는지 확인 (macOS·Bash/Zsh) [2]
# Windows PowerShell: Get-Command ego-browser   ·   cmd: where ego-browser [2]
ego-browser skill                        # 사용법 안내를 출력 — 에이전트는 이것을 읽고 따른다 [2]
```

Claude Code 대화창에서 이렇게 시킨다. README는 에이전트 CLI에서 `/ego-browser` 뒤에 한 칸 띄우고 할 일을 평범한 말로 쓰라고 안내한다[1].

```text
/ego-browser 내가 로그인해 둔 유튜브에서 구독 채널 최신 영상 제목 5개만 읽어 와줘. 아무것도 누르지 말고.
```

**화면에서 확인할 것**
에이전트는 내 탭이 아니라 **별도 Space** 에서 일한다. 마우스도 내가 둔 자리에 그대로 있다[1]. 작업을 여러 개 맡기면 각자의 Space에서 동시에 돈다[1][20]. 브라우저에서 어느 Space에 에이전트가 돌고 있는지 보이고, 언제든 넘겨받거나 멈출 수 있다[1]. 에이전트가 쓰는 도구는 snapshot·fill·click·wait·navigate·capture 같은 것이다. 에이전트가 이 도구들을 부르는 자바스크립트를 쓰면 `ego-browser` 가 페이지에서 한 번에 실행한다[1].

**막히면**
- **macOS에서 앱이 안 열린다** — 시스템 설정 → 개인정보 보호 및 보안에서 허용해야 할 수 있다[2].
- **Windows에서 경고가 뜬다** — SmartScreen에서 「추가 정보(More info)」 → 「실행(Run anyway)」을 누르라고 안내한다[2]. 설치 뒤 PATH는 **새 터미널부터** 적용되니 터미널을 새로 연다[2].
- **로그인했는데 「not logged in」이라고 한다** — 크롬 프로필을 둘 이상 가져왔다면 에이전트가 엉뚱한 프로필을 받았을 수 있다. 한 리뷰어는 프로필 이름을 지정해서 해결했다[3].
- **Claude Code가 명령마다 멈칫하며 느리다** — ego lite는 셸 히어독 안에 자바스크립트를 넣는 방식이라 Claude Code 기본 권한 모드의 셸 검사에 걸린다. 이 때문에 같은 작업이 76초 대 40초로 느려졌다는 측정이 있다. ego 문서는 전체 접근(Full access)을 권하고, 리뷰어는 Claude Code를 권한 우회 모드(`--dangerously-skip-permissions`)로 돌렸다[3]. **이 모드는 브라우저만이 아니라 파일 수정·명령 실행을 포함한 도구 호출 대부분의 확인과 안전 검사를 끈다**(거부 규칙 같은 일부는 남는다). 공식 문서는 컨테이너나 VM처럼 망가져도 되는 격리 환경에서만 쓰라고 하고, 프롬프트 인젝션도 막아 주지 않는다고 적는다[24]. 확인 창을 줄이고 싶으면 우회 모드보다 분류기가 대신 검토하는 auto 모드를 먼저 본다[24]. 입문자는 **기본 모드에서 느린 채로 쓰는 쪽**을 권한다. 굳이 켠다면 중요한 파일이 없는 빈 작업 폴더에서만 켜고, 끝나면 되돌린다. 전용 크롬 프로필은 이 위험을 줄여 주지 않는다.
- **이미 깔려 있는데 오래된 판이다** — `ego-browser upgrade` 로 올린다. 설치 안내는 이 명령을 실행하기 전에 사용자 승인을 먼저 받으라고 적어 둔다[2].

## 3단계 — Aside 설치하고 첫 작업 시키기

**할 일**
1. aside.com에서 내 운영체제에 맞는 앱을 받는다. macOS는 15.0 이상이어야 한다[8]. Windows판은 2026년 9월 14일 공개됐다. 공동창업자는 맥판 기능의 99%를 담았다고 밝혔다[9].
2. 앱을 열고 **계정을 만들거나 기존 계정을 연결한다**[9].
3. 공식 온보딩은 **설치 → 가져오기 → 첫 작업** 세 단계다[8]. 가져오기에서 크롬 데이터와 비밀번호를 옮긴다[8][21].
4. (선택) 설정에서 내 ChatGPT·클로드 구독을 연결한다. 한 국내 사용기에 따르면 크레딧은 **Aside 자체 모델을 쓸 때만** 줄어든다[11]. 구독 연결 화면은 영상에서 볼 수 있다[22].
5. 사이드 패널에 2단계와 같은 일을 말로 시킨다.

```text
내가 로그인해 둔 유튜브에서 구독 채널 최신 영상 제목 5개만 읽어 와줘. 아무것도 누르지 말고.
```

**화면에서 확인할 것**
새 탭에는 검색과 Ask AI가 있고, 옆에 사이드 패널·채팅 목록·설정 메뉴가 있다[21]. 결제·게시·메시지 같은 **민감한 작업은 사용자 확인을 기다리고**, 사용 내역이 기록된다[7]. Aside는 저장된 비밀번호를 에이전트에 건네지 않는다. 로그인 화면에서 대상 주소를 확인한 뒤 자동 입력만 하게 한다[15]. 무료 플랜은 월 500 크레딧이다. 한 사용 후기에서는 작업 두 건을 돌린 뒤 96%가 남았다[16]. 다만 작업 크기에 따라 소모가 크게 다를 수 있으니 한 사람의 기록으로만 읽는다.

**막히면**
- **크레딧이 생각보다 빨리 줄어든다** — 구독 연결 없이 Aside 자체 모델로 돌린 것이다. 4번의 구독 연결을 하면 Free로도 실사용이 된다[11].
- **카카오 같은 사이트 로그인에서 멈춘다** — 보안문자와 세션 끊김 때문에 게시 자동화가 실패한 기록이 있다[14]. 그 단계는 사람이 직접 처리한다.
- **Windows에서 메뉴가 영상과 다르다** — Windows판은 따로 기술 사양이나 기능 목록을 내지 않았다[9]. 맥판 기준 자료와 버튼 위치가 다를 수 있다.

## 4단계 — 같은 일을 두 쪽에 시켜 보고 비교 메모 쓰기

**할 일**
1. 「로그인해야 보이는 페이지에서 정보를 읽어 표로 정리하기」 하나를 골라 양쪽에 똑같이 시킨다.
2. 아래 표의 빈칸을 내 결과로 채운다. 숫자는 대충 재도 된다.

| 비교 항목 | ego lite | Aside |
|---|---|---|
| 어디서 시켰나 | 에이전트 대화창[1][18] | 브라우저 사이드 패널[21] |
| 끝날 때까지 걸린 시간 | (내 측정) | (내 측정) |
| 내 탭이 방해받았나 | (관찰) | (관찰) |
| 중간에 멈추고 넘겨받기 | Space에서 넘겨받거나 멈춤[1] | 민감 작업은 확인 대기[7] |
| 돈 | 무료[1]. 에이전트 쪽 토큰 비용은 따로 | 크레딧, 또는 내 구독[10][11] |

**화면에서 확인할 것**
같은 일인데 결과 표의 칸 수나 빠진 항목이 다를 수 있다. 차이가 나면 「어느 쪽이 페이지를 덜 읽었나」를 본다. ego lite 리뷰 하나는 복잡한 깃허브 페이지의 스냅숏이 약 14k 토큰이었다. 마케팅이 말한 200~400 토큰과 거리가 있었다[4].

**막히면**
속도를 비교하려면 한 번 잰 값으로 결론 내지 않는다. 한 제작자가 같은 맥에서 두 도구를 직접 쟀다(2026-09-17, macOS 26.5.2, 애플 실리콘, 같은 네트워크)[17]. 같은 자바스크립트로 9회 돌린 단일 작업 중앙값은 ego-browser 348ms, Aside repl 644ms로 ego lite가 1.85배 빨랐고 9회 모두 성공했다. 그런데 **동시 작업 수를 늘리자 순서가 뒤집혔다.**

| 동시 작업 수 | ego lite | Aside |
|---|---|---|
| 1개 | 374ms | 554ms |
| 2개 | 676ms | 569ms |
| 4개 | 1,611ms | 780ms |
| 8개 | 3,057ms | 1,856ms |

같은 측정에서 2개부터 Aside가 앞섰다[17]. 한 사람이 한 기기에서 잰 값이다. 개발사들의 주장은 따로 있다. ego lite는 31개 실제 작업 벤치마크에서 다른 도구보다 47~63% 빠르다고 적었다[1]. 이 수치는 벤더 자체 측정이다[6]. 한 리뷰어는 ego lite의 속도 배수가 README와 중국어 문서 사이에서 서로 맞지 않는다고 지적했다[4].

## 5단계 — Claude Code에서 둘 다 불러 보기

**할 일**
1. ego lite는 2단계의 스킬로 이미 붙어 있다. `/ego-browser` 로 부른다[1].
2. Aside는 CLI를 깔고 MCP 서버로 등록한다. `aside mcp` 를 실행하면 Aside가 다른 에이전트에 붙는 MCP 서버가 된다[13]. 그 서버는 exec와 repl 두 도구를 갖는다[14].

```bash
claude mcp add aside -- ~/.local/bin/aside mcp   # Aside를 Claude Code의 MCP 서버로 등록 [14]
```

3. 같은 일을 이번에는 Claude Code에서 두 경로로 시켜 본다.

**화면에서 확인할 것**
Claude Code 세션에서 `/mcp` 로 MCP 패널을 열어[23] aside 서버가 연결됐는지 확인한다. ego lite 쪽은 에이전트가 `ego-browser` 명령을 셸로 실행하는 것이 보인다[1][3]. 즉 **Aside는 「혼자 쓰는 브라우저」와 「에이전트에 빌려주는 브라우저」 두 역할을 다 하고**[13][21], ego lite는 평소 브라우저로는 쓸 수 있지만[1][18] AI에게 일을 시키려면 바깥 에이전트가 있어야 한다[4].

**막히면**
- **aside 명령을 못 찾는다** — 설치 위치가 다르면 `~/.local/bin/aside` 대신 실제 경로를 넣는다[14].
- **ego lite 스크린숏이 이상한 값으로 온다** — 캡처 함수는 base64가 아니라 임시 파일 경로를 돌려준다. 페이지가 바뀌면 스냅숏 참조가 만료되니 동작 전마다 스냅숏을 새로 받는다[4].

## 6단계 — 내 결론 내리고 안전장치 걸기

**할 일**
1. 1단계 점검표와 4단계 비교 메모를 나란히 놓고 아래 「상황별 추천」에서 내 줄을 찾는다.
2. 고른 도구에 다음 세 안전장치를 건다.
   - **전용 프로필**: 필요한 로그인만 남긴다[3].
   - **비밀번호와 인증 코드는 대화창에 치지 않는다**: 사이트가 로그인이나 보안문자를 요구하면 그 단계는 브라우저에서 사람이 직접 처리한다. 보안문자 앞에서 자동화가 실패한 기록이 있다[14].
   - **만드는 단계와 제출하는 단계를 가른다**: 게시·결제·전송은 사람이 마지막에 누른다[7][14].

**화면에서 확인할 것**
고른 도구의 브라우저 창에 업무 관리자나 금융 계정의 로그인이 남아 있지 않아야 한다.

**막히면**
ego lite를 골랐다면 Space가 「격리된 공간」이라는 말을 쿠키 수준까지 믿지 않는다. 한 리뷰어의 시험에서 작업 Space끼리 쿠키가 분리되지 않았다. 프로젝트 이슈 트래커에도 작업 Space가 사용자 쿠키를 지워 버렸다거나 다른 프로필의 쿠키를 통째로 돌려줬다는 보고가 열려 있다[3]. 에이전트가 들른 페이지에 프롬프트 인젝션이 있으면 그 공격이 내 세션 쿠키에 닿을 수 있다는 경고도 같은 리뷰에 있다[3].

## 하나만 고른다면

**이 가이드의 답은 Aside다.** 단, 이미 Claude Code를 매일 쓰는 사람이라면 ego lite부터 깔아 보라. 아래는 작성자의 판단이고, 각 근거에는 출처를 달았다.

이 가이드는 입문자를 기준으로 썼다. 그 기준에서 Aside를 고른 이유는 네 가지다.
1. **혼자서 완결된다.** 에이전트가 들어 있어 다른 도구 없이 첫날부터 쓴다[7][21]. ego lite는 에이전트 CLI와 그 사용료가 따로 있어야 한다[4].
2. **두 역할을 다 한다.** 나중에 Claude Code를 배우면 같은 Aside를 MCP로 붙일 수 있다[13][14]. 반대로 ego lite는 평소 브라우저로는 쓸 수 있어도[1][18] AI에게 일을 시키려면 바깥 에이전트가 있어야 한다[4].
3. **안전장치가 기본으로 켜져 있다.** 비밀번호를 에이전트에 넘기지 않고, 민감한 작업은 확인을 기다린다[7][15]. ego lite는 권한을 넓히라는 안내[3](그 모드의 위험은 [24])와 쿠키 격리 의문[3]이 입문자에게 부담이다. 다만 공평하게 적어 둔다. Aside의 안전장치는 공식 설명 기준이고 이번에 독립 시험은 찾지 못했다. ego lite의 쿠키 문제는 독립 리뷰의 시험 결과다.
4. **무료로도 시작한다.** Free 플랜이 있고[10], 한 국내 사용기에 따르면 이미 내는 구독을 연결하면 크레딧이 줄지 않는다[11].

**ego lite로 뒤집히는 조건.** 아래 셋 중 둘 이상이 맞으면 ego lite가 더 낫다. 첫째, Claude Code·Codex·Cursor를 이미 매일 쓴다. 둘째, 브라우저 쪽에는 계정과 크레딧을 더하고 싶지 않다. 셋째, 짧은 작업을 빠르게 많이 돌린다[1][17]. 이 경우에도 전용 프로필과 사람의 마지막 확인은 그대로 둔다[3].

지원 운영체제는 이 몇 달 사이에도 바뀌었다(ego lite Windows[1][3], Aside Windows[9]). 이 결론은 **2026년 11월 1일 기준**이다.

## 흔히 막히는 지점

**1. ego lite를 깔았는데 아무 일도 안 한다**
ego lite에는 AI가 없다[4]. 브라우저 창에 말을 거는 것이 아니라 Claude Code 같은 에이전트에서 `/ego-browser` 로 시킨다[1].

**2. 크롬 프로필을 여러 개 가져와서 로그인이 안 된 척한다**
에이전트가 기본 프로필을 받았을 수 있다. 쓸 프로필을 지정한다[3].

**3. Aside 크레딧이 며칠 만에 바닥난다**
한 국내 사용기에 따르면 자체 모델로 돌릴 때 크레딧이 줄어들고, ChatGPT·클로드 구독을 연결하면 줄지 않는다[11].

**4. 보안문자 페이지에서 무한히 기다린다**
두 도구 모두 사람이 풀어야 하는 단계가 있다. Aside에서는 카카오 로그인 보안문자 때문에 실패한 기록이 있다[14]. 그 단계는 직접 처리하고 다시 시킨다.

**5. 속도 비교를 한 번 재고 끝낸다**
단일 작업과 동시 작업에서 순위가 뒤집힌 측정이 있다[17]. 내 실제 작업 모양으로 몇 번 재 본다.

**6. 예전 자료를 보고 「ego lite는 맥 전용」이라고 단정한다**
2026-09-10 리뷰와 9월 초 영상 설명을 비롯한 이전 자료들은 맥 전용으로 적었다[3][4][20]. 지금 README는 Windows를 지원하고 설치 파일 링크를 둔다[1]. 10월 영상도 macOS와 Windows에서 무료라고 소개한다[19].
