# 루틴 지침 — 카드뉴스 주간 제작 (Search 전용)

> 사용법: 이 파일 전체(또는 아래 한 줄)를 **claude.ai/code → Routines** 지침란에 붙여넣고,
> 대상 리포 `irun20000-eng/Search`, 주기 주 1~2회(예: 화·목 아침 9시)로 등록.
> 한 줄 버전: `Search 리포의 routines/cardnews-weekly.md 지침을 그대로 수행해줘. 만들 게 없으면 "이번 회차 제작 없음"만 보고.`
>
> **이 루틴은 카피를 쓰고 머지까지 한다. 렌더만 GitHub Actions 가 한다.**
> 로컬 PC 의 한글 폰트가 기존 편을 렌더한 것과 달라(지침: "21편부터 카드 질감이 갈린다")
> 렌더 환경을 러너로 고정했다. 루틴이 렌더를 시도하지 말 것.
>
> **제작 규칙의 정본은 `studio/CLAUDE.md`** 다. 이 문서와 어긋나면 그쪽이 이긴다.

당신은 `irun20000-eng/Search` 가 체크아웃된 클라우드 에이전트입니다. 회차마다
**한 편**을 끝까지 발행합니다 — 카피 작성 → 브랜치 push → (러너가 렌더) →
컷 확인 → PR → **머지** → **라이브 반영 확인** → 보고. 중간에서 멈추지 않습니다.

## 0. 먼저 읽을 것

1. `studio/CLAUDE.md` — 절대 규칙 6조 · 10장 구조 · 카피 길이 · 실패 교훈
2. `cardnews/cardnews.yaml` 의 `production.concept_pool` — 다음 차례
3. `LESSONS.md` 의 방지 규칙 체크리스트
4. 학습자료를 함께 쓸 편이면 — `PIPELINE.md`(수집·무환각·측정 게이트 절차)와
   `tools/verify_concept.py` 머리말(하한의 근거)

## 1. 다음 차례 정하기

`cardnews/cardnews.yaml` 에서 고른다.

- `production.next_up.<시리즈>` 에 지정이 있으면 그것
- 없으면 `production.concept_pool.<시리즈>` 에서 상태가 **`다음`** 인 항목
- **`보류`·`검증필요` 상태로는 만들지 않는다**
- 시리즈는 `episodes[].date` 의 시리즈별 최댓값이 가장 오래된 쪽부터

레이아웃은 **A→B→C 회전**의 다음 차례다.

## 2. 카피 쓰기

`studio/CLAUDE.md` 의 10장 구조와 스키마를 그대로 따른다. 특히:

- **추측 수치·연구·랭킹·시장 데이터 창작 절대 금지.** 이 프로젝트에서 가장 큰 사고다.
  개념 구조·검증 가능한 산술·명명된 정리는 되고, 실제 통계·조사 결과·지어낸 인용은 안 된다.
- 가시 텍스트는 전부 한국어. 영문 UI 라벨 금지.
- 카피 길이는 플랜별로 다르다 — B(pill) 4~6자 · A(2단) 6~8자 · C(VS) 5~6자.
  **5번 대비 슬라이드가 제일 잘 터진다.**

## 3. 두 곳에 쓴다 — 하나만 쓰면 렌더가 멈춘다

| 파일 | 넣는 것 |
|---|---|
| `studio/contents/contents_<시리즈>.py` | `EPn = {...}` 카피 본문 + `EPISODES` 에 등록 |
| `cardnews/cardnews.yaml` 의 `episodes` | `folder` · `series` · `title` · `angle` · `layout` · **`date`** · `images[]` · `caption` |

> ⚠️ **`date` 는 필수다. 오늘 날짜(`YYYY-MM-DD`)를 넣는다.**
> 허브의 '최근에 올린 것' 과 갤러리 정렬이 이 값으로 돈다. 비워 두면 새 편이
> 목록에 아예 안 뜬다. `cardnews-sync` 워크플로가 date 없는 새 편을 발견하면
> 실패시킨다(옛 백필 16편만 `backfilled_no_date` 로 면제).

`folder` 는 `<시리즈>_<두자리>_<키워드>` (한글 그대로).
`images` 는 `<prefix><NN>.webp` 10개 — prefix 는 같은 시리즈의 직전 편을 따른다.

> ⚠️ **yaml 편 항목을 빠뜨리는 것이 가장 흔한 실수다.** 반입 스크립트가 이 경우
> 멈추고 "카피만 쓰고 편 항목을 빠뜨린 경우다" 라고 보고한다.

## 4. 직전 편 예고 갱신

같은 시리즈 **직전 편의 s10 `next`** 를 이번 편 제목으로 바꾼다.
각 편 마지막 장이 다음 편을 예고하는 구조이고, **가장 자주 빠뜨리는 단계**다.

## 4.5 학습자료(이해편)를 함께 쓴다 — 대상 편일 때만

이 편이 **개념노트 대상**이면 카피와 함께 이해편도 쓴다. 절차는 `PIPELINE.md` 의
주제 리서치와 같다 — 수집(국내+해외) → fact-ledger → 합성 → **측정 게이트** → 검수.
다른 것은 눈금뿐이다(카드 10장의 범위라 리서치 이해편보다 짧다).

### 대상인가 — 셋 다 맞아야 한다
1. **부모 노트가 아니다.** 부모 노트는 만들지 않는다(경험 기반 조언·심리 연구 재현성).
2. **검증 가능한 개념 핵이 있다.** 명명된 정리·문서로 확인되는 역사·직접 검산 가능한 산술.
   "열심히 하는데 왜 제자리일까" 같은 조언형은 핵이 없다 → 만들지 않는다.
3. **웹으로 확인할 수 있다.** 확인 못 하면 **안 만드는 것이 정답**이다(추측 금지).

### 어디에 쓰나 — 전부 리포다
| 파일 | 넣는 것 |
|---|---|
| `concept/notes/<슬러그>.md` | **프론트매터 + 본문.** 정본이다 |
| `studio/concepts/<슬러그>.py` | 개념 한 장 스펙 (`SPEC`) |

`concept/manifest.json` 은 손대지 않는다 — 워크플로가 `build_concept_manifest.py` 로 만든다.
옵시디언 볼트(`003-카드뉴스학습자료`)는 **사본**이며 `sync_obsidian.py` 가 없을 때만 내려보낸다.

슬러그는 제목의 괄호 안 영문에서 나온다 — `평균이라는 착시(Size Bias)` → `size-bias`.
그림은 **러너가 그린다**(`concept-sheet-render.yml`). 로컬에서 렌더하지 말 것.
그 워크플로가 그림 · manifest · 링크 인덱스 · 게이트를 한 번에 처리한다.

### 필수 골격
`# 제목 — 이해편` → `> 목표:` → `## TL;DR` → `## 핵심 포인트` → 본문 `## 1.`~ →
`## 다음 읽을 것` → `## 출처`(국내/해외) → `> 검증 메모` → `## 후속 질문·연결`

### 게이트 — 판단이 아니라 측정
```
python tools/verify_concept.py --vault <학습자료 폴더>
```
하나라도 미달이면 **PR 금지**. 하한은 기존 5편 실측 최저값이다.

| 항목 | 하한 |
|---|---|
| 글자수(공백 제외) | ≥ 5,400 |
| 줄수 | ≥ 165 |
| 섹션(`##`) | ≥ 12 |
| 시각화(표 행 + 코드블록) | ≥ 12 |
| 출처 국내 / 해외 | ≥ 2 / ≥ 3 |
| TL;DR · 핵심 포인트 · 다음 읽을 것 · 출처 · **검증 메모** | 전부 필수 |

### 어기기 쉬운 것 둘
- **출처는 연속 번호에 접두어**를 붙인다 — `1. (국내) …` `5. (해외) …`.
  국내/해외마다 번호를 재시작하면 본문의 `[n]` 이 어느 목록인지 기계가 못 가린다.
- **목록에만 올린 출처를 두지 말 것.** 본문에서 인용하지 않은 출처는 게이트가 경고한다.
  균형을 형식만 맞추는 것이라 실제로 2026-08-22에 네 편에서 적발됐다.

### 검증 메모에 반드시 적을 것
어떤 수치를 **어디서 언제 확인했는지**, 그리고 어떤 수치가 **설명용으로 지어낸 것인지**.
설명용 예시는 본문에도 명시한다(⚠️ 표시).

## 5. 브랜치에 올린다

```
브랜치명: claude/cardnews-<시리즈>-<EPn>      예) claude/cardnews-숫자노트-EP4
커밋:     카드뉴스 <시리즈> <EPn> 카피
```

`main` 에 직접 푸시하지 않는다. 브랜치에 올라가면 `cardnews-render.yml` 이
자동으로 렌더해 같은 브랜치에 컷을 커밋하고 PR 을 연다.

## 5.5 머지까지 하고 끝낸다 — 루틴의 일이다 (2026-08-27 사용자 지시)

**push 로 끝내지 않는다.** 예전 이 문서는 "사람이 모아보기를 보고 머지 버튼을 누른다"를
유일한 사람 게이트로 뒀는데, 실제로는 사용자가 그 버튼을 누르러 오지 않으면 갤러리가
며칠씩 옛 상태로 남았다(2026-08-27, EP3 가 그렇게 멈춰 있었다). 사용자 판단 —
**"내가 머지해야 한다면 자동화 의미가 없다."** 그래서 머지까지 루틴이 한다.

렌더 워크플로가 끝난 뒤 이 순서로 마무리한다.

1. **워크플로 결론을 확인한다.** push 했다는 사실은 컷이 나왔다는 뜻이 아니다.
   `git ls-tree origin/<브랜치> -- cardnews/assets` 로 컷 10장이 **실제로 있는지** 본다.
2. **컷을 눈으로 본다.** 자동검사는 규격·넘침·안전여백만 본다 — 지저분한 줄바꿈은 못 잡는다.
   webp 10장을 모아 한 장으로 붙여 직접 확인한다(사람 대신 보는 것이니 건너뛰지 말 것).
3. **PR 이 없으면 연다. `draft` 로 열지 않는다.** draft 는 머지 버튼이 비활성이라
   사람도 루틴도 머지할 수 없다. 이것 때문에 EP3 가 한 번 더 멈췄다.
4. **main 을 병합해 충돌을 먼저 없앤다.** 거의 항상 `link-index.json`·`backlog.json`
   둘이고 **빌드 산출물이다.** 손으로 병합하지 말고
   `git checkout origin/main -- link-index.json backlog.json` 후
   `python tools/build_link_index.py` 로 재생성한다(LESSONS 2026-08-25).
5. **게이트를 다시 돌리고**(`tools/verify_concept.py`) **squash 머지**한다.
6. **라이브에서 확인한다.** main 반영만으로는 부족하다. Pages 배포를 기다렸다가
   `https://irun20000-eng.github.io/Search/cardnews/manifest.json` 과
   `.../concept/manifest.json` 을 실제로 받아 이번 편이 들어 있는지 본다.
   **"머지했다"가 아니라 "라이브에 떴다"까지가 완료 1건이다**(CLAUDE.md 절대 규칙).

이상한 컷을 발견하면 머지하지 말고 카피를 줄여 다시 렌더한 뒤 머지한다.
머지한 뒤에 이상한 것이 보이면 되돌릴 수 있다 — 멈춰 세우는 것보다 낫다.

## 6. 보고

작업을 마치면 **PushNotification** 으로 알린다. 슬랙·카카오톡은 쓰지 않는다.

- 성공: `카드뉴스 <시리즈> <EPn> 발행 완료 — 머지·라이브 반영까지 확인`
  (`PR 곧 열림` 으로 끝내지 말 것. 머지·라이브 확인이 끝나야 성공이다 — §5.5)
- 학습자료를 함께 썼으면: `+ 이해편 <슬러그> (게이트 통과: 글자 N · 출처 국내N/해외M)`
- 대상인데 못 썼으면: `이 편은 개념노트 대상인데 <이유>로 못 썼습니다` — **조용히 넘기지 말 것**
- 만들 게 없음: `이번 회차 제작 없음 — 개념풀에 '다음' 항목이 없습니다`
- 막힘: 무엇이 막았는지 한 줄

**조용히 끝내지 말 것.** 이 파이프라인의 앞선 실패는 전부 "아무 일도 안 일어나서
몰랐던" 형태였다(2026-08-17 이후 동기화 루틴이 네 차례 빈손). 만들 게 없어도 보고한다.

## 7. 하지 말 것

- **렌더 시도 금지.** `python studio/cardnews.py render` 를 부르지 않는다. 폰트가 다르다.
- **시리즈에 종결 편을 만들지 말 것.** 네 시리즈 모두 무한 연재가 설계 의도다.
- **부모 노트는 학습자료(개념노트)를 만들지 않는다** — 경험 기반 조언·심리 연구 재현성 문제.
- **게이트를 통과 못 한 이해편으로 PR 을 열지 말 것.** 보강해 다시 재거나, 못 쓰겠으면 안 쓰고 보고한다.
- **개념 한 장을 로컬에서 렌더해 서가에 넣지 말 것.** 러너가 기준 환경이다.
- **카피 원본이 없는 편(부모 1~10 · 일머리 1)을 재렌더하지 말 것.** 발행본과 문구가 어긋난다.
- **`main` 직접 푸시 금지.** 반드시 브랜치 → PR → squash 머지로 간다(머지는 루틴이 한다, §5.5).
- **PR 을 `draft` 로 열지 말 것.** 머지 버튼이 비활성이라 루틴도 사람도 머지하지 못한다.
- **push 하고 끝내지 말 것.** 워크플로 결론·머지·라이브 반영까지 확인해야 완료다.

## 8. 이 뒤에 자동으로 일어나는 일

```
브랜치 push
  → cardnews-render.yml      폰트·크로미움 설치 → 렌더 10장 + 모아보기
                          → webp 변환 → cardnews/assets/ + manifest
                          → link-index 재생성 → 커밋 → PR 열기
  → 루틴이 컷을 눈으로 확인 → main 병합·충돌 해소 → squash 머지   ★ 2026-08-27 부터 루틴의 일
  → concept-sheet-render.yml (스펙·본문을 올린 경우) 개념 한 장 렌더 →
                             manifest · 링크 인덱스 · 게이트 → concept/ 커밋
                             ★ 갤러리에 바로 반영된다 (반입 단계 없음)
  → cardnews-sync.yml        main 반영 확인 → 개념노트 연결 검사 → Pages 배포
```

**사람이 할 일은 없다.** 루틴이 머지하고 라이브 반영까지 확인해 보고한다.
발행된 컷이 마음에 들지 않으면 그 편을 알려 주면 다음 회차에 카피를 줄여 다시 만든다.
