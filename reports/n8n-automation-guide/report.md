# n8n 완전 활용 가이드

> 앞서 다룬 **Zapier**가 "쉽고 앱 많은" 자동화의 대표라면, **n8n(엔에잇엔)**은 그 반대편의 강자다 — **오픈소스·셀프호스팅·AI 네이티브**. 노드를 드래그로 이어 워크플로우를 짜고, 원한다면 **내 서버에 무료로 돌리며**, LLM·벡터스토어·에이전트 노드로 **RAG 챗봇과 자율 AI 에이전트**까지 만든다 [8][12]. 결정적으로 과금 방식이 다르다 — Zapier가 '액션마다' 돈을 매길 때, n8n은 **'워크플로우 한 번 실행'을 1건으로** 센다 [10][11]. 이 글은 n8n이 **무엇이고, 왜 다르고, 어떻게 쓰는지(활용법)**를 실전 예시와 함께 정리한다.

## TL;DR
- **n8n = "노드를 잇는(nodes to nodes)" 오픈소스 워크플로우 자동화 도구.** 2019년 독일 베를린에서 시작, Node.js 기반의 **시각적 드래그앤드롭** 방식. Zapier·Make의 **셀프호스팅 가능한 대안**이다 [2][8][15].
- **결정적 차별 = 과금 방식.** Zapier는 **액션(태스크)마다** 과금하지만, n8n은 **워크플로우 실행[^실행] 1회를 1건으로** 센다. 노드가 5개든 20개든 한 번 돌면 1실행 → **복잡·대량 자동화에서 압도적으로 저렴** [10][11].
- **셀프호스팅[^셀프호스팅]하면 사실상 무료.** Docker로 내 서버에 올리면 **실행 횟수 제한 없이 무료**로 쓰고, **데이터가 밖으로 안 나간다**(보안·컴플라이언스) [2][7][15].
- **AI가 일급 시민.** **AI Agent 노드**[^에이전트](두뇌 LLM + 메모리 + 도구), 벡터스토어[^벡터], 문서 로더, 체인 노드로 **RAG**[^rag]·자율 에이전트를 시각적으로 조립한다 [6][9].
- **대신 문턱이 있다.** 노드·API 개념을 알아야 하고, 셀프호스팅은 직접 운영해야 한다. **기술을 조금 아는 사람·비용 절감·데이터 주권**이 목표라면 최선의 선택 [4][10].

## 핵심 포인트
1. **오픈소스·셀프호스팅**: 내 서버에 무료로, 데이터는 내 손안에 [2][7].
2. **실행 단위 과금**: 노드 수와 무관하게 워크플로우 1회 = 1실행 → 대량에 강함 [10][11].
3. **HTTP 노드로 무한 확장**: 기본 통합이 400~500개로 Zapier보다 적지만, **HTTP 노드로 모든 API**를 붙인다 [12][13].
4. **AI 네이티브**: LLM·에이전트·벡터스토어·RAG를 워크플로우 부품으로 [6][14].
5. **트레이드오프**: 유연·저렴·강력하지만 **기술 문턱·운영 부담**이 있다 [4][10].

## 1. n8n이란 무엇인가 — "노드를 잇는" 오픈소스 자동화

**n8n**은 이름부터 정체성이다 — **"nodes to nodes"**(노드에서 노드로)의 줄임말로, "엔에잇엔"이라 읽는다 [2][8]. 한 문장 정의:

> **n8n = 앱·API·AI 모델을 '노드'로 만들어 드래그앤드롭으로 잇는, 오픈소스이며 셀프호스팅 가능한 워크플로우 자동화 플랫폼.**

2019년 독일 베를린의 n8n GmbH가 만들었고, **Node.js 기반**이다 [2]. 화면에서 **블록(노드)을 선으로 연결**해 "이 앱에서 이걸 가져와 → 변환하고 → 저 앱에 넣어"라는 흐름을 그림처럼 짠다. Zapier·Make와 같은 계열이지만, 결정적으로 다른 세 가지가 있다.

- **① 오픈소스·셀프호스팅**[^셀프호스팅]: 소스가 공개돼 있고(페어코드[^페어코드] 라이선스), **내 서버(Docker)에 직접 올려 무료로** 돌릴 수 있다. 데이터가 밖으로 안 나간다 [7][15].
- **② 실행 단위 과금**: 뒤에서 자세히 보지만(§2·§8), 과금이 **'액션'이 아니라 '워크플로우 실행'** 기준이라 대량·복잡 자동화에서 훨씬 싸다 [10][11].
- **③ AI 네이티브**: LLM·AI 에이전트·벡터스토어·RAG가 **기본 부품**으로 들어 있다 [6].

국내 블로거들의 표현이 정확하다 — *"Zapier보다 저렴하면서 셀프호스팅까지 가능해 데이터 보안까지 책임지는 도구"*, *"셀프 호스팅하면 실행 횟수 제한 없이 무료"* [3][6].

## 2. Zapier와 무엇이 다른가 — 과금 방식이 갈림길

n8n을 이해하는 가장 빠른 길은 **Zapier와의 대조**다(짝 문서 [Zapier 가이드] 참고). 핵심은 **과금 철학**이다 [10][11].

| 구분 | **Zapier** | **n8n** |
|---|---|---|
| 과금 단위 | **태스크**(실행된 액션 1개 = 1) | **실행(execution)**(워크플로우 1회 = 1) |
| 5스텝 × 1,000회 | **5,000태스크** | **1,000실행** |
| 오픈소스 | ✕ | **○(페어코드)** |
| 셀프호스팅 | ✕ | **○(무료)** |
| 기본 통합 수 | 7,000+ | 400~500(+HTTP로 무한) |
| 난이도 | 매우 쉬움 | **중간(기술 요구)** |
| AI/RAG | AI Actions·Agents | **AI Agent·벡터스토어·RAG 네이티브** |

이 표의 **2번째 줄**이 전부다. Zapier는 **액션(태스크)마다** 과금하므로, 5단계 자동화를 1,000번 돌리면 **5,000태스크**가 나간다. n8n은 **워크플로우 한 번 실행을 1건**으로 세므로, 노드가 5개든 20개든 1,000번 돌면 **1,000실행**이다 [11].

결과적으로 **복잡하고 자주 도는 자동화일수록 n8n이 극적으로 싸진다.** 여러 비교가 **"Zapier에 월 $200 이상 쓰는 순간부터 n8n(특히 셀프호스팅)이 총소유비용에서 거의 항상 이긴다"**고 정리한다 [11]. 반대로 **월 $100 미만의 가벼운 사용**이라면 쉬운 Zapier가 여전히 합리적이다.

> **한 줄 감각**: **"쉽고 가볍게"면 Zapier, "저렴하게·대량으로·내 서버에서·AI까지"면 n8n.**

## 3. 작동 원리 — 노드·워크플로우·트리거

### 3-1. 노드(Node) = 작업 한 조각
n8n의 최소 단위는 **노드**[^노드]다. 노드 하나가 **하나의 작업**을 뜻한다 [8].
- **API 호출**(예: Gmail에서 메일 읽기)
- **데이터 변환**(형식 바꾸기, 필터링)
- **트리거**[^트리거](워크플로우 시작 신호)
- **흐름 제어**(조건 분기 If, 반복 Loop)
- **AI 추론**(LLM 호출, 에이전트 실행)
- **코드**(JavaScript·Python 직접 작성)

### 3-2. 워크플로우(Workflow) = 노드의 연결
노드를 **선으로 이어 붙인 것**이 **워크플로우**[^워크플로우]다. "트리거 노드 → 처리 노드들 → 액션 노드"로 흐른다. 예:
```
[트리거] 웹훅 수신(폼 제출)
   ↓
[If]   금액 ≥ 10만원?  ──아니오→ [종료]
   ↓ 예
[변환] 데이터 정리(포매팅)
   ↓
[액션] Google Sheets 기록  +  Slack 알림
```
Zapier와 달리 n8n은 **분기·병합·반복·에러 처리**를 노드로 시각적으로 그릴 수 있어, **복잡한 로직**에 강하다 [12][13].

### 3-3. 트리거 — 언제 시작하나
워크플로우를 시작시키는 방식은 여럿이다 [8].
- **스케줄**: "매일 9시" 정기 실행
- **웹훅**: 외부에서 신호가 오면
- **앱 이벤트**: "새 메일", "새 행" 등
- **수동/채팅**: 버튼·챗 입력으로

### 3-4. ★ HTTP 노드 — "통합 수가 적다"의 반전
n8n의 기본 통합은 **400~500개**로 Zapier(7,000+)보다 훨씬 적다 [11][12]. 언뜻 약점 같지만 반전이 있다 — **HTTP Request 노드**[^http]다. 이 노드로 **API가 있는 어떤 서비스든 직접 호출**할 수 있어, **사실상 연결 못 하는 앱이 없다**. 국내 서비스처럼 전용 통합이 없어도 HTTP 노드로 붙인다. "통합 수가 적다"는 **기술을 아는 사람에겐 사실상 무한대**가 되는 셈이다 [13].

## 4. AI·에이전트·RAG — n8n의 진짜 무기

2026년 n8n의 최대 강점은 **AI를 워크플로우 부품으로 다룬다**는 점이다. AI가 애드온이 아니라 **일급 시민(first-class primitive)**이다 [6][14].

### 4-1. AI Agent 노드 — 세 부품으로 조립
n8n의 **AI Agent 노드**[^에이전트]는 **자율 AI**를 시각적으로 만든다. 세 요소로 구성된다 [6][9].
- **두뇌(Brain)**: LLM 제공자 — OpenAI GPT, **Anthropic Claude**, 로컬 Ollama 등 자유 선택.
- **메모리(Memory)**: 단기·장기 대화 맥락 유지.
- **도구(Tools)**: LLM이 호출할 수 있는 능력 — HTTP 요청, 계산기, 코드, 위키피디아, **하위 워크플로우** 등.
- (여기에 트리거가 붙어 언제 작동할지 정함)

즉 *"질문이 오면 → 필요한 도구를 스스로 골라 쓰고 → 답한다"*는 에이전트를, 코드 없이 노드로 조립한다.

### 4-2. RAG — 내 문서로 답하는 챗봇
n8n은 **벡터스토어**[^벡터] 노드·문서 로더·체인 노드를 기본 제공해, **RAG**[^rag](검색 증강 생성) 파이프라인을 만든다 [6]. 흐름은:
```
[문서 로더] 사내 PDF·노션 → [임베딩] → [벡터스토어] 저장
                                          ↓
[챗 트리거] 질문 → [검색] 관련 문서 → [LLM] 근거 기반 답변
```
이걸로 **"우리 회사 문서만 보고 답하는 사내 지식 챗봇"**을 만든다. RAG 지식 도우미는 n8n의 대표 고가치 용도다 [14]. n8n은 **MCP 서버**에도 접속할 수 있어 외부 도구를 에이전트에 물릴 수 있다 [14].

> **정리**: Zapier가 자동화에 AI를 '얹는다'면, n8n은 **AI 에이전트·RAG 시스템 자체를 만드는 빌더**에 가깝다.

## 5. 설치·시작 — 클라우드 vs 셀프호스팅

n8n을 쓰는 길은 크게 둘이다 [15].

### 5-1. n8n Cloud (쉬움)
- 가입만 하면 바로 사용. **운영 부담 없음.**
- 유료(실행 단위, §8). 무료 체험 제공.
- **빠르게 시작·관리 안 하고 싶다**면 이쪽.

### 5-2. 셀프호스팅 (무료·강력)
- **Docker**[^도커]로 내 서버·PC에 설치 → **실행 무제한·무료**, 데이터 완전 통제 [7][15].
- 최소 예시(개념):
```bash
docker volume create n8n_data
docker run -it --rm -p 5678:5678 \
  -v n8n_data:/home/node/.n8n n8nio/n8n
# 브라우저에서 http://localhost:5678 접속
```
- AWS 등 클라우드 서버에 올리면 **24시간 나만의 자동화 서버**가 된다 [1][7].
- 단점: **직접 설치·업데이트·백업**을 해야 한다(약간의 기술 필요).

> **선택 팁**: 체험·비기술자는 **Cloud**, 비용 절감·데이터 주권·대량 실행은 **셀프호스팅**. 커뮤니티 전용 노드 일부는 **셀프호스팅에서만** 동작한다 [14].

## 6. 첫 워크플로우 만들기 (단계별)

1. **접속**: Cloud 로그인 또는 셀프호스팅 `localhost:5678` 접속.
2. **새 워크플로우** 생성 → **트리거 노드** 추가(예: Schedule 또는 Webhook, 또는 "Manual Trigger"로 테스트).
3. **처리/액션 노드 추가**: `+`로 노드 검색(예: Gmail → "Get Messages", 이어서 Slack → "Send Message"). 노드끼리 **선을 드래그**해 연결.
4. **자격 증명 연결**: 각 앱 계정을 한 번 등록(OAuth/API 키).
5. **데이터 매핑**: 앞 노드의 출력(발신자·제목 등)을 뒷 노드 입력 칸에 **드래그로 끼워 넣기**.
6. **실행·확인**: **Execute Workflow**로 테스트 → 각 노드의 입출력 확인 → 정상이면 **Active(켜기)**.

> **팁**: n8n은 **커뮤니티 템플릿**이 방대하다(수백 개). Gmail·Slack·Telegram·Notion·OpenAI용 **완성 워크플로우를 가져와** 수정하는 게 가장 빠른 학습법이다 [14].

## 7. 활용 예시 — 역할별 레시피

바로 응용할 수 있는 시나리오를 자동화·AI·RAG로 나눠 정리한다(국내·해외 사례 종합) [3][5][6][14].

### 7-1. 기본 업무 자동화
- **문의 처리**: *웹훅(폼) → 조건 분기 → Sheets 기록 + Slack 알림 + 확인 메일.* 다단계·분기가 있어도 **1실행**으로 처리 [5].
- **정기 리포트**: *매일 9시(Schedule) → 여러 API에서 지표 수집 → 요약 → 이메일/슬랙 발송.*
- **데이터 동기화**: *A DB의 새 레코드 → 변환 → B 서비스로 이관(양방향 가능).*

### 7-2. AI 자동화 비서
- **메일 자동 분류·답변 초안**: *새 메일 → LLM으로 분류(문의/영수증/기타) → 초안 생성 → 상신.* 코드 없이 LLM 노드로 [4].
- **콘텐츠 파이프라인**: *주제 입력 → LLM 초안 → 이미지 생성 → Notion 저장 → SNS 예약.*

### 7-3. AI 에이전트 (자율)
- **고객지원 에이전트**: *채팅 질문 → AI Agent(두뇌+메모리+도구) → FAQ 검색·주문 조회 도구 사용 → 답변.* [6][14]
- **리드 자격 판별**: *문의 → 에이전트가 정보 조사·점수화 → CRM 등록 + 담당자 알림.* 고가치 기업 용도로 꼽힌다 [14].

### 7-4. RAG 지식 챗봇
- **사내 문서 Q&A**: *사내 PDF·노션 → 벡터스토어 인덱싱 → 질문 시 관련 문서 검색 → 근거 기반 답변.* "우리 회사만 아는 챗봇" [6][14].
- **계약서 검토·인보이스 처리**: 문서 로더+LLM으로 추출·요약·분류 [14].

> **활용 설계 팁 3줄**: (1) **템플릿에서 시작**해 수정하라(맨땅 금지). (2) **에러 워크플로우**를 붙여 실패를 잡아라. (3) 민감 데이터는 **셀프호스팅+로컬 LLM(Ollama)**으로 밖에 내보내지 마라.

## 8. 요금·비용 — 실행 과금과 셀프호스팅 무료

n8n의 비용 구조는 **두 축**이다 [10][11][16].

| 방식 | 비용 | 특징 |
|---|---|---|
| **셀프호스팅(커뮤니티)** | **무료** | 실행 무제한, 데이터 내 서버, 직접 운영 |
| **n8n Cloud** | **약 €20/월~**(2.5k 실행) | 운영 대행, **인원·워크플로우·스텝 무제한** |

핵심은 **모든 플랜이 사용자·워크플로우·스텝 수 무제한**이고, **오직 '실행 횟수'로만** 나뉜다는 점이다 [10]. Zapier의 태스크 과금과 대비하면, **노드를 아무리 많이 써도 실행당 비용이 그대로**라 **복잡한 자동화의 비용 폭증이 없다**. 대량·복잡 자동화에서 **비용이 90% 가까이 차이 난다**는 비교도 있다 [11].

## 9. 잘 쓰는 법 · 주의점

1. **템플릿 우선.** 수백 개 커뮤니티 워크플로우에서 시작해 고쳐 쓰는 게 가장 빠르다 [14].
2. **에러 처리를 설계하라.** 실패 시 알림·재시도 워크플로우를 붙여 조용한 중단을 막아라.
3. **자격 증명·비밀키 관리.** API 키는 n8n의 Credentials에 안전 보관, 워크플로우에 평문 노출 금지.
4. **셀프호스팅이면 운영을 챙겨라.** **업데이트·백업·보안 패치**는 내 몫이다(방치 금물).
5. **로컬 LLM으로 민감정보 보호.** Ollama 등 로컬 모델을 두뇌로 쓰면 데이터가 밖으로 안 나간다.
6. **버전 관리.** 워크플로우를 내보내(export) Git으로 관리하면 협업·롤백이 쉽다.

## 10. 한계와 선택 가이드 — 언제 Zapier·Make를

정직하게, n8n이 모두에게 정답은 아니다 [4][10].

- **기술 문턱.** 노드·API·데이터 매핑 개념이 필요하다. **완전 비개발자**에겐 Zapier가 더 편하다 [4][10].
- **운영 부담(셀프호스팅).** 서버·업데이트·백업을 직접 관리해야 한다. 이게 싫으면 n8n Cloud나 Zapier.
- **기본 통합 수.** 400~500개로 Zapier보다 적다(HTTP로 보완되지만, 그러려면 API를 다뤄야 함) [11].

**선택 가이드**
| 상황 | 추천 |
|---|---|
| 완전 비개발자·앱 클릭 연결·가벼운 사용 | **Zapier** |
| 시각적 편집·복잡 분기·가성비 | **Make** |
| 저렴·대량·데이터 주권·AI/RAG·커스텀 | **n8n**(셀프호스팅) |

> 결론적 한 줄: **"코딩을 조금 할 줄 알고, 비용을 아끼면서 고성능 AI 자동화를 만들고 싶다"면 n8n**이 최적이다 [6].

## 11. 흔한 오해·FAQ

**Q1. n8n은 완전 무료인가요?**
**셀프호스팅(커뮤니티 에디션)은 무료**다 — 실행 제한 없이. 다만 **직접 서버에 설치·운영**해야 한다. 관리가 싫으면 유료 **n8n Cloud**(약 €20/월~)를 쓴다 [7][15].

**Q2. 코딩을 꼭 해야 하나요?**
아니다. 기본은 **노드 드래그앤드롭**이라 코드 없이도 된다. 단, **HTTP 노드로 API를 직접 붙이거나** 복잡한 변환을 할 땐 약간의 기술 이해가 도움이 된다. 필요하면 **코드 노드(JS/Python)**로 직접 짤 수도 있다 [8][13].

**Q3. Zapier보다 정말 싼가요?**
**복잡·대량일수록 그렇다.** Zapier는 액션(태스크)마다, n8n은 **워크플로우 실행당** 과금이라, 다단계 자동화에서 n8n이 크게 저렴하다. 대략 **월 $200 이상 Zapier 지출**이면 n8n이 유리해진다 [11].

**Q4. 통합이 400개뿐이면 부족하지 않나요?**
전용 통합은 적지만 **HTTP Request 노드로 API가 있는 어떤 서비스든** 연결된다. 국내 서비스처럼 전용 노드가 없어도 붙일 수 있어, 실질 연결 범위는 훨씬 넓다 [12][13].

**Q5. AI 에이전트·RAG도 진짜 되나요?**
된다. **AI Agent 노드(두뇌+메모리+도구)**, 벡터스토어, 문서 로더가 기본 제공돼, **자율 에이전트와 RAG 챗봇**을 시각적으로 만든다. LangChain[^랭체인] 기반이며 MCP 서버도 붙는다 [6][9][14].

**Q6. 데이터 보안은요?**
**셀프호스팅하면 데이터가 내 서버 밖으로 안 나간다.** 여기에 **로컬 LLM(Ollama)**을 결합하면 AI 처리까지 완전 로컬로 가능해, 보안·컴플라이언스가 중요한 조직에 적합하다 [7][15].

## 12. 한눈 요약 + 빠른 시작 체크리스트

| 항목 | 요점 |
|---|---|
| 무엇 | **노드를 잇는** 오픈소스 워크플로우 자동화(셀프호스팅 가능) |
| 차별 | **실행 단위 과금**(태스크 아님) → 복잡·대량에 저렴 |
| 구조 | 노드 → 워크플로우, 트리거(스케줄·웹훅·이벤트), **HTTP 노드로 무한 확장** |
| AI | **AI Agent 노드**(두뇌+메모리+도구)·벡터스토어·**RAG** 네이티브 |
| 설치 | n8n Cloud(쉬움) vs **셀프호스팅 Docker(무료·데이터 통제)** |
| 비용 | 셀프호스팅 무료 / Cloud €20/월~(실행 기준·인원·스텝 무제한) |
| 활용 | 업무 자동화·AI 비서·자율 에이전트·사내 RAG 챗봇 |
| 언제 | 저렴·대량·데이터 주권·AI 구축 → n8n / 쉬움·앱 많음 → Zapier |

**빠른 시작 5단계**: ① Cloud 가입 **또는** Docker로 셀프호스팅 → ② 커뮤니티 템플릿 가져오기 → ③ 트리거+노드 연결·자격 증명 등록 → ④ Execute로 테스트 → ⑤ Active로 켜고 에러 워크플로우 부착.

**마지막 한 줄** — n8n은 *"자동화를 '구독'하는 대신 '소유'하고 싶은 사람"*을 위한 도구다. 약간의 기술을 감수하면, **비용 걱정 없이·데이터를 내 손에 쥐고·AI 에이전트까지** 직접 짓는 자유를 얻는다. Zapier로 시작해 벽(비용·유연성·보안)에 부딪혔다면, 다음 정거장은 n8n이다.

[^노드]: 노드(node) — n8n 워크플로우의 최소 단위. API 호출·데이터 변환·트리거·조건 분기·AI 추론·코드 등 '작업 한 조각'을 뜻한다.
[^워크플로우]: 워크플로우(workflow) — 노드들을 선으로 이어 만든 자동화 흐름 전체. "트리거 → 처리 → 액션"으로 구성된다.
[^트리거]: 트리거(trigger) — 워크플로우를 시작시키는 노드. 스케줄·웹훅·앱 이벤트·수동 실행 등이 있다.
[^실행]: 실행(execution) — n8n의 과금 단위. 워크플로우가 처음부터 끝까지 한 번 도는 것을 1실행으로 센다(노드 개수와 무관). Zapier의 '태스크'와 대비된다.
[^셀프호스팅]: 셀프호스팅(self-hosting) — 소프트웨어를 남의 클라우드가 아니라 내 서버·PC에 직접 설치해 운영하는 방식. 데이터 통제·비용 절감이 장점, 운영 부담이 단점.
[^페어코드]: 페어코드(fair-code) — 소스는 공개하되 대규모 상업적 재판매엔 조건을 두는 n8n의 라이선스 방식. 개인·기업 내부 사용은 자유롭다.
[^http]: HTTP Request 노드 — API가 있는 어떤 서비스든 직접 호출하게 해주는 만능 노드. 전용 통합이 없어도 이걸로 연결해 n8n의 확장성을 사실상 무한대로 만든다.
[^에이전트]: AI Agent 노드 — 두뇌(LLM)+메모리+도구로 구성돼, 질문에 따라 스스로 도구를 골라 쓰는 자율 AI를 시각적으로 만드는 n8n 노드.
[^벡터]: 벡터스토어(vector store) — 문서를 의미 기반으로 검색할 수 있게 '임베딩(숫자 벡터)'으로 저장하는 DB. RAG의 핵심 부품.
[^rag]: RAG(검색 증강 생성) — LLM이 답하기 전에 관련 문서를 먼저 검색해 그 근거로 답하게 하는 방식. 환각을 줄이고 '내 문서 기반' 답변을 만든다.
[^도커]: Docker — 앱과 실행 환경을 '컨테이너'로 묶어 어디서든 동일하게 실행하는 도구. n8n 셀프호스팅의 표준 설치 방법이다.
[^랭체인]: LangChain — LLM·메모리·도구·검색을 엮어 AI 애플리케이션을 만드는 프레임워크. n8n의 AI 노드가 이를 기반으로 한다.
