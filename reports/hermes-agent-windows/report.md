# Hermes Agent 윈도우 데스크톱 설치 및 활용

> 대부분의 AI 에이전트가 남의 클라우드에서 돌 때, **Hermes Agent(헤르메스 에이전트)**는 **내 컴퓨터 안에서 산다.** Nous Research가 2026년 2월 공개한 이 **오픈소스(MIT) 자율 AI 에이전트**는 데이터를 밖으로 내보내지 않고, 나와의 대화를 **영속 기억**하며, 쓸수록 스스로 **스킬을 만들어 성장**한다 [8][11]. 이 글은 **윈도우 데스크톱에 설치하는 세 가지 방법**과, 설치 후 **모델 연결·핵심 개념·실전 활용법**을 단계별로 정리한다. 국내 맥락(업스테이지 '솔라 오픈 2' 등재)과 보안 주의점까지 담았다.

## TL;DR
- **Hermes Agent = "내 기기에서 돌아가는, 기억하고 성장하는" 오픈소스 자율 AI 에이전트.** Nous Research 제작, 2026년 2월 공개, **MIT 라이선스**[^오픈소스]. 데이터는 전부 로컬에 남고 **텔레메트리·클라우드 종속이 없다** [8][11][15].
- **클라우드 에이전트와 결이 다르다.** 구글 Gemini Spark 같은 상시 클라우드 에이전트와 달리, Hermes는 **셀프호스팅(로컬 우선)**[^로컬퍼스트]·**모델 자유(OpenAI·Anthropic·OpenRouter·로컬 Ollama 등 무엇이든)**·**오픈소스**가 핵심 [14][17].
- **윈도우 설치는 세 경로** — ① **데스크톱 설치관리자**(원클릭), ② **PowerShell 한 줄**(`iex (irm …/install.ps1)`), ③ **WSL2**[^WSL2](가장 검증된 안정 경로). 네이티브 윈도우 지원은 비교적 최신이라, **안정성을 원하면 WSL2**가 무난하다 [16][9].
- **설치 요구사항**: Git(필수) + Python 3.11↑·Node.js 22(없으면 설치관리자가 자동 설치) + **RAM 4GB↑**(로컬 모델 돌리면 8GB 권장). 연결 모델은 **컨텍스트 64K 이상**이어야 한다 [16].
- **활용의 뼈대는 5가지 개념** — **프로필·SOUL.md(정체성)·영속 메모리·스킬·크론**[^크론]. 개발·리서치·시스템관리·자동화 봇·개인비서까지, **"전체 시스템 접근 + 지속 맥락"**이 필요한 일에 강하다 [12][15][17].
- **국내 접점**: 업스테이지가 국산 모델 **'솔라 오픈 2'를 Hermes Agent 플랫폼에 등재**(2026-07-23)해 '소버린 AI'[^소버린] 확산을 노린다 — Hermes에서 국산 모델을 직접 골라 쓸 길이 열렸다 [1][2][5].

## 핵심 포인트
1. **로컬 우선(local-first)**: "내 서버/PC에 살고, 배운 걸 기억하고, 오래 돌릴수록 유능해진다. 모든 데이터가 내 기기에 남는다" — 공식이 내세우는 정체성 [8][15].
2. **모델에 종속되지 않음**: 프로바이더 무관(provider-agnostic). OpenRouter[^오픈라우터] 한 곳으로 수백 모델을, 혹은 Ollama[^올라마]로 완전 로컬 모델을 붙인다 [13][14].
3. **성장하는 에이전트**: 경험에서 **스킬(절차적 기억)**을 만들어 재사용·공유하고, **홀로그래픽 메모리**[^메모리]로 세션을 넘어 맥락을 유지한다 [12][17].
4. **자동화의 완성 = 크론**: 코드를 짜지 않고 **평문(영어)으로 작업을 서술**하면, 정해진 일정에 사람 개입 없이 스스로 실행한다 [17].
5. **주의: 힘이 세다.** 로컬에서 **풀 시스템 접근**을 갖는 자율 에이전트이므로, 권한·비밀키·비공식 다운로드 미러에 대한 보안 감각이 필수다 [9][18].

## 1. Hermes Agent란 무엇인가 — 왜 '설치형'인가

**Hermes Agent**는 Nous Research가 만든 **오픈소스 자율 AI 에이전트**다 [8][11]. 이름의 뿌리는 Nous Research가 오래 공개해 온 **Hermes 계열 오픈 모델**이지만, 여기서 말하는 'Hermes Agent'는 그 모델을 얹어 **실제로 일하는 에이전트 프레임워크/앱**을 가리킨다.

한 문장 정의부터:

> **Hermes Agent = 내 컴퓨터(또는 내 서버)에 설치해, 어떤 LLM이든 붙여서, 영속 기억과 스킬을 갖고 자율적으로 일하는 오픈소스 에이전트.**

핵심 성격 세 가지:

- **① 셀프호스팅(설치형)이다.** 브라우저에서 로그인해 쓰는 SaaS가 아니라, **내 기기에 깔아서 돌린다.** 공식 표현 그대로 *"Hermes는 당신의 서버에 살고, 배운 것을 기억하며, 오래 돌릴수록 유능해진다. 모든 데이터는 당신의 기기에 남는다 — 텔레메트리·추적·클라우드 종속 없음"* [15].
- **② 오픈소스다.** **MIT 라이선스**[^오픈소스]로 코드가 공개돼 있고(깃허브 `NousResearch/hermes-agent`), 커뮤니티가 스킬·플러그인·메모리 제공자를 붙인다 [11][17].
- **③ 모델 자유다.** 특정 회사 모델에 묶이지 않는다. OpenAI·Anthropic·**OpenRouter**·로컬 모델(Ollama) 등 **무엇이든 연결**해 두뇌로 쓴다 [14].

왜 '설치형'을 택할까? 이유는 분명하다 — **프라이버시·통제·비용·자유.** 대화와 파일이 밖으로 나가지 않고(민감 업무에 유리), 어떤 모델을 쓸지 내가 정하며, 구독료 대신 **내가 고른 모델의 사용량만** 낸다(로컬 모델이면 그마저 0에 수렴). 클라우드 에이전트의 '편의' 대신 **'주권(내 손안의 통제)'**을 택한 설계다.

## 2. 다른 에이전트와 뭐가 다른가 — 좌표 잡기

바로 앞서 다룬 **구글 Gemini Spark**(클라우드에서 24시간 도는 상시 에이전트)와 대조하면 Hermes의 자리가 선명해진다.

| 축 | **Hermes Agent** | 클라우드 에이전트(예: Gemini Spark) |
|---|---|---|
| 실행 위치 | **내 기기/서버(로컬)** | 제공사 클라우드 |
| 데이터 | **로컬에 잔류**, 텔레메트리 없음 | 제공사 인프라 경유 |
| 모델 | **자유 선택**(OpenAI/Anthropic/OpenRouter/로컬) | 제공사 모델 고정 |
| 라이선스 | **오픈소스(MIT)** | 폐쇄형 상용 |
| 비용 | 고른 모델 사용량(로컬이면 ≈0) | 구독료 |
| 설치 | **필요(설치형)** | 불필요(로그인) |
| 강점 | 프라이버시·통제·확장·자동화 | 편의·상시성·워크스페이스 밀착 |

정리하면, **"편하게 남의 클라우드에 맡기기"의 반대편에서, "내 기기에서 내가 통제하며 기른다"**가 Hermes의 철학이다. 개발자·프라이버시 민감 사용자·자동화 마니아·온프레미스가 필요한 조직에 특히 어울린다 [14][15].

## 3. 설치 전 준비 — 요구사항과 '경로 선택'

### 3-1. 시스템 요구사항 [16]
- **필수 선행 조건**: **Git 설치**(유일한 하드 전제).
- **런타임**: **Python 3.11 이상 + Node.js 22**. 없으면 **Hermes 설치관리자가 자동 설치**하고, 이미 있으면 기존 버전을 존중한다.
- **메모리**: **최소 4GB RAM**. **로컬 모델(Ollama)**을 돌릴 계획이면 **8GB 권장**. 클라우드 API만 쓰면 4GB로 충분.
- **연결 모델 조건**: **컨텍스트 윈도우 64K 토큰 이상**[^컨텍스트]. 시스템 프롬프트+도구 스키마가 작은 창을 다 채워 대화 여지가 없어지므로, **64K 미만 모델은 시작 시 거부**된다.

### 3-2. 세 가지 설치 경로 — 무엇을 고를까
윈도우에서 Hermes를 올리는 길은 셋이다. **안정성 vs 간편함**의 트레이드오프로 이해하면 된다.

| 경로 | 난이도 | 안정성 | 추천 대상 |
|---|---|---|---|
| **A. 데스크톱 설치관리자** | ★(원클릭) | 보통(비교적 최신) | GUI 선호·빠른 체험 |
| **B. PowerShell 스크립트** | ★★ | 보통 | CLI 익숙·자동화 |
| **C. WSL2**[^WSL2] | ★★★ | **높음(가장 검증됨)** | 안정성 최우선·개발자 |

> **핵심 판단**: 여러 가이드가 **"네이티브 윈도우(PowerShell) 지원은 아직 초기 베타이며, 가장 road-tested(검증된) 경로는 WSL2"**라고 안내한다 [16]. 반면 데스크톱 설치관리자는 **원클릭·60초 내 설치**의 간편함이 강점이다 [9]. **처음 맛만 보려면 A, 오래 진지하게 쓸 거면 C(WSL2)**를 권한다.

## 4. 윈도우 설치 — 단계별

> ⚠️ **먼저 지킬 것(보안)**: 설치 파일·스크립트는 **반드시 공식 출처**에서 받는다 — 공식 도메인 `hermes-agent.nousresearch.com`과 공식 깃허브 `github.com/NousResearch/hermes-agent`. 검색에 뜨는 유사 도메인(비공식 미러)이 많으니 주의(§9) [8][11].

### 경로 A. 데스크톱 설치관리자 (가장 쉬움)
1. 공식 사이트에서 **Windows 데스크톱 설치관리자**를 내려받는다(Win10/11 x64) [9].
2. 내려받은 설치관리자를 실행 → **원클릭 설치 마법사**를 따른다. 최신 하드웨어에서 **60초 내** 완료 [9].
3. 네이티브 설치 산출물은 **`%LOCALAPPDATA%\hermes`** 아래에 놓인다 [9].
4. 설치 완료 후 데스크톱 앱을 실행 → §5의 **모델 연결**로 진행.

### 경로 B. PowerShell 한 줄 설치
1. **PowerShell**을 연다(가급적 일반 권한, 필요 시 안내에 따름).
2. 공식 설치 스크립트를 실행:
   ```powershell
   iex (irm https://hermes-agent.nousresearch.com/install.ps1)
   ```
   `irm`(Invoke-RestMethod)으로 스크립트를 받아 `iex`(Invoke-Expression)로 실행하는 방식이다 [16].
   > ⚠️ **원격 스크립트를 그대로 실행**하는 명령이다. **출처(공식 도메인)를 반드시 확인**하고, 사내 정책상 필요하면 스크립트를 먼저 열어 검토한 뒤 실행하라(§9).
3. 설치관리자가 **Git/Python/Node**를 점검·보완하고 Hermes를 설치한다 [16].

### 경로 C. WSL2 (가장 안정적) — 권장
1. **WSL2 활성화**: PowerShell(관리자)에서
   ```powershell
   wsl --install
   ```
   실행 후 재부팅하면 기본 Ubuntu가 설치된다.
2. **Ubuntu 실행** → 그 안에서 리눅스용 설치 절차를 따른다(이 안에서 모든 걸 돌리는 게 "검증된 경로") [16].
3. Ubuntu 안에 **Git** 준비 → Hermes 설치 스크립트 실행 → Python 3.11↑·Node 22 자동 보완 [16].
4. 이후 사용은 WSL2 터미널(Ubuntu) 안에서 이뤄진다. 윈도우 파일 시스템과 연동 가능.

> **팁**: 로컬 모델(Ollama)을 쓸 계획이면 WSL2 경로가 리소스·호환성 면에서 특히 무난하다.

## 5. 첫 실행 · 모델 연결

설치가 끝나면 **두뇌(LLM)를 연결**해야 움직인다(공식 퀵스타트도 첫 실행 후 모델 연결을 안내한다) [10]. 가장 쉬운 두 갈래는 **OpenRouter(클라우드, 모델 다양)**와 **Ollama(완전 로컬)**다.

### 5-1. OpenRouter로 연결 (초보자 추천) [13][18]
**OpenRouter**[^오픈라우터]는 한 개의 API 키로 수백 개 모델을 라우팅해 주는 관문이다. 2단계면 끝난다.
1. `openrouter.ai` 가입 → **Settings → API Keys → 새 키 생성**. 키는 `sk-or-`로 시작한다. **키를 복사**해 둔다 [13][18].
2. Hermes에서 **프로바이더 목록에서 OpenRouter 선택 → API 키 입력 → 사용할 모델 선택**. 신규 사용자 권장 방식이다 [13].
   - 이때 **컨텍스트 64K 이상 모델**을 고른다(그 미만은 거부됨, §3-1).

### 5-2. Ollama로 완전 로컬 연결 (프라이버시 최대) [14][16]
- 로컬에 **Ollama**[^올라마]를 깔고 모델을 받아두면, **인터넷 없이·비용 없이** Hermes의 두뇌로 쓸 수 있다. **8GB↑ RAM 권장**. 데이터가 한 발짝도 밖으로 안 나가는 게 장점.

### 5-3. 직접 API 키 (OpenAI·Anthropic 등)
- 특정 제공사 키를 **환경변수/설정에 안전하게** 넣어 연결한다. **키는 절대 대화창·리포지토리에 노출하지 말 것**(§9) [18].

> **국내 사용자 참고**: 업스테이지 **'솔라 오픈 2'**가 OpenRouter·Hermes Agent에 등재돼(§8), Hermes의 모델 선택에서 **국산 모델을 직접 고를 수 있는** 길이 열렸다 [1][2].

## 6. 핵심 개념 이해 — 프로필·SOUL·메모리·스킬·크론·MCP

Hermes를 '잘' 쓰려면 다섯 개념만 잡으면 된다. 각 **프로필(profile)**은 독립된 에이전트 인격으로, 다음을 가진다 [12][17].

- **① 프로필 & 설정(`config.yaml`)**: 격리된 에이전트 하나의 구성 파일. 여러 프로필을 분리해 운영할 수 있다.
- **② 정체성(`SOUL.md`)**: 이 에이전트가 **누구이고 어떻게 행동하는지**를 적는 정체성 문서. 말투·역할·원칙을 여기서 규정한다.
- **③ 영속 메모리**: **홀로그래픽 메모리**[^메모리] — 사실 기반 저장을 **SQLite + FTS5**[^fts5] 전문검색으로 뒷받침한다. 에이전트가 **무엇을 기억할지 스스로 큐레이션**하고, 세션을 요약·검색 가능한 DB(`memory_store.db`)에 쌓아 나중에 맥락을 되살린다. 기본 `MEMORY.md`·`USER.md` 외에 **8종 외부 메모리 제공자 플러그인**으로 확장된다 [12].
- **④ 스킬(skills)**: **절차적 기억** — 경험에서 만들어 재사용·개선하는 **재사용 가능 능력**. 커뮤니티 **스킬 허브**로 공유되며, **Claude Code·Cursor·Codex 등과 호환되는 개방형 스킬 표준**을 따른다 [17].
- **⑤ 크론(cron)**: 내장 스케줄러. **코드가 아니라 평문으로 작업을 서술**하면, `~/.hermes/cron/jobs.json`에 저장돼 **사람 개입 없이 일정대로 실행**한다 [17].

여기에 **MCP**[^MCP]가 도구를 확장한다. Hermes는 **MCP 클라이언트**로 `config.yaml`의 `mcp_servers`에 서버를 선언해 **도구 묶음**을 통째로 얻고, `hermes mcp serve`로 **자신을 MCP 서버로 노출**해 Claude Code·Cursor·Codex가 Hermes를 도구로 쓰게 할 수도 있다 [17].

> 그림으로: **프로필(누구)** + **SOUL(성격)** + **메모리(기억)** + **스킬(능력)** + **크론(언제)** + **MCP(도구)** = 나만의 자율 에이전트.

## 7. 활용방법 — 실전 시나리오

Hermes는 **"전체 시스템 접근 + 지속 맥락"**이 필요한 일에서 진가를 낸다. 공식·커뮤니티가 꼽는 대표 용도는 **소프트웨어 개발·리서치·시스템 관리·데이터 분석·콘텐츠 제작·홈 오토메이션**이다 [15]. 바로 베껴 쓸 시나리오로 정리한다.

### 7-1. 개발 보조 에이전트
> *"이 리포지토리에서 실패하는 테스트를 찾아 원인을 정리하고, 수정 초안을 브랜치에 올려줘."* — 로컬 코드에 직접 접근하는 개발 에이전트. **MCP로 Hermes를 Cursor/Claude Code에 도구로 물려** 협업시킬 수도 있다 [17].

### 7-2. 리서치 에이전트(성장형)
> *"매일 이 주제의 새 논문/뉴스를 모아 요약하고, 지난 요약과 비교해 '무엇이 바뀌었는지'만 알려줘."* — **영속 메모리** 덕에 어제 맥락을 기억하고 **차이만** 보고한다. 반복할수록 **스킬로 굳어져** 빨라진다 [12][17].

### 7-3. 무인 자동화(크론)
> 크론에 평문으로: *"매주 월요일 09:00, 지난주 서버 로그를 훑어 이상징후를 정리하고 Slack으로 보내줘."* — 코드 없이 서술 → **스케줄대로 자동 실행** [17].

### 7-4. 멀티채널 개인비서
> Hermes는 **Telegram·Discord·Slack·WhatsApp·Signal 등 20+ 메시징 플랫폼**을 지원한다 [17]. *"텔레그램으로 말 걸면 답하고, 내가 부탁한 리마인더는 기억해 뒀다가 알려줘."* — 채팅으로 부리는 상주 비서.

### 7-5. 시스템 관리·홈 오토메이션
> *"디스크가 90% 넘으면 오래된 캐시를 정리하고 결과를 보고해."* 로컬 접근 + 크론 + 스킬의 조합으로 **셀프호스팅 운영 자동화**에 적합 [15].

> **활용 설계 팁**: (1) **프로필을 용도별로 분리**(개발용/리서치용/개인비서용). (2) **SOUL.md에 역할·원칙을 명확히** 적어 행동을 고정. (3) **위험한 액션(삭제·배포·송금)엔 사람 확인**을 남기고, 반복·안전한 일부터 크론에 맡겨라.

## 8. 국내 관점 — 업스테이지 '솔라 오픈 2' 등재와 소버린 AI

Hermes Agent는 국내에서도 이미 접점이 생겼다. **업스테이지**는 2026년 7월 23일 에이전트 특화 오픈웨이트 모델 **'솔라 오픈 2(Solar Open 2)'**를 공개하면서, **글로벌 플랫폼인 OpenRouter와 Hermes Agent에 이 모델을 등재**해 해외 개발자 생태계 확산을 추진한다고 밝혔다 [1][2][6]. 업스테이지는 국산 NPU까지 결합한 **'풀스택 소버린 AI'**[^소버린] 구축을 내세웠는데, 그 확산 통로로 Hermes Agent를 지목한 것이다 [3][4].

이것이 **한국 사용자에게 주는 실질적 의미**는 이렇다.

- **Hermes에서 국산 모델을 직접 고를 수 있다.** OpenRouter/Hermes의 모델 선택 화면에서 솔라 오픈 2를 택하면, **한국어·에이전트 성능에 최적화된** 두뇌로 Hermes를 돌릴 수 있다 [1][5].
- **'소버린 AI'와 로컬 우선의 궁합.** 데이터를 밖으로 안 내보내는 Hermes의 로컬 우선 철학은, **데이터 주권**을 중시하는 소버린 AI 흐름과 자연스럽게 맞물린다 — 민감 데이터를 다루는 국내 기관·기업에 시사점이 크다 [7][15].

김성훈 업스테이지 대표는 솔라 오픈 2를 두고 *"단순 벤치마크 점수를 넘어 실제로 일하는 AI"*를 지향한다고 밝혔다 [2]. 이는 **'설치해서 실제로 일 시키는'** Hermes의 지향과도 자연스럽게 맞닿는다.

## 9. 보안·프라이버시·주의점

Hermes의 힘은 **"로컬에서 전체 시스템에 접근하는 자율 에이전트"**라는 데서 오고, 위험도 같은 곳에서 온다. 반드시 지킬 수칙.

- **① 공식 출처에서만 설치.** 검색하면 **유사 도메인·비공식 미러**가 다수 뜬다. 설치 파일·스크립트는 **공식 도메인/깃허브**에서만 받아라 [8][11].
- **② 원격 스크립트 실행에 유의.** PowerShell `iex (irm …)`는 **원격 코드를 즉시 실행**한다. 출처를 확인하고, 정책상 필요하면 **스크립트를 먼저 열어 검토**하라 [16].
- **③ 비밀키 관리.** OpenRouter·OpenAI 등 **API 키를 대화창·리포지토리·SOUL.md에 노출하지 말 것.** 설정/환경변수에 안전하게 보관하고, **스모크 테스트로 최소 권한부터** 확인하라 [18].
- **④ 권한 범위 최소화.** 자율 에이전트에 **삭제·배포·결제** 같은 파괴적 권한을 무분별하게 주지 말고, 위험 액션엔 **사람 확인 게이트**를 남겨라.
- **⑤ 로컬이라고 100% 안전은 아니다.** 로컬 우선이라 **데이터 유출면은 작지만**, 에이전트가 시스템에서 **실제로 행동**하므로 오작동·프롬프트 오염 가능성은 여전히 관리 대상이다. 자동 실행 결과를 **주기적으로 감사**하라.

## 10. 한계와 클라우드 에이전트와의 비교

정직하게, Hermes가 모두에게 정답은 아니다.

- **설치·운영 부담.** 로그인 한 번으로 끝나는 SaaS와 달리 **설치·설정·모델 연결**이 필요하다. 비개발자에겐 초기 문턱이 있다.
- **네이티브 윈도우는 성숙 중.** 앞서 봤듯 **PowerShell 네이티브 경로는 초기 베타** 성격이 있어, 안정성을 원하면 **WSL2**가 권장된다 [16].
- **품질은 붙인 모델에 좌우.** 두뇌를 자유롭게 고르는 게 장점이자 책임 — **약한 모델·좁은 컨텍스트를 붙이면 성능이 떨어진다**(64K↑ 필수) [16].
- **상시성은 내 인프라 몫.** "24시간"을 원하면 **내 기기/서버를 켜 둬야** 한다(클라우드 에이전트는 제공사가 상시 구동).

**언제 Hermes, 언제 클라우드 에이전트?**
- **Hermes가 낫다**: 프라이버시·데이터 주권이 중요, 모델을 자유롭게 바꾸고 싶다, 오픈소스로 커스터마이즈·자동화하고 싶다, 온프레미스가 필요하다.
- **클라우드 에이전트가 낫다**: 설치 없이 바로, 워크스페이스(지메일·문서) 밀착, 상시 구동을 제공사에 맡기고 싶다.

## 11. 흔한 오해·FAQ

**Q1. Hermes Agent는 'Hermes 모델'과 같은 건가요?**
아니다. **Hermes 모델**은 Nous Research의 오픈 LLM 계열이고, **Hermes Agent**는 그 위(또는 다른 모델 위)에서 **실제로 일하는 에이전트 프레임워크/앱**이다. 에이전트에 **어떤 모델이든** 붙일 수 있다 [8][14].

**Q2. 완전 무료인가요?**
**코어는 오픈소스로 무료**다(MIT) [11][15]. 다만 **클라우드 모델(OpenRouter 등)을 붙이면 그 모델 사용료**가 든다. **로컬 모델(Ollama)**을 쓰면 모델 비용도 0에 수렴한다.

**Q3. 윈도우에서 꼭 WSL2를 써야 하나요?**
아니다. **데스크톱 설치관리자·PowerShell**로도 된다. 다만 여러 가이드가 **가장 검증된 안정 경로로 WSL2**를 권한다. **간편 체험은 설치관리자, 진지한 운영은 WSL2**로 이해하면 된다 [16][9].

**Q4. 인터넷 없이 되나요?**
**로컬 모델(Ollama)**을 붙이면 **오프라인**으로도 동작한다. 클라우드 모델을 쓰면 그 API 호출에 인터넷이 필요하다 [14][16].

**Q5. 국산 모델도 쓸 수 있나요?**
그렇다. 업스테이지 **솔라 오픈 2**가 OpenRouter·Hermes Agent에 등재돼, Hermes에서 **국산 모델을 직접 선택**할 수 있다 [1][2].

**Q6. 데이터가 밖으로 나가나요?**
Hermes 자체는 **로컬 우선 설계로 텔레메트리·추적이 없다** [15]. 단, **클라우드 모델을 붙이면** 그 모델에 보내는 요청은 해당 제공사를 경유한다 — **완전 오프라인을 원하면 로컬 모델**을 써라.

## 12. 한눈 요약 + 빠른 시작 체크리스트

| 항목 | 요점 |
|---|---|
| 무엇 | 내 기기에 설치하는 **오픈소스(MIT) 자율 AI 에이전트**(Nous Research, 2026-02) |
| 철학 | **로컬 우선·모델 자유·성장형(메모리+스킬)** |
| 윈도우 설치 | **① 설치관리자 ② PowerShell ③ WSL2(권장·안정)** |
| 요구사항 | Git(필수)+Python3.11↑/Node22(자동)·RAM 4GB↑·모델 컨텍스트 64K↑ |
| 모델 연결 | **OpenRouter(간편)·Ollama(완전 로컬)·직접 API 키** |
| 5대 개념 | 프로필·SOUL.md·영속 메모리·스킬·크론(+MCP) |
| 활용 | 개발·리서치·자동화·멀티채널 비서·시스템 관리 |
| 국내 | 업스테이지 **솔라 오픈 2** 등재 → 국산 모델 선택 가능 |
| 주의 | 공식 출처·원격 스크립트·비밀키·권한 최소화·결과 감사 |

**빠른 시작 5단계**: ① Git 준비 → ② (안정) WSL2 설치 **또는** (간편) 데스크톱 설치관리자 → ③ Hermes 설치 → ④ OpenRouter 키 생성·연결(64K↑ 모델) → ⑤ SOUL.md 작성 후 첫 작업 지시.

**마지막 한 줄** — Hermes Agent는 *"AI를 남의 클라우드에서 빌려 쓰는"* 시대에 *"AI를 내 기기에서 기르는"* 대안을 제시한다. **편의 대신 통제**, **구독 대신 소유**를 택하려는 사람에게, 이 설치형 에이전트는 강력한 출발점이다.

[^오픈소스]: 오픈소스·MIT 라이선스 — 소스코드가 공개되고, 상업적 이용·수정·재배포가 매우 자유로운 대표적 허용형(permissive) 라이선스.
[^로컬퍼스트]: 로컬 우선(local-first)·셀프호스팅 — 데이터와 실행을 남의 클라우드가 아니라 내 기기/서버에 두는 방식. 프라이버시·통제·오프라인 동작이 강점.
[^WSL2]: WSL2(Windows Subsystem for Linux 2) — 윈도우 안에서 진짜 리눅스 커널을 돌리는 공식 기능. 리눅스용 개발 도구를 윈도우에서 안정적으로 쓰게 해준다.
[^크론]: 크론(cron) — 정해진 시간·주기에 작업을 자동 실행하는 스케줄러. Hermes에선 코드 대신 평문으로 작업을 서술한다.
[^메모리]: 홀로그래픽 메모리(holographic memory) — Hermes의 사실 기반 영속 기억 방식. 대화·사실을 DB에 쌓고 검색해 세션을 넘어 맥락을 유지한다.
[^MCP]: MCP(Model Context Protocol) — AI 에이전트를 외부 도구·데이터에 규격화해 연결하는 개방형 표준. Hermes는 MCP 클라이언트이자 서버가 될 수 있다.
[^오픈라우터]: OpenRouter — 하나의 API 키로 여러 회사의 수백 개 LLM을 라우팅해 주는 관문 서비스. 모델을 자유롭게 바꿔 쓸 수 있다.
[^올라마]: Ollama — 개인 PC에서 오픈 LLM을 손쉽게 내려받아 로컬 구동하는 도구. 인터넷·비용 없이 완전 로컬로 모델을 돌릴 수 있다.
[^컨텍스트]: 컨텍스트 윈도우(context window) — 모델이 한 번에 다룰 수 있는 토큰(글자 조각) 총량. Hermes는 시스템 프롬프트+도구 정의가 커서 64K 이상을 요구한다.
[^fts5]: SQLite FTS5 — 가벼운 파일 기반 DB인 SQLite의 전문(full-text) 검색 확장. 저장된 기억을 빠르게 키워드 검색하게 해준다.
[^소버린]: 소버린 AI(sovereign AI) — 특정 국가·조직이 자국 데이터·인프라·모델에 대한 주권(통제권)을 갖고 구축하는 AI. 데이터 국외 유출을 줄이는 것이 핵심 동기.
