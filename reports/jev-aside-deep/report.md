# Jev와 Aside — 글을 안 쓰는 AI와 통합을 안 쓰는 브라우저

> 단톡방에서 "Jev랑 Aside"가 한 묶음으로 돌아다니는데, **먼저 바로잡을 것이 있다 — 둘은 한 제품이 아니다.** 만든 회사도, 하는 일도, 나온 시점도 다르다. **Aside**는 2026년 6월에 공개된 **AI 에이전트 브라우저**이고 [10], **Jev**는 9월 중순에 나온 **판단 전용 AI 모델**이다 [5][13]. 둘이 같이 언급되는 이유는 따로 있다 — **Jev가 결정을 내리고 Aside가 그 결정을 브라우저에서 실행하는** 조합이 커뮤니티에서 만들어지고 있기 때문이다 [14][15]. 이 보고서는 둘을 갈라 놓고 각각 무엇인지, 기존 도구와 정확히 어디가 다른지, 실무와 일상에 무엇을 바꿀 수 있는지, 그리고 **지금 시점에 믿으면 안 되는 것이 무엇인지**까지 다룬다.

## TL;DR

- **Aside** = 크로미엄 기반으로 다시 만든 **에이전트 브라우저**. 연동(integration)을 붙이지 않고 **내가 이미 로그인해 둔 사이트를 그대로 조작한다** [1][10]. 한국인 3명이 창업했고 Y Combinator(F25) 투자를 받았다 [11][12].
- **Jev** = TypeSafe AI의 **System One 모델**. 문장을 만들지 않고 상태를 받아 **타입이 정해진 값과 확률**을 바로 돌려준다 [5][6]. 응답이 **70~500ms** 다 [5].
- Jev가 답하는 질문은 딱 세 종류다 — **Noul**(예/아니오) · **Choice**(최대 255개 중 택1) · **Score**(순서 있는 등급) [5].
- **차별성의 핵심은 "무엇을 안 하기로 했는가"다.** Aside는 API 연동을 안 하기로 했고, Jev는 글쓰기를 안 하기로 했다. 그 포기가 각각 커버리지와 속도·비용을 샀다.
- **숫자는 출처마다 다르다.** "193배 빠르고 445배 싸다"(톰스하드웨어 [7])부터 "Haiku 대비 5.43배"(liteLLM 벤치마크 [17])까지 **비교 대상이 다르면 배수가 40배 차이 난다**(§5).
- **가장 중요한 경고** — Jev의 판단은 **프롬프트 인젝션[^프롬프트인젝션]으로 움직일 수 있다** [8]. 파이단틱 공식 문서는 "선택지의 **순서**만 바꿔도 답이 바뀔 수 있다"고 적고, "Jev로 만든 가드는 결정론적 검사를 **대체**하는 게 아니라 **곁에** 두는 것"이라고 못 박는다 [8].

## 핵심 포인트

1. **둘은 서로를 필요로 하지 않는다.** Aside 혼자서도 돌아가고 Jev 혼자서도 돌아간다. 묶는 것은 선택이고, 그 접착제는 아직 **커뮤니티 어댑터** 수준이다 [14][15].
2. **Aside의 발명은 기술이 아니라 우회다.** "API를 붙일 수 없는 사내 시스템"이 자동화의 최대 장벽이었는데, 사람처럼 로그인해서 쓰면 그 장벽이 사라진다 [1].
3. **Jev의 발명도 기술이 아니라 포기다.** 생성을 포기하니 파싱도, 재시도도, "JSON 좀 제대로 뱉어라"도 사라진다 — **샘플링 레이어에서 타입과 확률이 바로 나온다** [16].
4. **확률이 나온다는 것이 실무에서 결정적이다.** "0.87 확신"이 숫자로 오면 **자동 처리 / 사람 확인 / 보류**의 경계선을 코드로 그을 수 있다 [16].
5. **지금은 초기다.** 리뷰어들은 "출시 며칠 된 제품", "리더보드 주장이 벤더가 관리하는 저장소에 있으니 중립 기관이 재현하기 전까지는 마케팅으로 보라"고 적는다 [2].

## 1. 먼저 바로잡을 것 — 둘은 한 제품이 아니다

단톡방에서 "Jev랑 Aside"가 한 단어처럼 도는데, 연표를 놓으면 별개라는 것이 바로 보인다.

| 시점 | 무슨 일 |
|---|---|
| 2026-06-23 | Aside 공식 소개 영상 공개 — "웹사이트·계정·히스토리를 가로질러 복잡한 일을 해내는 브라우저" [10] |
| 2026-09-14 | Aside 윈도우판 출시, 맥과 거의 동등한 기능 [3] |
| 2026-09-16 | Jev 공개 보도 시작 [13] |
| 2026-09-19 | Jev 상세 소개 기사 — "텍스트 대신 타입이 정해진 보정된 결정을 돌려주는 System One 모델" [5] |
| 2026-09-20~22 | 국내 블로그·유튜브에서 두 이름이 동시에 확산 [11][18][19][20] |

**만든 곳도 다르다.** Aside는 샌프란시스코의 At Your Side 라는 회사가 만들었고 [18], Jev는 TypeSafe AI 가 만들었다 [5].

**그럼 왜 같이 묶이나.** 깃허브에 둘을 잇는 어댑터가 올라오고 있기 때문이다. 한 저장소는 자신을 이렇게 설명한다 — "브라우저 에이전트를 **대체하는 것이 아니라 어댑터**이며, Aside 의 기존 지속 탭 워크플로를 타입이 정해진 선택을 돌려주는 로컬 Jev CLI 에 연결한다" [14]. 다른 저장소는 더 짧게 정리한다 — "**Jev 가 모델이고 Aside 가 브라우저 런타임이다**" [15].

> **읽는 법**: Jev는 "무엇을 할지 정하는 쪽", Aside는 "정해진 것을 실제로 누르는 쪽"이다. 한쪽만 써도 되고, 붙이면 판단과 실행이 분리된 구조가 된다.

## 2. Aside — 통합을 버리고 브라우저를 택한 에이전트

### 2-1. 무엇인가

Aside 는 **다운로드해서 설치하는 크로미엄 기반 브라우저**다. 겉보기엔 크롬과 같지만 안에 에이전트가 들어 있어서, **연동을 스무 개 넘게 붙이는 대신 내가 이미 로그인해 둔 사이트를 직접 조작한다** [1].

이 한 문장이 차별성의 전부라고 해도 과하지 않다. 기존 자동화 도구는 **연결할 수 있는 것만** 자동화할 수 있었다. 사내 그룹웨어, 낡은 ERP, 계정만 있고 API 는 없는 SaaS — 여기서 자동화가 막혔다. Aside 의 답은 **"API 를 찾지 말고 사람처럼 쓰자"** 다.

### 2-4. 한국에서 화제인 이유

국내 확산에는 별도의 이유가 있다. 조회수 3만 회를 넘긴 국내 소개 영상은 **"한국인 3명이 만들고 Y Combinator 가 투자한 AI 브라우저"** 라고 소개한다 [11]. 창업자 중 한 명은 이찬희(Chanhee Lee)다 [12]. 국내 블로그들이 9월 중순부터 설치법·사용법을 연달아 올린 것도 같은 맥락이다 [18][19][20].

**한 가지는 짚어 두는 것이 정직하다.** 같은 영상의 제작자는 처음에 **"클로드 코드나 코덱스의 하위호환 아니냐"는 부정적인 글을 올렸다가 다음 날 생각이 바뀌었다**고 밝힌다 [11]. 초기 반응이 갈렸다는 뜻이고, 그 자체가 이 도구의 성격을 말해 준다 — **개발자용 코딩 에이전트와 겹쳐 보이지만 겨냥하는 일이 다르다.**

## 3. Jev — 글을 쓰지 않는 AI

### 3-1. System One 이란 무엇인가

Jev 는 **텍스트를 생성하지 않는다.** 기사·답변·코드를 쓰지 않고 대화도 하지 않는다. 대신 **정리되지 않은 상태(state)를 받아, 미리 정해 둔 타입의 질문에 구조화된 결정과 확률로 답한다** [16].

이름의 유래가 설계를 말해 준다[^System One]. 사람의 사고를 빠른 직관(System 1)과 느린 숙고(System 2)로 나누는 구분에서, **LLM 이 System 2 쪽이라면 Jev 는 System 1 쪽**을 맡는다는 것이다 [5][16].

**기술적으로 무엇이 다른가.** 보통의 LLM 구조화 출력은 "텍스트를 생성한 다음 그것을 파싱"한다. Jev 는 그 단계가 없다 — **타입이 정해진 값과 확률분포를 샘플링 레이어에서 직접 돌려준다** [16].

```
   보통의 LLM 구조화 출력              Jev

   프롬프트                            상태(state) + 질문
      ↓                                  ↓
   토큰을 한 개씩 생성                  샘플링 레이어
      ↓                                  ↓
   JSON 비슷한 문자열                   타입 값 + 확률분포
      ↓                                  ↓
   파싱 → 실패하면 재시도               끝 (파싱 없음)
      ↓
   검증 → 또 실패하면 재시도
```

이 그림에서 사라진 것이 **파싱 실패·재시도·스키마 강제**다. 실무에서 구조화 출력이 골치인 지점이 정확히 거기였다.

### 3-2. 무엇을 못 하나 — 이게 더 중요하다

국내 소개글이 이 점을 정확히 적는다 — **"JEV 를 챗GPT처럼 대화나 글쓰기 용도로 대신 사용할 수 있나요? 아니요, 대체하기 어렵습니다"** [21]. 다른 국내 글도 같은 선을 긋는다 — "자유로운 문장을 생성하기보다 **코드가 사용할 수 있는 구조화된 판단과 확률**을 반환한다" [22].

**그래서 Jev 는 LLM 의 경쟁자가 아니다.** 한 비교 분석은 이렇게 정리한다 — "Jev 와 기존 LLM 은 **서로 다른 인터페이스 문제**를 푼다. Jev 는 코드를 위해 경계가 정해진 확률을 돌려주고, LLM 은 언어·코드·설명을 생성한다" [16].

## 4. 세 프리미티브 — Noul · Choice · Score

Jev 에게 물을 수 있는 것은 **세 가지뿐**이다 [5].

| 프리미티브 | 묻는 것 | 돌려주는 것 | 제한 |
|---|---|---|---|
| **Noul** | 예/아니오 | 값 하나 | **별도 확신도가 없다** — 값 자체가 확신도다. 0.5 는 "모르겠다" |
| **Choice** | 여러 선택지 중 하나 | 선택지별 확률 + 전체 확신도 | 선택지 최대 **255개** |
| **Score** | 순서 있는 등급(낮음·보통·높음 등) | 연속 점수 + 분포 + 확신도 | — |

**Noul 의 설계가 특히 영리하다.** 보통은 "답"과 "확신도"를 따로 받는데, 예/아니오 문제에서는 그게 중복이다. 0.87 이면 그 자체로 "예 쪽에 0.87 만큼 기울었다"는 뜻이고, **0.5 는 미정**이다 [5]. 그래서 코드가 이렇게 짧아진다.

```
   답 = jev.noul("이 문의는 환불 요청인가?", 상태=본문)

   if 답 > 0.9:    자동으로 환불 절차로 보낸다
   elif 답 < 0.1:  자동으로 일반 문의로 보낸다
   else:           사람에게 넘긴다          ← 0.5 근처가 여기 모인다
```

**이 세 줄이 Jev 의 실무 가치 전부**라고 해도 된다. "애매한 것을 애매하다고 말해 주는 것"이 자동화에서 가장 비싼 기능이다.

### 4-1. 어떻게 부르나

```
pip install typesafe-sdk          # 파이썬 3.10 이상
export TYPESAFE_API_KEY=...       # 개발자 콘솔에서 발급
```

파이썬에서는 `TypeSafeClient` 를 열고 `client.system_one(state=..., questions={...})` 을 호출하면서 질문 자리에 Noul·Choice·Score 객체를 넣는다. 기본 모델은 `jev-latest` 다 [9]. 웹 플레이그라운드도 있어서 코드 없이 아무 텍스트나 상태로 붙여 넣고 시험해 볼 수 있다 [9].

**생태계 편입 속도가 빠르다.** 파이단틱이 공식 문서를 갖고 있고 [8], 오픈라우터·스프링 AI 에 연동이 올라왔으며 [5], 랭체인은 **Jev 가 에이전트의 도구 호출 실행 여부를 결정하는 미들웨어**를 이미 출시했다 [8].

## 5. 숫자를 어떻게 읽을 것인가 — 193배와 5.43배 사이

여기가 이 보고서에서 가장 조심해야 할 대목이다. **성능 주장이 출처마다 다르고, 차이가 크다.**

| 출처 | 속도 | 비용 | 비교 대상 |
|---|---|---|---|
| 톰스하드웨어 [7] | **193배** 빠름 | **445배** 저렴 | 프런티어 LLM |
| explainx(회사 수치 인용) [5] | 최대 **200배** | 최대 **400배** | 프런티어 LLM |
| refix.ai [16] | **40~200배** | **40~400배** | 프런티어 LLM |
| liteLLM 벤치마크 [17] | **5.43배** (중앙값 지연) | **96% 절감** | **Haiku**(소형 모델) |

**배수가 40배 가까이 벌어지는 이유는 단순하다 — 비교 대상이 다르다.** 프런티어 LLM 과 비교하면 수백 배가 나오고, 이미 싸고 빠른 소형 모델(Haiku)과 비교하면 5배 남짓이 나온다.

**실무 판단에 쓸 숫자는 뒤쪽이다.** 분류·라우팅 작업을 이미 소형 모델로 돌리고 있다면 기대치는 "수백 배"가 아니라 **"5배 빠르고 비용 96% 절감"** 쪽이다 [17].

### 5-1. 절대값으로 보기

| 항목 | Jev | 프런티어 LLM |
|---|---|---|
| 케이스당 비용 [16] | **$0.0004** | $0.0304 ~ $0.1761 |
| 케이스당 시간 [16] | **0.4초** | 10 ~ 38초 |
| 응답 지연 [5] | 70~500ms | — |
| 가격 구조 [5] | 입력 100만 토큰당 $0.042, **출력 무료** | — |

**월 10만 건을 돌린다고 치면** 이렇게 환산된다.

| | 비용 | 직렬 처리 시간 |
|---|---|---|
| Jev | **$40** | 11.1시간 |
| 프런티어 LLM(하한) | $3,040 | 277.8시간 (11.6일) |
| 프런티어 LLM(상한) | $17,610 | 1,055.6시간 (44.0일) |

차액이 월 **$3,000~$17,570** 이다. 다만 이 계산은 [16] 이 보고한 케이스당 값을 그대로 10만 배 한 것이고, **실제 워크로드의 토큰 길이·병렬도에 따라 달라진다.**

### 5-2. 정확도는 어떤가

속도와 비용이 아무리 좋아도 정확도가 떨어지면 의미가 없다. 한 비교 실험은 **같은 노르웨이 정부 청문 문서 24건**에 Jev 와 DeepSeek V4.1 Flash 를 돌렸고, **기준 라벨과 일치하는 비율이 사실상 동률**이었다 [16].

표본 24건은 작다. 그래도 방향은 말해 준다 — **경계가 정해진 분류에서는 큰 모델을 쓸 이유가 약하다.**

## 6. 기존 도구와 무엇이 다른가

### 6-1. Aside vs 기존 자동화 도구

| | 연동형 자동화(재피어·n8n 류) | RPA | **Aside** |
|---|---|---|---|
| 연결 방식 | API·커넥터 | 화면 좌표·셀렉터 | **사람처럼 로그인해서 사용** [1] |
| 커버 범위 | 커넥터가 있는 서비스만 | 화면이 안 바뀌면 | **브라우저로 되는 일 전부** [1] |
| 화면이 바뀌면 | 영향 적음 | **깨진다** | 에이전트가 보고 판단 |
| 맥락 유지 | 없음(실행마다 초기화) | 없음 | **히스토리가 메모리** [1][2] |
| 이벤트 반응 | 웹훅 필요 | 별도 구성 | **푸시 알림이 heartbeat** [1] |

**핵심 대비는 "커버리지 대 안정성"이다.** 연동형은 되는 것만 확실히 되고, Aside 는 되는 범위가 훨씬 넓은 대신 화면·판단에 기댄다.

### 6-2. Aside vs 다른 AI 브라우저

| | ChatGPT Atlas | Perplexity Comet | **Aside** |
|---|---|---|---|
| 강점 | ChatGPT 대화 모델을 브라우저로 [4] | 다중 사이트 리서치 종합, 무료·전 플랫폼 [4] | **AI 네이티브 작업 실행** [4] |
| 성격 | 대화형 보조 | 리서치 중심 | 실행 중심 |

비교 기사 자체가 결론을 이렇게 낸다 — **"이 셋은 사실 경쟁자가 아니라 서로 다른 문제를 푼다"** [4]. 즉 "어느 게 최고냐"는 잘못된 질문이고, **"내가 브라우저에서 읽기를 하나 실행을 하나"** 가 맞는 질문이다.

### 6-3. Jev vs LLM 구조화 출력

| | LLM 구조화 출력 | **Jev** |
|---|---|---|
| 내부 동작 | 텍스트 생성 후 파싱 [16] | **샘플링 레이어에서 타입·확률 직접 반환** [16] |
| 확률 | 없거나 신뢰하기 어려움 | **진짜 확률이 나온다** [16] |
| 파싱 실패 | 있음 → 재시도 | 없음 |
| 잘하는 일 | 생성·설명·리서치·코딩·개방형 추론 [16] | **경계가 정해진 분류·스코어링·라우팅·검증** [16] |

그리고 실무의 답은 양자택일이 아니다 — **"쓸 만한 시스템 상당수는 Jev 와 결정론적 코드와 생성 모델을 조합한다"** [16].

## 7. 실무 적용 시나리오

### 7-1. Jev 가 맞는 자리

| 업무 | 프리미티브 | 왜 맞나 |
|---|---|---|
| 고객문의 1차 분류 | Choice | 카테고리가 정해져 있고 하루 수천 건 |
| 스팸·어뷰징 판정 | Noul | 확률로 자동/보류 경계를 그을 수 있다 |
| 문서 우선순위 | Score | 등급이 순서를 갖는다 |
| 모델 라우팅 | Choice | 쉬운 질문은 소형, 어려우면 대형으로 [17] |
| 에이전트 도구 호출 승인 | Noul | 랭체인 미들웨어가 이미 이 형태다 [8] |
| 사내 규정 위반 사전 점검 | Noul + Score | 결정론적 검사와 **병행**한다는 전제로 [8] |

### 7-2. Aside 가 맞는 자리

- **API 가 없는 사내 시스템** — 낡은 그룹웨어·ERP에서 반복 조회와 입력. 연동형 도구가 못 들어가던 자리다 [1].
- **여러 사이트를 가로지르는 조사** — 로그인해야 보이는 대시보드 세 개를 열어 숫자를 모아 한 장으로 만드는 일 [1].
- **이벤트 대응** — 알림이 오면 반응해서 이어서 처리하는 형태 [1][2].
- **반복 사무** — 국내 사용기들이 공통으로 드는 예가 자료 수집·정리·문서 작성이고, 한 사용기는 **그 블로그 글 자체를 Aside 와 함께 썼다**고 적는다 [20].

### 7-3. 둘을 붙였을 때

커뮤니티 어댑터가 겨냥하는 구조는 이렇다 [14][15].

```
   Aside(브라우저 런타임)          Jev(판단 모델)
   ─────────────────────          ──────────────
   화면을 읽는다          ──상태──▶
                                   Noul/Choice/Score
            ◀──타입 + 확률──        70~500ms 안에
   클릭·입력을 실행한다

   확률이 애매하면(0.5 근처) → 사람에게 확인 요청
```

**분업의 이점이 분명하다.** 실행은 브라우저가, 판단은 전용 모델이 맡고, **판단이 숫자로 나오니 "언제 사람을 부를지"를 코드로 정할 수 있다.**

## 8. 일상 적용 시나리오

- **메일함 정리** — "이 메일이 지금 답해야 하는 것인가"를 Noul 로 물어 0.9 넘는 것만 남긴다.
- **구독 점검** — 로그인해야 보이는 결제 내역 페이지들을 Aside 가 돌며 모은다. **결제 자체는 확인을 기다리므로** 조회까지만 맡기면 안전하다 [1].
- **읽을거리 선별** — 저장해 둔 링크를 Score 로 등급 매겨 상위만 읽는다.
- **장보기·예약** — 로그인 상태로 비교·담기까지. 실행 직전 확인 단계가 기본이다 [1].
- **가계·문서 수집** — 여러 사이트의 명세서를 모아 한 폴더로. 메모리가 쌓여 두 번째부터 설명이 짧아진다 [2].

## 9. 기대효과를 계산해 본다

**모든 가정을 드러내고** 계산한다. 아래 수치는 실측이 아니라 [16] 의 케이스당 값과 [2] 의 요금표에 내 가정을 곱한 것이다.

**가정**: 문의 분류를 하루 300건, 월 6,600건 처리한다. 지금은 사람이 건당 20초 본다.

| 항목 | 지금(사람) | Jev 도입 |
|---|---|---|
| 월 처리량 | 6,600건 | 6,600건 |
| 건당 시간 | 20초 | 0.4초 [16] |
| 월 소요 시간 | 36.7시간 | **0.73시간** |
| 월 모델 비용 | $0 | **약 $2.6** (6,600 × $0.0004) |

**그런데 이 표는 정직하지 않다.** 실제로는 애매한 건이 사람에게 넘어오기 때문이다. 확신도 0.1~0.9 구간이 **20%** 라고 보면 이렇게 바뀐다.

| 항목 | 값 |
|---|---|
| 자동 처리 | 5,280건 (80%) |
| 사람 확인 | 1,320건 (20%) → 7.3시간 |
| 절감 시간 | **28.6시간/월** (정확값 36.67 − 7.33 − 0.73) |

> ⚠️ **반올림 주의**: 위 표의 표시값(36.7 · 7.3 · 0.73)을 그대로 빼면 28.7 이 나오는데, 반올림하지 않은 값으로 빼면 **28.6** 이다. 중간값을 반올림한 뒤 빼면 마지막 자리가 어긋난다 — 이런 표에서 늘 생기는 일이다.

**핵심은 절감 시간이 아니라 "20%"라는 숫자를 알 수 있다는 것이다.** 기존 LLM 분류에서는 어느 건이 애매했는지 사후에도 알기 어려웠다. Jev 는 그것을 확률로 준다 [16].

## 10. 리스크 — 프롬프트 인젝션이 '판단'을 움직인다

**여기는 낙관적으로 쓰면 안 되는 절이다.**

벤처비트는 Jev 확산 속도를 이렇게 요약한다 — **"기업이 Jev 가 내리는 결정을 감사하고 제약하고 검토하는 체계를 세우기도 전에, Jev 가 에이전트 인프라로 더 빠르게 퍼지고 있다"** [8].

구체적인 취약점을 **벤더 스스로 문서에 적어 두었다** [8].

| 출처 | 적힌 내용 |
|---|---|
| 파이단틱 공식 Jev 문서 | "**Literal 선택지나 Enum 멤버의 순서가 Jev 가 보는 것의 일부이고, 순서를 바꾸면 답이 움직일 수 있다**" |
| TypeSafe 한계 페이지(Jev 1.13) | "**모델을 적대적으로 유도하려고 쓴 내용** — 주입된 지시, 의도적으로 오도하는 프레이밍, 자기 분류를 주장하는 텍스트 — **이 답을 움직일 수 있다**" |
| 파이단틱 권고 | "**Jev 로 만든 가드는 결정론적 검사를 대체하는 것이 아니라 곁에 두는 것이다**" |

**"선택지 순서를 바꾸면 답이 바뀐다"는 특히 무서운 성질이다.** 코드 리팩터링으로 Enum 멤버 순서를 정렬하는 것만으로 판정이 달라질 수 있다는 뜻이고, 이건 테스트로 잡기 어렵다.

**대응은 이미 나와 있다.** 랭체인은 Jev 로 도구 호출 승인을 결정하는 미들웨어를 내면서 **Jev 가 볼 수 있는 것을 명시적으로 제한**했다 [8]. 즉 판단 모델에게 원문 전체를 주지 않는 것이 방어의 시작이다.

**Aside 쪽 리스크도 별개로 있다.** 브라우저 에이전트는 로그인된 세션 전체에 접근한다. Aside 는 자격증명을 AI 에 노출하지 않고, 결제·게시·메시지 같은 민감 작업에 확인을 두고, 사용 기록을 남기는 방식으로 대응한다 [1]. **설계는 옳은 방향이지만, 확인 단추를 습관적으로 누르기 시작하면 그 설계는 무력해진다.**

## 12. 지금 시점의 정직한 판정

**셋으로 나눠 말하는 것이 맞다.**

**(1) 지금 써도 되는 것** — Jev 로 **경계가 정해진 분류·라우팅**을 시험하는 것. 파이썬 몇 줄이고, 플레이그라운드가 있고 [9], 비용이 케이스당 $0.0004 라 실패 비용이 사실상 0이다 [16]. 기존 소형 모델 분류를 대체할 수 있는지 **자기 데이터로 재 보는 것**이 가장 빠른 검증이다.

**(2) 조건부로 쓸 것** — Aside 로 **읽기·수집·정리**를 맡기는 것. 실행(결제·발송·게시)까지 맡기려면 확인 단계 운영 규칙을 먼저 세워야 한다 [1].

**(3) 아직 이르다고 봐야 할 것** — Jev 를 **단독 보안 게이트**로 세우는 것. 벤더 문서가 스스로 인젝션 취약성과 순서 민감성을 적고 있고 [8], 권고 자체가 "결정론적 검사와 함께"다 [8].

**그리고 전반적인 유보** — 두 제품 다 출시 수개월 이내다. 리뷰어들은 "출시 며칠 된 제품이라 일주일 차 소프트웨어의 버그가 보인다", **"리더보드 주장이 벤더가 관리하는 저장소에 있으니 중립 기관이 재현하기 전까지는 마케팅으로 취급하라"** 고 적는다 [2].

**한 문장으로**: **Jev 는 "AI 에게 글 말고 판단을 시키는" 새 범주라 가치가 분명하고, Aside 는 "연동 없이 되는 자동화"라는 오래된 숙제를 정면으로 푸는데, 둘 다 검증 기간이 절대적으로 짧다.** 시험은 지금 하되 **되돌릴 수 있는 범위에서** 하는 것이 맞다.

## 후속 질문·연결

- **Jev 를 우리 데이터로 재 보려면?** 플레이그라운드에 실제 문의 텍스트를 붙여 Noul 로 시작하는 것이 가장 빠르다 [9]. 이 보고서의 짝 문서인 **[[Aside와 Jev 시작하기]]** 가이드가 설치부터 첫 판정까지를 단계로 잡아 둔다.
- **자동화 도구를 이미 쓰고 있다면?** Aside 는 연동형을 대체한다기보다 **연동이 없는 자리**를 메운다 [1]. 기존 흐름은 [[n8n으로 첫 자동화 워크플로우 만들기]] 쪽이 맞다.
- **모델을 직접 붙여 쓰는 쪽이 궁금하다면?** [[OpenRouter API로 AI 활용하기]] 가 API 키 발급부터 호출까지를 다룬다. Jev 도 오픈라우터에 연동이 올라와 있다 [5].
- **Aside 를 화면으로 먼저 보고 싶다면?** 이 서가에 이미 한국어 실사용 영상 노트가 있다 → [[요즘 AI 브라우저는 어디까지 할까? Aside 직접 써봤습니다 | 설치·개념·사용법 총정리 [어사이드 브라우저]]]
- **"확률 0.5 는 미정"을 어디까지 믿을 수 있나?** 보정(calibration)이 실제로 맞는지는 자기 데이터로 재야 한다. 벤더 저장소의 리더보드는 중립 재현 전까지 마케팅으로 보라는 경고가 이미 나와 있다 [2].
- **인젝션 방어를 어떻게 설계하나?** 랭체인이 택한 방식 — **판단 모델이 볼 수 있는 것을 좁히는 것** — 이 출발점이다 [8].
