# 모빈(Mobbin) MCP 하나로 리서치·기획·제안서까지 생산성을 몇 배 끌어올리기 (실전: 온보딩 UX 기획)

> 한 줄 요약: 백지에서 기획·디자인이 막막한 근본 원인은 **의사결정이 너무 많고 근거·기준이 없어서** — AI에게 그냥 시키면 **"평균값의 함정"**(신입처럼 그럴듯하지만 왜 좋은지 근거 없음)에 빠진다. 해법은 **레퍼런스로 AI에게 근거를 주는 것**. 드리블·비핸스는 **출시된 적 없는 포트폴리오 그림**이라 현실성이 떨어지지만, **모빈은 실제 출시된 iOS·웹 화면 60만+ 캡처**(AB테스트·규모 검증을 거쳐 생존한, 개발 가능한 레퍼런스). 최근 **모빈 MCP**가 나와, 검색→다운로드→그루핑→분석→문서화의 몇 시간~며칠 과정을 AI에게 60만 레퍼런스를 통째로 넘겨 **시간 5~10배 절약**(직군 특화 용어 검색도 가능). 실전(영어 듣기 앱 온보딩): 클로드 코드+모빈 MCP로 ①리서치 범위 자동 확장 ②참고 화면을 **패턴 토픽별 그룹핑**+공통 요소 표시 ③**아티팩트**로 보고서 ④UX 라이팅·마케팅·사업 등 **분야별 딥 분석**(중복 제외 프롬프트) ⑤디자인 MD로 와이어프레임 제안. ★실무 팁: 원하는 보고서가 나오면 **역추적으로 프롬프트를 저장**해 재사용. 단 모빈은 절대 정답이 아니라 **현실성 반영 선택지 모음** — 우리 사용자 테스트·**사람의 최종 판단**이 필수. 한계: 국내 서비스 부족·초최신 버전 미반영.

## 1. ★막막함의 근본 원인 + AI '평균값의 함정'★ · [04:31](https://youtu.be/3W8hJr3DUzI?t=271)
- **3줄 요약**
  - 15년 경력에도 새 프로젝트는 막막 — 근본 원인은 **의사결정할 게 너무 많고 근거·기준이 없어서**(온보딩 몇 단계? 회원가입 앞/뒤? 등). 각 결정이 전환율(가입·결제)을 좌우.
  - "AI한테 시키면?" → **평균값의 함정**. AI는 신입 같아 그럴듯하게 하지만 기준선 없이 물으면 아는 것들의 평균값 — 왜 경쟁사 대비 좋은지·트렌드에 맞는지 답 못 함.
  - 필요한 건 **AI에게 줄 근거** → 레퍼런스가 그 근거.
- **핵심 인용**: "AI에게 어떤 기준선을 정해 주지 않은 상태에서 질문을 하면 AI는 자신이 알고 있는 것들의 평균값으로 결과물을 만들 가능성이 높습니다."
- **내 팁**: '평균값의 함정 → 근거를 주라'는 이 큐레이션 투쏠(기획 먼저)·레인(입력·출력·제약)과 같은 결 — 좋은 결과의 전제는 AI에게 근거·제약을 먼저 주는 것.

## 2. ★모빈 = 실제 출시 화면 (드리블·비핸스와 다름)★ · [06:40](https://youtu.be/3W8hJr3DUzI?t=400)
- **3줄 요약**
  - 드리블·비핸스의 함정: **대부분 출시된 적 없는 포트폴리오 그림** — 긴 문구·빈 리스트 같은 현실 케이스를 안 다뤄 실무 적용 어려움.
  - 모빈은 **실제 출시된 iOS·웹 화면 60만+ 캡처**(1천+ 앱, 14만+ 유저 플로우). 장점 ①개발 가능한 형태 ②AB테스트·데이터로 **생존한 화면** ③규모 있는 서비스(수백만~수억 검증, 익숙한 패턴).
  - 즉 **남이 닦은 길을 적은 비용으로 활용**. 단 조심: 모빈의 성공이 우리에게 꼭 맞진 않음(사용자층·브랜드·문제 다름) → **테스트·크로스체크** 필수. "절대 정답이 아니라 현실성 반영 선택지의 모음".
- **핵심 인용**: "여기는 실제로 출시가 된 iOS나 웹사이트들의 화면들을 캡처해서 모아둔 도서관… 많은 테스트를 거쳐 생존을 한 화면들."
- **내 질문**: '출시·검증된 화면 vs 예쁜 포트폴리오'는 큐레이션 레이디러너(핀터레스트 출처 불명 지적)와 정확히 같은 문제의식 — 레퍼런스의 신뢰성이 곧 근거의 질 아닐까?

## 3. ★모빈 MCP가 해결하는 문제 + 연결★ · [12:34](https://youtu.be/3W8hJr3DUzI?t=754)
- **3줄 요약**
  - 기존 리서치: 검색→카테고리 필터→다운로드→피그마/PPT 정리→그루핑→분석→문서화 (몇 시간~며칠). 분류가 디자이너 친화 용어(엠티 스테이트·바텀시트)라 타 직군은 검색 난감.
  - **모빈 MCP**: AI에게 60만 레퍼런스를 통째로 넘겨 검색·패턴 분석·문서화를 한 번에 → **시간 5~10배 절약**. 직군 특화 용어 검색도 가능(웹사이트에선 불가).
  - 연결: 클로드 코드(코덱스 등 MCP 연결 AI)+유료 회원(월 15달러부터). 설정→MCP 복사→"MCP 연결해줘"→슬래시 MCP→인증→컨펌.
- **핵심 인용**: "AI에게 모빈의 60만 개 넘는 레퍼런스를 모두 넘겨 주는 거라서 검색부터 패턴을 분석하고 문서를 만드는 것까지 내가 한 땀 한 땀 하지 않아도."
- **내 팁**: 'MCP로 대형 레퍼런스 DB를 에이전트에 연결'은 이 큐레이션 투쏠(매니페스트 MCP)·스티치(디자인 MCP)와 같은 계열 — 리서치 자산을 표준 인터페이스로 코딩 에이전트에 주입.

## 4. ★실전 — 아티팩트 보고서 + 패턴 그룹핑 + 분야별 딥분석★ · [24:22](https://youtu.be/3W8hJr3DUzI?t=1462)
- **3줄 요약**
  - 영어 앱 온보딩: MVP 정의+"유사 앱 온보딩 패턴 리서치, 대표 스크린샷 포함, 넘버링 매핑, **아티팩트**(클로드가 HTML을 클라우드에 올려 웹 확인)". 결과: 24화면·엑제큐티브 서머리·10단계(S0~S10).
  - 개선 반복: 와이어프레임 대신 **실제 캡처**, 개별 화면 대신 **패턴 토픽별 그룹핑**(14패턴 매트릭스), **공통 요소 화면 표시**(가입은 온보딩 후 등). 패턴 예: 진행 표시로 부담 완화, 선택지에 의미 단어(5분=캐주얼), 결제 전 가치 체험, 가입은 뒤.
  - **분야별 딥 분석**: "종합 보고서와 **중복 제외, 새 관점 중심**"으로 UX 라이팅(레벨을 사용자 인말로)·사업마케팅(가격 월/일 환산=커피 비유) 보고서.
- **핵심 인용**: "결제하기 전에… 최소한 한 번 정도는 이 앱을 통해서 무엇을 얻을 수 있는지 경험하게 해 줘야 된다."
- **내 질문**: '개별→패턴 그룹핑→공통 표시'는 큐레이션 Cole Medin(정규화·퍼지 매칭)과 같은 지식 구조화 — 리서치도 개별 수집을 넘어 패턴 통합이 핵심 아닐까?

## 5. ★프롬프트 역추적 + 사람의 최종 판단 + 한계★ · [35:19](https://youtu.be/3W8hJr3DUzI?t=2119)
- **3줄 요약**
  - ★**프롬프트 역추적**: 원하는 보고서가 나오면 "이렇게 나오게 하려면 어떤 프롬프트?"를 AI에 물어 **재사용 프롬프트로 저장**(다음 프로젝트 시행착오 방지). 프롬프트는 한 번에 안 나오고 모델(오퍼스·페이블)마다 다름.
  - 분석 기반 **와이어프레임 제안**(에어비앤비 **디자인 MD** 활용으로 흑백보다 이해 쉽게). 결과는 10단계와 크게 안 벗어남(레벨을 사용자 언어로·가입은 뒤). 개선점(낯선 문구·인디케이터 일관성).
  - 결론: 레퍼런스 유무는 속도뿐 아니라 **퀄리티·생각의 범위** 차이. 단 절대 정답 아님 → **사람의 최종 판단력이 중요**. 한계: 국내 서비스 부족·초최신 버전 미반영.
- **핵심 인용**: "레퍼런스를 참고했다고 해서 그게 또 절대적인 정답은 아니거든요. 결국에는 기획에서 사람의 최종 판단력이 중요."
- **내 팁**: '역추적으로 프롬프트 저장'은 이 프로젝트가 LESSONS·재현 규칙을 남기는 것과 동일 — 좋은 산출물보다 **재현 가능한 프롬프트/규칙을 자산화**하는 것이 핵심. 디자인 MD는 큐레이션 여러 편의 공용 브랜드 컨텍스트.

## TL;DR (5줄)

1. **문제(★)**: 막막함의 원인은 의사결정 과다+근거 부재. AI 단독은 **평균값의 함정** → 레퍼런스로 근거를 줘라.
2. **모빈(★)**: 드리블·비핸스(출시 안 된 그림)와 달리 **실제 출시·검증된 60만+ 화면**. 단 우리 사용자엔 테스트 필수.
3. **MCP**: 60만 레퍼런스를 AI에 통째로 연결 → 검색·분석·문서화 **5~10배 단축**. 직군 특화 용어 검색 가능(유료 월 15달러~).
4. **실전**: 아티팩트 보고서→패턴 토픽 그룹핑+공통 요소 표시→UX라이팅·마케팅 분야별 딥분석(중복 제외).
5. **자산화(★)**: 원하는 결과의 **프롬프트를 역추적해 저장**, 디자인 MD로 와이어프레임. 레퍼런스는 근거일 뿐 **사람의 최종 판단**이 결정.
