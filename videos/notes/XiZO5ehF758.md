# 클로드코드 + 노트북LM = AI 리서치 끝판왕! (NLM CLI + 스킬 연동)

> 한 줄 요약: 노트북LM 결과를 복붙 없이 클로드 코드에 연동해 **리서치→결과물 생성을 한 흐름**으로. 도구는 **NLM CLI(터미널 명령어로 노트북LM의 모든 작업 실행)** + **NLM 스킬**(자연어→CLI 명령어 변환). **MCP 대신 CLI를 택한 이유**: MCP는 상시 실행돼 컨텍스트를 많이 먹고 불안정(크래시·좀비) — 공식 MCP가 없는 커뮤니티 도구는 CLI가 유리(컨텍스트 절약+터미널 에러를 클로드가 잘 처리). 실증: ①유튜브 3개→**한국어 오디오 팟캐스트** ②소스 질문→답변 기반 **마크다운 보고서** ③**딥리서치**로 소스 자동 추가→회사 문서(브랜드 가이드·비즈니스 컨텍스트)와 결합→**PDF 전략 보고서**(PDF 스킬). 핵심은 **역할 분담**(노트북LM=환각 적은 소스 기반 인사이트, 클로드=종합·구조화·파일 생성). ※비공식 도구라 UI 변경 시 불안정.

## 1. 문제의식 + NLM CLI 소개 · [00:00](https://youtu.be/XiZO5ehF758?t=0)
- **3줄 요약**
  - 노트북LM 결과(분석·딥리서치)를 다른 작업(보고서·PPT·마크다운)에 이으려면 **지금까진 수동 복붙**.
  - 이제 클로드 코드에 자연어로 "유튜브 링크로 새 노트북 만들고 요약해 마크다운으로" 하면 **클로드가 노트북LM에 들어가 다 처리**.
  - **NLM CLI**: 터미널 명령어로 노트북LM의 브라우저 작업(노트북 생성·소스 추가·채팅·오디오·PPT·인포그래픽)을 대신 실행.
- **핵심 인용**: "지금까지는 … 수동으로 복사 붙여 넣기를 많이 했어야 됐습니다. 근데 이제 클로드 코드에서 손쉽게 연동."
- **내 팁**: 앞 영상(데키랩 유튜브 요약)이 YT-DLP였다면, 이건 노트북LM을 CLI로 감싸 리서치를 자동화 — 같은 '터미널 도구를 자연어로' 패턴.

## 2. ★MCP vs CLI — 왜 CLI인가★ · [02:32](https://youtu.be/XiZO5ehF758?t=152)
- **3줄 요약**
  - 외부 서비스 연동은 **MCP와 CLI** 두 방식. **MCP 단점**: 상시 실행돼 도구 정보(예: 35개)를 항상 컨텍스트로 로드 → **토큰 소모↑**, 서버 크래시·좀비 프로세스 등 불안정.
  - **CLI 방식**: 자연어→클로드가 터미널 명령어로 실행 + **NLM 스킬**이 변환 보조. 장점: **컨텍스트 절약**, 터미널 명령·에러를 클로드가 잘 이해·처리.
  - 판단 기준: **공식 MCP 제공(노션·구글 캘린더·Gmail)** → MCP도 충분. **공식 MCP 없이 커뮤니티만** → **CLI가 유리**.
- **핵심 인용**: "MCP 서버가 상시 실행이 되기 때문에 컨텍스트를 많이 잡아먹게 되거든요."
- **내 질문**: 'MCP는 상시 컨텍스트 부담, CLI는 온디맨드'는 앞 영상(태오 GWS의 MCP 내장 강조)과 대비 — 통합 방식 선택이 토큰 경제성과 직결되는 것 아닐까?

## 3. 설치 — uv·NLM CLI·로그인·프로젝트 스킬 · [04:24](https://youtu.be/XiZO5ehF758?t=264)
- **3줄 요약**
  - **uv 패키지 설치**(인스톨러) → `uv tool install notebooklm-mcp-cli`(가장 인기·유지보수 잘 되는 리포). 터미널이 어려우면 클로드 코드에 요청(토큰 아끼려면 직접 터미널 권장).
  - **`nlm login`**으로 구글 계정 연동(브라우저). **NLM 스킬 설치**(`nlm skill install claude-code`, **프로젝트 로컬**로) → 자연어→CLI 변환 보조.
  - 스킬은 클로드 재시작(`/exit` 후 재실행) 후 프로젝트 스킬로 활성화.
- **핵심 인용**: "명령어를 직접 타이핑해야 되면 비개발자 입장에서는 접근성이 떨어질 수 있겠죠. 그래서 자연어로 요청."
- **내 팁**: 스킬을 프로젝트 로컬로 설치 → 재시작 후 활성화는 앞 영상(코워크 스킬)과 같은 스킬 운영 패턴.

## 4. ★실증 — 오디오·질문 보고서·딥리서치★ · [07:34](https://youtu.be/XiZO5ehF758?t=454)
- **3줄 요약**
  - **① 오디오 팟캐스트**: AI CEO 팟캐스트 3개(각 1h+)를 노트북 만들고 소스 추가→**한국어 오디오 브리핑(26분)** 생성→디렉토리 이동(출퇴근 청취). 소스 기반이라 **환각↓**.
  - **② 질문→보고서**: "CEO들의 공통 트렌드·입장 차이 분석해 마크다운으로" → 클로드가 노트북LM에 질문→답변 받아 **비교 분석 마크다운** 생성.
  - **③ 딥리서치**: "AI 에이전트 트렌드 딥리서치" → 노트북LM이 **소스 자동 추가·리포트·후속 질문** → 종합 마크다운. (자동 PDF는 실패해 삭제, 브리핑 문서는 마크다운으로 재수집.)
- **핵심 인용**: "노트북LM을 활용해서 최대한 환각 없이 소스 기반으로 인사이트를 도출 … 클로드로 종합·구조화해 파일로."
- **내 질문**: '노트북LM=환각 적은 인사이트, 클로드=종합·파일화'라는 **역할 분담**은 앞 영상(롱폼 영상의 서브에이전트 분업)과 같은 계열 — 각 도구의 강점에 업무를 배분하는 원칙 아닐까?

## 5. 회사 문서 결합 → PDF 전략 보고서 + 한계 · [13:20](https://youtu.be/XiZO5ehF758?t=800)
- **3줄 요약**
  - 딥리서치 리포트(외부 트렌드) + **회사 문서**(브랜드 디자인 가이드·비즈니스 컨텍스트=미션·정책)를 폴더로 제공 → "우리 사업 관점 전략 보고서 한국어 PDF, 액션 아이템·브랜드 디자인 반영".
  - **PDF 스킬**(클로드 코드 기본 플러그인의 document 스킬) 사용 → 브랜드 킥 컬러 반영한 전략 보고서 PDF(목차·요약·지표·기회·리스크·액션플랜·로드맵).
  - **핵심 장점**: 리서치→결과물 생성까지 **여러 단계를 클로드 코드 한 곳에서** 자연어로 관리. **한계**: NLM CLI는 비공식 → 노트북LM UI 변경 시 실행 실패 가능(현재는 커뮤니티 중 가장 쓸 만, 공식 출시 시 재검토).
- **핵심 인용**: "리서치 단계부터 결과물 생성까지 여러 단계의 업무를 클로드 코드 안에서 실행하는 게 이 워크프로세스의 가장 큰 장점."
- **내 팁**: '외부 리서치 + 회사 컨텍스트 결합 → 브랜드 반영 산출물'은 앞 영상(태오 GWS 브랜드 슬라이드, 노트북LM 슬라이드 JSON)과 같은 '내 컨텍스트로 개인화'.

## TL;DR (5줄)

1. **목표**: 노트북LM 결과를 복붙 없이 클로드 코드에 연동해 **리서치→결과물을 한 흐름**으로. 도구 = **NLM CLI + NLM 스킬**.
2. **MCP vs CLI(★)**: MCP는 상시 컨텍스트·불안정 → **공식 MCP 없는 커뮤니티 도구는 CLI**(컨텍스트 절약, 터미널 에러 처리 우수).
3. **설치**: uv → `nlm` CLI 설치 → `nlm login`(구글) → NLM 스킬(프로젝트 로컬, 재시작 후 활성).
4. **실증(★)**: ①유튜브→한국어 오디오 ②질문→마크다운 보고서 ③**딥리서치**로 소스 자동 추가→종합. 노트북LM=환각↓ 인사이트, 클로드=종합·파일화 **역할 분담**.
5. **결합·한계**: 딥리서치 + **회사 문서(브랜드·비즈니스)** → **PDF 전략 보고서**(PDF 스킬). 단 NLM CLI는 **비공식**이라 UI 변경 시 불안정.
