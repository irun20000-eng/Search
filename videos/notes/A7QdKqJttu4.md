# 미쳤다! 옵시디언 캔버스에 AI 붙이면 생기는 일 (Claude Code x Obsidian)

> 한 줄 요약: 옵시디언 **캔버스(Canvas)**는 카드·문서·이미지를 연결하는 다이어그램 도구인데, 그 파일이 **순수 텍스트(JSON: 노드+엣지)**라서 **Claude Code가 직접 읽고 편집**할 수 있다. 흩어진 카드 자동 정렬·색상, 내 아이디어 스케치를 AI가 완성, 100페이지 문서를 캔버스로 변환까지 — HTML/SVG 대비 빠르고·편집 가능·검색되는 게 핵심.

## 1. 캔버스란? 마인드맵처럼 생각을 구조화하는 도구 · [0:00](https://youtu.be/A7QdKqJttu4?t=0)
- **3줄 요약**
  - (콜드오픈) 복잡한 캔버스가 클로드 코드로 깔끔히 정리되는 결과를 먼저 보여주고 시작.
  - 옵시디언이 제공하는 **캔버스** 기능을 **Claude Code와 연동**해 멋진 작업을 하는 게 이번 주제.
  - 캔버스는 카드·문서·이미지를 자유롭게 배치·연결하는 무한 캔버스(마인드맵/다이어그램) 도구.
- **핵심 인용**
- **내 질문**
- 노트를 옵시디언 볼트에서 관리하는 우리 워크플로우에 캔버스를 얹으면, 영상 노트들을 시각적으로 연결하는 지식그래프로 쓸 수 있지 않을까?

## 2. 캔버스 만들기 — 카드·문서·이미지 연결 · [1:30](https://youtu.be/A7QdKqJttu4?t=90)
- **3줄 요약**
  - 좌측 "새 캔버스 만들기"(또는 탐색기 우클릭 → 캔버스)로 생성, 스크롤로 확대·축소.
  - 하단에서 **문서 연결 / 카드 새로 만들기 / 이미지 불러오기**가 가능하고, 각 객체를 선으로 **연결**할 수 있다(마인드맵·다이어그램처럼).
  - 연결된 문서를 캔버스에서 바로 수정하면 원본 파일도 함께 업데이트된다(링크된 오브젝트 동기화).
- **핵심 인용**
- **내 질문**
- 카드가 실제 .md 파일과 양방향 링크된다면, 캔버스를 "노트 대시보드"로 두고 편집까지 거기서 할 수 있을까?

## 3. 캔버스 파일의 비밀 — JSON 텍스트라 AI가 수정 가능 · [3:44](https://youtu.be/A7QdKqJttu4?t=224)
- **3줄 요약**
  - `.canvas` 파일을 VS Code로 열면 **순수 텍스트(JSON)** — **노드(node)**와 **엣지(edge)** 구조. 각 노드엔 id·type·file·위치(x,y)·크기(width/height)가 들어 있다.
  - JSON의 width를 400→1000으로 바꾸면 옵시디언 캔버스에서도 실시간 반영(마치 CAD 파일처럼 수치로 편집).
  - **텍스트 파일이므로 Claude Code(또는 어떤 LLM이든)가 직접 읽고 수정 가능** — 이게 이 영상의 핵심 전제.
- **핵심 인용**
- **내 질문**
- 캔버스가 JSON이라 AI가 좌표·색·연결을 직접 조작한다 — "구조화된 데이터를 AI가 편집"한다는 점에서 우리 build_gallery(데이터→화면)와 방향이 반대(화면 자체가 데이터)인 점이 흥미롭다.

## 4. Claude Code 시연 1 — 흩어진 카드 자동 정렬 + 색상 · [6:10](https://youtu.be/A7QdKqJttu4?t=370)
- **3줄 요약**
  - VS Code에서 `.canvas` 파일을 참조로 걸고 **"캔버스 파일을 멋지게 정리해 주세요"**만 입력(구체 지시 없음).
  - 클로드 코드가 파일을 읽고 "3개 노드가 흩어져 있다 → 재배치하겠다"고 스스로 판단 → 카드를 한 줄로 정렬, 텍스트에 초록색·제목 크기, 화살표 방향까지 흐름에 맞게 수정.
  - 옵시디언에서 확인하면 실제로 깔끔하게 정렬됨.
- **핵심 인용**
- **내 질문**
- 막연한 "멋지게 정리해 줘"에도 AI가 의도를 추론해 배치·색·방향을 정한다 — 어디까지가 "알아서 잘"이고 어디서 명시가 필요할까?

## 5. Claude Code 시연 2 — 내 아이디어 스케치를 AI가 완성 · [8:25](https://youtu.be/A7QdKqJttu4?t=505)
- **3줄 요약**
  - 사용자가 먼저 거친 스케치(에이전트 OS ← 클로드 코드의 루프·골(Goal)·CLAUDE.md 등)를 카드로 그려두고 **"클로드 코드를 활용한 에이전트 OS 관련 내용으로 완성해 줘"**.
  - AI가 의도를 파악해 순식간에 보완 — 클로드 코드의 5대 요소(**지시·기억(메모리)·반복(루프)·목표(골)·도구**)와 훅·스킬·태스크 노드를 추가·연결.
  - "내가 아이디어를 캔버스로 표현 → AI가 구조적으로 보완 → 다시 내가 수정"을 주고받으며 다이어그램을 완성. 이후 이 캔버스로 보고서/발표자료 생성(유튜브 강의용 대본 등) 가능.
- **핵심 인용**
- **내 질문**
- "사람이 뼈대 스케치 → AI가 살 붙이기 → 사람이 다듬기" 루프는 우리 작성↔검수 분리와 같은 협업 패턴 — 캔버스가 그 협업의 공용 캔버스(아티팩트)가 되는 셈.

## 6. 복잡한 문서 → 캔버스 변환 (100페이지도 OK) · [12:00](https://youtu.be/A7QdKqJttu4?t=720)
- **3줄 요약**
  - 아이디어를 직접 그리지 않아도, **이미 있는 복잡한 문서(예: 100페이지)를 통째로 "캔버스로 변환해 줘"** 하면 다이어그램으로 정리된다.
  - 시연: AI와 문서 편집 프로토콜을 정의한 문서를 새 캔버스 파일로 변환 → 복잡한 내용이 깔끔히 구조화.
  - 겹치는 노드는 "겹치지 않게 해 줘" 하면 AI가 루프 돌며 재배치(발표자는 직접 배치하며 머릿속 정리를 선호).
- **핵심 인용**
- **내 질문**
- 긴 강의 노트(.md)도 캔버스로 변환하면 챕터 구조가 한눈에 보이는 맵이 될까? video2post 노트와 캔버스를 엮어볼 여지.

## 7. HTML·SVG 말고 캔버스를 쓰는 이유 · [14:20](https://youtu.be/A7QdKqJttu4?t=860)
- **3줄 요약**
  - AI로 다이어그램을 만들 때 보통 이미지/SVG/HTML로 만드는데 — 이미지는 깨지고 편집 불가, SVG·HTML도 편집이 어렵다.
  - **캔버스는 순수 텍스트**라 빠르고, 불필요한 텍스트 생성에 **비싼 토큰을 안 써도 되고**, 무엇보다 옵시디언의 강점인 **시각화 + 검색**에 그대로 들어맞는다.
  - 결론: 클로드 코드(또는 다른 AI)와 연동해 꼭 써볼 것. 강력 추천.
- **핵심 인용**
- **내 질문**
- "순수 텍스트=빠름·편집·검색·저렴한 토큰"은 우리가 노트를 .md로, 갤러리를 단일 HTML로 둔 이유와 정확히 같은 철학.

## TL;DR (5줄)

1. **캔버스 = 옵시디언의 다이어그램 도구** — 카드·문서·이미지를 연결해 생각을 구조화.
2. **핵심 전제: `.canvas`는 순수 텍스트(JSON 노드+엣지)** — 그래서 Claude Code가 직접 읽고 편집.
3. **시연 1** — "멋지게 정리해 줘"만으로 흩어진 카드를 자동 정렬·색상·화살표 정리.
4. **시연 2** — 내가 스케치한 아이디어를 AI가 완성(보완), 주고받으며 다이어그램 완성 → 문서/발표자료로 확장.
5. **왜 캔버스?** 이미지/SVG/HTML은 편집·검색이 어렵지만 캔버스는 순수 텍스트라 빠르고 편집·검색 가능, 토큰도 절약.
