# 클로드 X 오팔(Opal) AI 자동화로 영상 제작 방식 바뀝니다 (광고 영상 에이전트)

> 한 줄 요약: 구글 **오팔(Opal)**의 **에이전트 인터랙티브 기능**으로 제품 광고 영상을 만든다. 노드는 **Generator 하나**만 쓰고, 프롬프트에 **역할→작업 흐름→인터랙티브 선택 옵션(톤·무드·쇼폼/롱폼 비율)→출력 지침→오류 방지 규칙**을 넣으면 사용자가 채팅으로 계속 피드백하며 수정 가능. **클로드로 씬별 기획서를 만들고 → 스킬(.md 템플릿)로 굳혀** 재사용(토큰 절약), 오팔에서 제품 이미지+프롬프트 입력 → **씬별 이미지 4시안 생성 → 선택 이미지를 영상+나레이션으로 변환**까지 한 흐름. 핵심 가치는 결과물이 아니라 **이미지 생성→영상 변환이 한 곳에서 이어지는 자동화 프로세스**.

## 1. 오팔 에이전트 + 광고 영상 에이전트 개요 · [00:00](https://youtu.be/zCxUyclc_So?t=0)
- **3줄 요약**
  - 클로드 + 오팔 조합으로 광고성 제작 속도가 완전히 달라짐. 오늘 만들 것은 요청 많던 **광고 제작 에이전트**.
  - 오팔 에이전트는 **유저인풋·제너레이터·아웃풋 노드를 직접 연결할 필요 없이** Generator 노드 하나로 충분.
  - 미리 준비한 프롬프트를 Generator에 입력하는 것으로 시작(원리를 이해하면 응용 가능).
- **핵심 인용**: "58 에이전트의 가장 좋은 점은 굳이 복잡하게 … 노드를 직접 연결할 필요가 없다는 점이죠."
- **내 팁**: 오팔은 구글의 노코드 AI 앱 빌더 — 앞 영상들(데키랩 Remotion, 힉스필드)과 달리 '노드 최소화 + 에이전트 대화형'이 특징.

## 2. ★프롬프트 5구성 — 역할·흐름·인터랙티브·출력·규칙★ · [01:49](https://youtu.be/zCxUyclc_So?t=109)
- **3줄 요약**
  - **① 역할 부여**(AI에 먼저 역할) **② 작업 흐름 설명**(4가지 이미지 스타일 추천→선택→영상 변환).
  - **③ 인터랙티브 선택 옵션**(핵심): 사용자가 직접 고르는 옵션 제공 — **영상 톤·무드, 쇼폼/롱폼 비율**까지. 예전엔 Generator 노드에서 비율을 일일이 설정했으나 이제 선택값 기반 자동 생성.
  - **④ 출력 지침**(선택 후 결과물 출력 방식) **⑤ 오류 방지 규칙**(이미지·영상 생성 오류를 줄이는 조항). 오팔은 **채팅으로 계속 피드백**("프리미엄 느낌으로", "카메라 무빙 빠르게")하며 수정 가능.
- **핵심 인용**: "인터랙티브 기능은 … 사용자가 직접 선택할 수 있는 옵션을 제공하는 기능."
- **내 질문**: '인터랙티브 옵션 + 오류 방지 규칙 + 피드백 수정'은 앞 영상(스펙주도개발의 선택지 채우기, 힉스필드 검토 게이트)과 같은 '사람 개입 지점 설계' 아닐까?

## 3. 클로드로 씬별 기획서 + 스킬(.md) 템플릿화 · [05:45](https://youtu.be/zCxUyclc_So?t=345)
- **3줄 요약**
  - 오팔에 바로 넣어도 되지만, **클로드로 광고 기획서를 씬별로** 완성(모델은 Opus 대신 **4.6 버전 추천** — 사용량 절약, 기획 차이 적음). 인트로 훅·연출·전환 등 기획력 연습 권장.
  - 완성한 기획을 **클로드 스킬 파일(.md)**로 만들면 매번 긴 프롬프트 재입력 없이 템플릿처럼 호출 → ChatGPT 커스텀·제미나이 Gems와 유사. **공유 가능 + 토큰 절약**.
  - 클로드는 **시간대별 사용량 제한** 구조라 합리적 사용 중요(이미지 생성·MCP 시 토큰 급소모). 발표자는 Max, 입문은 Pro/무료로 충분.
- **핵심 인용**: "클로드 스킬은 쉽게 말해서 템플릿 개념 … 스킬 파일만 불러와도 긴 프롬프트를 다시 입력하지 않아도 돼요."
- **내 팁**: '기획→스킬 템플릿화'는 앞 영상 다수(데키랩·힉스필드·클로드 디자인 taste)와 동일 결론 — 반복 워크플로우를 스킬로 굳혀 재사용.

## 4. 오팔 실행 — 씬별 이미지 4시안 → 영상+나레이션 · [11:44](https://youtu.be/zCxUyclc_So?t=704)
- **3줄 요약**
  - 오팔 Start → 제품 이미지 업로드 + 클로드 기획서의 훅 씬 프롬프트 입력(한글+영문 동시 생성: AI엔 영문이 낫고 사람은 한글로 이해). 톤(에너지틱)·사이즈(9:16 쇼폼) **인터랙티브 선택**.
  - 하나의 프롬프트로 **시안 1~4 이미지**를 한 번에 생성(업로드 제품 반영). 원하는 시안을 골라 **"영상으로 변환 + 패키지 텍스트 안 깨지게 + 나레이션 생성"**.
  - 영상+음성까지 완성(광고용 퀄리티, 텍스트 깨짐 없음).
- **핵심 인용**: "58의 좋은 점은 이 안에서 바로 이미지를 생성하고 그 상태로 영상으로 변환을 해 줄 수 있기 때문."
- **내 질문**: 이미지 다양화는 제미나이/믹스보드가 더 빠르지만 오팔은 '생성→변환 한 흐름'이 강점 — 도구 조합에서 '연결성'을 우선하는 판단 기준 아닐까?

## 5. 한 번에 씬별 생성 + 수정·되돌리기 + 포지셔닝 · [16:46](https://youtu.be/zCxUyclc_So?t=1006)
- **3줄 요약**
  - 두 번째 방식: 프롬프트에 **씬별 이미지 흐름 전체를 내장** → 기획서만 넣으면 **각 구간 이미지를 한 번에 자동 생성**(황도복숭아 예시: 훅·문제·해결·증거·CTA). 무드(친환경)·사이즈(16:9) 선택.
  - **수정·되돌리기**: "5번 이미지 사람을 한국인 농부로" 즉시 수정, "돌아가죠"로 이미지 선택 화면 복귀(수정분 유지). 선택 이미지를 영상 변환, 영상도 재수정 가능.
  - 포지셔닝: 이미지 생성만이면 GPT가 더 빠를 수 있으나, **오팔은 이미지→영상 변환까지 한 자동화 프로세스**를 보여주는 것이 목적. "AI는 이제 선택이 아니라 필수".
- **핵심 인용**: "오팔을 사용하는 가장 큰 이유는 바로 영상까지 한 번에 완성되는 자동화 프로세스."
- **내 팁**: '한 번에 씬 생성 + 부분 수정 + 되돌리기'는 앞 영상(그래프 엔지니어링의 되돌려 재실행, 인스타/롱폼의 반복 수정)과 같은 '반복 개선 루프'.

## TL;DR (5줄)

1. **도구**: 구글 **오팔(Opal)** 에이전트로 광고 영상 제작 — Generator **노드 하나**, 대화형 인터랙티브.
2. **프롬프트(★)**: 역할→작업 흐름→**인터랙티브 선택(톤·무드·비율)**→출력 지침→오류 방지 규칙. 채팅으로 계속 피드백 수정.
3. **클로드 연계**: 클로드로 **씬별 기획서**(모델 4.6 추천) → **스킬(.md) 템플릿**으로 굳혀 재사용(토큰 절약·공유).
4. **실행**: 제품 이미지+프롬프트 → **시안 1~4 이미지** → 선택 이미지를 **영상+나레이션 변환**(텍스트 안 깨지게). 씬 전체 한 번에 생성도 가능.
5. **핵심(★)**: 이미지 생성만이면 GPT가 빠를 수 있으나, 오팔의 진짜 가치는 **이미지→영상이 한 흐름으로 이어지는 자동화 프로세스**. 부분 수정·되돌리기 자유.
