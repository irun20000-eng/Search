# 2026 노션 사용법 풀버전 — 기초·데이터베이스·자동화·AI까지 이 영상 하나로 (템플릿 제공)

> 한 줄 요약: 노션을 4단계로 관통하는 풀강의 — **① 페이지/블록 기초**(집=워크스페이스, 방=페이지, 가구=블록, 만능키 `/`) → **② 데이터베이스**(속성·보기·필터/정렬, 행 하나=페이지) → **③ 자동화**(템플릿·반복·버튼) → **④ AI**(AI로 DB 생성, AI 노트, 자동 채우기, 수식, 에이전트, **클로드 커넥터**). 핵심 메시지: **AI·자동화·바이브 코딩은 결국 '내 일의 데이터'를 읽고 구조화하는 것 → 그 데이터를 쌓기 가장 쉬운 곳이 노션**. "처음부터 완벽하게 말고 빈 화면에서 하나씩 빌드업."

## 1. 왜 노션인가 — 데이터가 없어서다 · [00:00](https://youtu.be/XzU81FfDXLs?t=0)
- **3줄 요약**
  - AI가 "내 일에 안 맞고 결국 내가 다 해야 한다"고 느끼는 이유 = **내 데이터 기록이 없어서**(AI가 나·내 일을 모름).
  - 발표자는 3년간 노션에 업무·일상·사업 데이터를 쌓아둔 것이 AI 동료와 사업 확장의 비결. AI·자동화·바이브 코딩은 결국 **내 데이터를 읽고 구조화**하는 것.
  - 흩어진 기록을 한 곳에 모으는 허브 = 노션. 지금 쓰는 사람과 아닌 사람은 1년 뒤 완전히 달라짐.
- **핵심 인용**: "AI도, 자동화도, 바이브 코딩도, 결국 내 일의 데이터를 읽고 그걸 구조화하는 거예요."
- **내 질문**: 이 영상의 전제(데이터가 AI 활용의 전제)는 앞의 여러 영상(LLM 위키·세컨드브레인·CoWork "첫째도 데이터")과 정확히 같은 메시지 — 결국 '내 데이터 자산화'가 AI 시대의 공통 관문 아닌가?

## 2. 1편 기초 — 집/방/가구 + `/` · [05:25](https://youtu.be/XzU81FfDXLs?t=325)
- **3줄 요약**
  - 노션이 어려운 건 기능이 아니라 **구조 개념** — **워크스페이스=집, 페이지=방, 블록=가구**, 사이드바=현관.
  - 블록은 만능키 **`/`(슬래시)** 하나로: 텍스트·제목(`/제목1~3`)·체크박스(`/할일`)·토글·콜아웃·인용·이미지/북마크/임베드·표(`/표`)·구분선(`---`). 전체 검색 **Ctrl+P**.
  - 활용 = **반복되는 설명을 페이지 하나로**(고객 안내 페이지: 인사말·표·체크박스·콜아웃·FAQ 토글·포트폴리오) → **공유→웹에 게시→링크 복사**로 전달.
- **핵심 인용**: "페이지 = 방, 블록 = 가구, '/' 하나면 다 해결된다."
- **내 팁**: '반복 설명 페이지 + 링크 공유'가 시스템의 시작 — 카톡 반복 타이핑을 없애는 첫 단추.

## 3. 2편 데이터베이스 — 속성·보기·필터 · [19:55](https://youtu.be/XzU81FfDXLs?t=1195)
- **3줄 요약**
  - 페이지가 흩어지면 맥락이 안 보임 → **DB=서랍장**. 단기 읽는 정보=페이지, **장기 누적=DB**. 엑셀과 차이: **행 하나=페이지**, 같은 데이터를 여러 보기로.
  - 핵심 3: **속성**(텍스트·상태·선택·다중선택·날짜·체크박스) / **보기**(표·보드(칸반)·캘린더·갤러리·리스트) / **필터·정렬**(보이는 것만·순서).
  - 응용 CRM: 고객 단계를 **선택 속성→보드 보기**로 영업 흐름(신규/상담중/거래중/종료)을 카드 드래그로 관리.
- **핵심 인용**: "노션 데이터베이스는 단순한 표가 아니라 정보를 계속 쌓고 정리하고 꺼내보기 위한 시스템."
- **내 질문**: '같은 데이터, 여러 보기'는 데이터와 표현의 분리 — 앞 영상(엑셀→클플 대시보드)의 '데이터 소스와 시각화 분리'와 같은 사고방식 아닐까?

## 4. 3편 자동화 — 템플릿·반복·버튼 · [35:00](https://youtu.be/XzU81FfDXLs?t=2100)
- **3줄 요약**
  - '입력 지옥'(매일 비슷한 걸 재타이핑)을 없애는 3가지: **① 템플릿**(자주 쓰는 양식 미리) **② 반복**(정해진 주기 자동 생성, [D]/[W]/[M] 네이밍) **③ 버튼**(원할 때 클릭 한 번으로 워크플로우 할 일 생성).
  - MTS 응용: 루틴 트래커(자정 자동), 데일리·주간·월간 리포트/회고(버튼), 프로젝트 시작/종료 버튼 — 할 일→루틴→주간→월말이 같은 원리 도미노.
  - **초보는 딱 2개**: 매일 반복 [D]템플릿 1개 + 자주 만드는 버튼 1개(복제→수정으로 쉽게).
- **핵심 인용**: "매번 새로 만들 필요 없이, 한 번만 세팅해 두면 정해진 주기에 자동으로 쌓이게."
- **내 팁**: 실수 방지 — **DB 구조를 먼저 잡고 자동화**, 처음부터 다 하지 말고 3가지만.

## 5. ★4편 AI — DB 생성·노트·자동채우기·수식·에이전트★ · [47:21](https://youtu.be/XzU81FfDXLs?t=2841)
- **3줄 요약**
  - **AI로 DB 생성**("콘텐츠 DB 만들어 줘, 속성은 …"), 쌓인 페이지를 "미팅 DB로 만들어 줘"로 구조화. **AI 노트**(미팅·수업 중 집중, 끝난 뒤 요약·결정·다음액션, 링크 공유).
  - **자동 채우기**(카테고리 자동 분류 + 긴 페이지 세 줄 요약), **AI 수식**("마감일 지났으면 '기한 초과', 남았으면 D-숫자" — 결과만 정확히 말하면 수식 생성, 기능 암기 불필요).
  - **AI 에이전트**(내 기록을 읽어 주간 결산 자동, "이런 에이전트 만들고 싶어"로 지시서·트리거·DB 세팅). 단 **AI는 참고·확장용, 해석·선택은 내가**.
- **핵심 인용**: "앞으로 노션을 잘 쓰는 노하우는 어려운 기능을 외우는 게 아니라 내가 보고 싶은 결과를 정확하게 설명하는 데 있다."
- **내 질문**: '결과를 정확히 설명하면 AI가 수식/구조를 만든다'는 건 앤트로픽 6프롬프트 영상의 '내가 뭘 원하는지 아는 것'과 정확히 같은 축 — 도구 지식보다 요구 정의력이 핵심 역량 아닐까?

## TL;DR (5줄)

1. **전제**: AI 활용의 관문은 **내 데이터 기록** — 그걸 쌓기 가장 쉬운 곳이 노션(허브).
2. **기초**: 집=워크스페이스/방=페이지/가구=블록, 만능키 **`/`**. 반복 설명은 페이지+링크 공유로.
3. **DB**: 서랍장(행=페이지). **속성·보기(표/보드/캘린더/갤러리/리스트)·필터/정렬** 3가지. CRM은 선택 속성+보드 보기.
4. **자동화**: **템플릿·반복·버튼**. 초보는 [D]템플릿 1개 + 버튼 1개. DB 구조 먼저, 그다음 자동화.
5. **AI(★)**: AI로 DB 생성·페이지→DB, AI 노트(요약·공유), 자동 채우기, **수식은 '결과만 말하면 생성'**, AI 에이전트(자동 결산), **클로드 커넥터로 노션 직접 읽고 쓰기**(롤업까지). AI는 참고, 해석·선택은 나.
