# [한영자막·한국어 더빙] YouTube 전체를 AI 세컨드 브레인으로 만드는 법 (Cole Medin)

> 한 줄 요약: 카파시의 LLM 위키를 보편 표준화한 **OKF(Open Knowledge Framework)** — MCP가 에이전트↔도구, A2A가 에이전트↔에이전트 표준이듯 **OKF는 에이전트↔지식 베이스 표준**. 저자는 **자기 유튜브 채널 200개 영상 전체를 OKF 지식 베이스(번들)로** 만들어, 에이전트에게 물으면 **답변마다 특정 영상·타임스탬프까지 인용**. 구조: **리드미→인덱스(테마)→마크다운 개념/개체 파일**, 옵시디언 **그래프 뷰**로 연결 시각화. 구축 **파이프라인**: ①영상별 대본을 마크다운으로 추출(원본 스크립트도 포함) → ②**정규화**(반복 개념 파악, 핵심 개체/개념만 개별 파일화, ★같은 개념의 다른 표현을 **퍼지 매칭**으로 통합 — "PIV 루프"="계획 구현 검증"; **2번 이상 언급된 것만** 넣어 확장성 유지) → ③문서 연결로 **지식 그래프**. 남의 채널도 **스킬 하나(예: `/channel2kb`)에 채널 URL만** 주면 자동 구축(스크립트 소스는 YT-DLP·유튜브 트랜스크립트 API 등). 토큰은 많이 들지만 즐겨보는 채널을 세컨드 브레인으로 만들 가치. (후원: 웹검색 서프 API)

## 1. ★OKF — 에이전트↔지식 베이스 표준★ · [00:00](https://youtu.be/brjG7hQgm1I?t=0)
- **3줄 요약**
  - 구글의 새 오픈 지식 형식 = 개인 에이전트·제2의 뇌를 위한 지식 베이스 표준. 카파시의 대규모 LLM 위키를 **보편적 형식**으로 제공.
  - **OKF**는 MCP(에이전트↔도구)·A2A(에이전트↔에이전트)에 이은 **에이전트↔지식 베이스 표준**. 나뿐 아니라 모두와 공유 가능한 지식 베이스.
  - 저자는 **자기 채널 200개 영상 전체를 OKF 번들**로 만들어 무엇이든 질문 가능하게 함.
- **핵심 인용**: "OKF는 우리를 위한 에이전트와 지식 베이스 간의 표준을 만들고 있습니다. MCP가 에이전트와 도구 간의 표준을 만든 것처럼."
- **내 팁**: 이 갤러리 옵시디언·노트북LM 세컨드 브레인 편들(Aiden·신영선)과 같은 계열의 최상위 표준화 버전 — OKF는 여러 세컨드 브레인을 상호운용하는 규격.

## 2. ★사용 경험 — 답변마다 영상·타임스탬프 인용★ · [01:26](https://youtu.be/brjG7hQgm1I?t=86)
- **3줄 요약**
  - "AI 코딩 에이전트로 새 기능 만드는 전체 과정?" → 에이전트가 단계별 설명 + **각 내용을 가르친 특정 영상과 타임스탬프까지 인용**(인덱스로 어디를 봐야 할지 앎).
  - "RAG는 언제 끝날까?" 같은 질문도 영상 전체를 안 보고 핵심만, 필요하면 해당 부분 클릭. 수백 영상 채널 탐색에도 유용.
  - 사용법: **에이전트에게 프롬프트 하나만**(클로드 코드·헤르메스·오픈클로드 무관). 깃허브 리드미의 프롬프트 복사→전송, 형식 모르면 알아서 학습.
- **핵심 인용**: "개념이나 답변을 얻은 타임스탬프가 포함된 특정 영상까지 모든 출처를 인용하고 있습니다."
- **내 질문**: '답변에 출처 영상·타임스탬프 인용'은 이 프로젝트 노트의 챕터별 youtu.be?t= 타임스탬프와 정확히 같은 설계 — 검증 가능한 인용이 세컨드 브레인 신뢰의 핵심 아닐까?

## 3. ★구조 — 리드미·인덱스·마크다운 + 옵시디언 그래프★ · [03:24](https://youtu.be/brjG7hQgm1I?t=204)
- **3줄 요약**
  - **리드미**(이해+설치 프롬프트) → 에이전트가 먼저 볼 **인덱스**(모든 위키의 진입점), 인덱스의 핵심은 **테마**(어떤 지식이 있는지 개요).
  - 모든 것이 **마크다운**(영상→마크다운 대본→핵심 개념·개체 추출). VS 코드나 **옵시디언**에서 확인.
  - 핵심은 옵시디언 **그래프 뷰** — 정보량과 연결을 시각화(컨텍스트 엔지니어링↔바이브 코딩, 검증↔서브 에이전트). 구축에 **LLM 토큰이 매우 많이** 듦.
- **핵심 인용**: "이 지식 베이스의 핵심인 옵시디언의 그래프 뷰입니다. 모든 것이 어떻게 연결되어 있는지 확인하실 수 있을 겁니다."
- **내 팁**: '마크다운+인덱스+그래프뷰'는 이 갤러리 옵시디언 편들과 동일 스택 — OKF는 그 위에 '에이전트가 먼저 읽는 인덱스/테마'라는 기계 진입점을 표준화한 것.

## 4. ★구축 파이프라인 — 추출→정규화(퍼지매칭)→그래프★ · [07:20](https://youtu.be/brjG7hQgm1I?t=440)
- **3줄 요약**
  - ①**대본 추출**: 영상별 대본을 마크다운으로(문장별 타임스탬프). 출처·전체 영상 확인용으로 **원본 스크립트도 포함**.
  - ②**정규화**(가장 복잡): 반복 개념 파악→핵심 **개념 파일**(추상화 등)·**개체 파일**(도구) 생성. ★같은 개념의 다른 표현을 **퍼지 매칭**으로 하나로("PIV 루프"="계획 구현 검증"). **2번 이상 언급된 것만** 넣어 확장성·탐색성 유지(일회성 도구 제외).
  - ③문서 연결→**지식 그래프**(옵시디언 그래프 자동 생성).
- **핵심 인용**: "단순히 키워드를 맞추는 것이 아니라 유사한 표현들을 퍼지 매칭해야 합니다… 두 번 이상 언급된 핵심 개념과 개체만 추려서."
- **내 질문**: '2회 이상 언급 + 퍼지 통합'은 이 프로젝트의 노트 태그·중복 제거와 같은 큐레이션 원칙 — 지식 베이스도 '무엇을 안 넣을지'가 품질을 좌우하는 것 아닐까?

## 5. ★남의 채널도 — 스킬 하나에 URL만 (채널2KB)★ · [11:52](https://youtu.be/brjG7hQgm1I?t=712)
- **3줄 요약**
  - 저장소에 **스킬(기술)** 제공 — 하나 선택하면 **유튜브 채널 주소 하나만으로** 지식 베이스 자동 구축. 세 스킬로 스크립트 소스 옵션 다양화.
  - 스크립트 소스: 슈퍼 API(유료·안정) 대신 무료 먼저 권장. 유튜브 데이터 API는 본인 채널만 → 남의 채널은 **유튜브 트랜스크립트 API·YT-DLP** 등 제3자. 예시는 **채널2KB** 스킬.
  - 실행: 클로드 코드에서 **`/channel2kb` + 채널 URL/핸들**. 토큰 많이 쓰는 긴 과정이나 즐겨보는 채널엔 투자 가치.
- **핵심 인용**: "슬래시 채널2KB라고 입력한 다음 전체 채널 URL이나 콜 메딘 같은 채널 핸들을 입력하면 됩니다."
- **내 팁**: '채널 URL→세컨드 브레인 자동화'는 이 프로젝트의 video2post 파이프라인(재생목록→노트→갤러리)과 정확히 같은 목표 — OKF/채널2KB는 그 표준화·에이전트 질의형 버전. YT-DLP 스크립트 소스는 이 갤러리 데키랩 편과도 연결.

## TL;DR (5줄)

1. **OKF(★)**: 에이전트↔지식 베이스 표준(MCP·A2A의 계보). 카파시 LLM 위키의 보편 형식.
2. **번들**: 채널 200개 영상을 OKF로 → 질문마다 **영상·타임스탬프 인용**. 프롬프트 하나로 어떤 에이전트에도 로드.
3. **구조**: 리드미→인덱스(테마)→마크다운 개념/개체 파일. 옵시디언 **그래프 뷰**로 연결 시각화.
4. **파이프라인(★)**: 대본 추출(원본 포함)→정규화(퍼지 매칭·2회 이상만)→지식 그래프. 정규화가 가장 복잡.
5. **남의 채널**: 스킬 하나(`/channel2kb`)에 채널 URL만. 소스는 YT-DLP·트랜스크립트 API. 토큰 많이 들지만 가치 있음.
