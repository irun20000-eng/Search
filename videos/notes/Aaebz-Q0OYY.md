# AI가 Figma 변수 200개를 혼자 만듦 — 디자인 토큰부터 변수 구조, 시스템까지 자동 완성 (feat. Claude)

> 한 줄 요약: 피그마 **MCP + 공식 스킬**을 Claude Code에 붙이면, 디자인 시안·`design.md` 문서를 입력받아 **디자인 토큰 → 피그마 변수(Primitive/Semantic/Component) → 파운데이션 문서 → UI 컴포넌트**까지 자동 생성한다. 실제로 `design.md` 하나에서 **변수 200개 가까이(프리미티브 135·시멘틱 29·컴포넌트 37)**를 컬렉션까지 구분해 한 번에 등록하는 걸 시연. 다크/라이트 모드 전환되는 마스터 컴포넌트까지 만들지만, 텍스트 변수 누락 등 **수정이 필요한 부분도 솔직히** 짚는다.

## 1. 인트로 — 피그마 스킬로 디자인 시스템 자동화 · [0:00](https://youtu.be/Aaebz-Q0OYY?t=0)
- **3줄 요약**
  - **Google Stitch**·**Claude 디자인**이 시각 가이드를 잡아주는 수준이라면, **피그마 스킬**은 **디자인 토큰·변수 구조·UI 컴포넌트·디자인 시스템까지 자동으로** 만든다.
  - 즉 디자인 토큰을 일일이 설계해 변수로 등록하고 다크 모드를 연결하던 반복 작업을 자동화.
  - 오늘은 피그마 스킬 세팅 → 토큰 생성/변수 등록 → 파운데이션 문서 → UI 컴포넌트까지 전부 시연(개발 지식 없어도 따라오게). 진행자는 **CLI의 Claude Code**로 시현.
- **핵심 인용**
- **내 질문**
- Stitch/Claude 디자인=시각 가이드, 피그마 스킬=구조·토큰까지 — 우리 파이프라인도 "표현"과 "구조(데이터)"를 나눠 생각하면 좋겠다.

## 2. Claude Code 설치 & 작업 폴더 세팅 · [1:15](https://youtu.be/Aaebz-Q0OYY?t=75)
- **3줄 요약**
  - Claude Code 공식 문서의 **1단계 설치 명령어**(맥/윈도우 별도)를 복사해 터미널에 붙여 넣고 엔터 → 동의하며 진행하면 설치 완료.
  - Claude Code는 **특정 작업 폴더 안에서만** 동작하므로, 빈 폴더(예: `claude-code`)를 미리 만들어 둔다.
  - 터미널에서 `cd ~/Desktop/<폴더>`로 이동한 뒤 `claude`를 입력하면 실행된다.
- **핵심 인용**
- **내 질문**
- "폴더 = 작업 경계"는 우리 프로젝트 구조와 같다 — 컨텍스트를 폴더로 가두는 게 곧 안전장치.

## 3. 피그마 플러그인 설치 — MCP + 공식 스킬 7개 + CC Figma Tokens · [2:34](https://youtu.be/Aaebz-Q0OYY?t=154)
- **3줄 요약**
  - **피그마 플러그인**(GitHub 설치 명령어)을 설치하면 **피그마 MCP + 여러 스킬을 한 번에** 세팅. `/plugin`으로 등록 확인. **MCP=피그마와 클로드를 잇는 연결 장치, 스킬=업무 매뉴얼**.
  - 이 플러그인 하나로 **피그마 공식 스킬 7개**까지 함께 설치된다.
  - 추가로 커뮤니티 스킬 **CC Figma Tokens**(구조화된 JSON에서 피그마 토큰 자동 생성)를 설치하면 토큰 작업에 유용. GitHub의 초록 버튼으로 레포 URL을 복사해 "이 스킬 설치해 줘"라고 시켜도 된다.
- **핵심 인용**
- **내 질문**
- "MCP=연결, 스킬=매뉴얼"이라는 정의가 명쾌하다 — 영상4의 shadcn(스킬 vs MCP) 설명과 정확히 같은 프레임.

## 4. 피그마 디자인 → 코드 구현 (implement-design 스킬) · [4:25](https://youtu.be/Aaebz-Q0OYY?t=265)
- **3줄 요약**
  - 샘플 시안 섹션을 우클릭 → **파일 링크 복사** → Claude Code에 붙여 "이 피그마 디자인을 코드로 구현해 줘".
  - 피그마 공식 스킬 중 **implement-design 스킬이 자동 로드** — 피그마 디자인을 **픽셀 퍼펙트 프로덕션 코드**로 변환.
  - 여러 시안을 한 번에 구현해 리마인더 클릭 시 해당 페이지로 이동까지. **기존 MCP 단독보다 정확도가 크게 향상**됐다.
- **핵심 인용**
- **내 질문**
- "스킬이 상황에 맞게 자동 로드"되는 게 핵심 UX — 필요할 때만 규칙이 붙는 구조(영상4 L: 스킬은 온디맨드)와 일치.

## 5. 디자인 토큰 생성 → 피그마 변수 등록 (Primitive/Semantic) · [5:41](https://youtu.be/Aaebz-Q0OYY?t=341)
- **3줄 요약**
  - 같은 방식으로 링크를 붙여 "이 시안들로 **디자인 토큰을 생성하고 피그마 변수로 등록**해 줘" → 변수 구조를 **Primitive·Semantic 두 컬렉션**으로 나눠 설계.
  - **Primitive**엔 원재료값(컬러·간격·폰트 사이즈·라인 높이·보더·폰트 패밀리·웨이트) **총 34개** 등록 — 기존 시안값을 분석해 자동으로.
  - **Semantic**은 Primitive를 실제 쓰임새 이름으로 참조(예: `color/neutral/400` → 텍스트 대비색). **2단계 참조 구조**가 토큰·디자인 시스템의 핵심.
- **핵심 인용**
- **내 질문**
- Primitive→Semantic 참조는 "값과 의미의 분리" — 코드의 상수/의미변수 분리와 똑같은 설계 원칙이다.

## 6. 제로베이스: design.md → 토큰 → 변수 200개 · [7:06](https://youtu.be/Aaebz-Q0OYY?t=426)
- **3줄 요약**
  - 백지 상태에서 **Stitch로 뽑은 `design.md`(디자인 시스템 문서)**를 작업 폴더에 넣고, `/clear`로 컨텍스트를 비운 뒤 `@`로 파일을 참조.
  - "이 문서로 토큰 생성 + 피그마 변수 등록"에 **미리 짠 프롬프트**(Primitive/Semantic/Component 3컬렉션 구성 + 금지사항)를 함께 투입(16줄).
  - 결과: **Primitive 135 · Semantic 29 · Component 37 = 약 200개 변수**가 컬렉션까지 구분돼 **한 번에 등록**(Neutral·Sage·Oak 등 색, 간격·라디우스·타이포까지).
- **핵심 인용**
- **내 질문**
- "문서 하나 → 200변수"는 우리 `build_gallery`(노트→갤러리)와 방향이 같다 — 한 소스에서 구조화 산출물을 자동 생성.

## 7. 스타일 등록 + 파운데이션 문서 생성 · [11:07](https://youtu.be/Aaebz-Q0OYY?t=667)
- **3줄 요약**
  - "생성한 변수 기반으로 **스타일도 등록**" → 텍스트 스타일(디스플레이/헤드라인/타이틀/바디/레이블), 색상 스타일(서피스/브랜드/텍스트/보더/피드백), 그림자까지 변수 연결.
  - 이어 "**파운데이션 문서** 생성" → 커버·컬러 팔레트·토큰 레이어·타입 스케일·간격 테이블·라디우스·섀도우가 정리된 문서가 **약 10분** 만에.
  - 물론 실사용엔 수정이 필요하지만 **이 정도 구조를 자동으로** 만드는 게 인상적.
- **핵심 인용**
- **내 질문**
- "자동 생성 후 사람이 수정" — ASR 노트 교정과 같은 원칙. 완성이 아니라 **초안 가속**이 AI의 역할.

## 8. 컴포넌트 문서 & 마스터 컴포넌트 — 한번에 vs 개별 · [12:36](https://youtu.be/Aaebz-Q0OYY?t=756)
- **3줄 요약**
  - "컴포넌트 문서까지" 한 번에 요청하면 **카드가 다크만 있고 라이트 없음·이미지 영역 누락** 등 결함 발생(진행자는 **Sonnet**으로 작업 — **Opus**면 결과가 다를 수 있음). → **개별 컴포넌트를 하나씩** 만드는 걸 권장.
  - **로그인폼·카드·인풋** 컴포넌트를 개별 생성 → 토큰 기반이라 **다크/라이트 즉시 전환**, 마스터 컴포넌트로 등록해 **인스턴스 재사용·일괄 수정** 가능.
  - 단점: **텍스트에 변수가 잘 안 붙는 경우**가 있어, 폰트 패밀리/사이즈/라인하이트/레터스페이스 변수를 **프롬프트에 명시**하면 좋다.
- **핵심 인용**
- **내 질문**
- "한 번에 다 시키면 품질 저하 → 잘게 쪼개라"는 영상2의 'AI 직원에게 잘게 인계'와 같은 교훈이다.

## 9. 디자인 토큰 & 변수란? — 레고 비유 · [16:35](https://youtu.be/Aaebz-Q0OYY?t=995)
- **3줄 요약**
  - **디자인 토큰** = UI 요소 중 더 쪼갤 수 없는 **가장 작은 단위**(색·간격·사이즈·라인 높이·두께). 레고의 기본 블록에 비유.
  - **변수**로 관리한다: 알아보기 힘든 색 코드를 `검은색 1번`(Primitive)으로, 이해하기 쉬운 `버튼-배경색`(Semantic)에 연결 → **한 곳만 바꿔도 참조하는 모든 곳이 일괄 변경**.
  - 모드별 값(라이트/다크)을 등록하면 **버튼 하나로 전체 모드 전환**. 게다가 토큰·변수는 피그마를 넘어 **실제 웹/앱 코드에도 동일 반영**되는 구조를 만들 수 있어 강력.
- **핵심 인용**
- **내 질문**
- "값에 이름을 붙여 참조" = 단일 진실 원천(SSOT). 우리 노트 frontmatter/태그도 이 원리로 갤러리 전체를 제어한다.

## 10. 마무리 — 상황에 따라 선택하라 · [18:36](https://youtu.be/Aaebz-Q0OYY?t=1116)
- **3줄 요약**
  - 지금까지 만든 토큰·변수로 **웹 포트폴리오 사이트**를 만들면 **일관된 느낌의 사이트**가 나온다(완성도는 추가 개선 여지).
  - 단, **피그마 토큰/변수가 항상 정답은 아니다** — 제품 목적·상황에 따라 다르다.
  - **검증용·가벼운 랜딩페이지**엔 디자인 시스템이 필요 없을 수 있다. 무엇이 필요한지부터 판단할 것.
- **핵심 인용**
- **내 질문**
- "도구는 상황에 맞게" — 우리도 모든 영상에 풀 파이프라인을 강제하기보다, 깊이(간결/표준/상세)를 상황별로 고르는 게 맞겠다.

## TL;DR (5줄)

1. **피그마 MCP + 공식 스킬**을 Claude Code에 붙이면 디자인 시안·`design.md`에서 **토큰→변수→문서→컴포넌트**를 자동 생성한다.
2. 세팅: Claude Code 설치 → 작업 폴더 → **피그마 플러그인(MCP+스킬 7개)** + 커뮤니티 **CC Figma Tokens** 스킬.
3. 변수는 **Primitive(원재료) → Semantic(의미 참조) → Component** 3단계; `design.md` 하나로 **약 200개**를 컬렉션까지 자동 등록.
4. 파운데이션 문서·스타일·마스터 컴포넌트(다크/라이트 전환)까지 만들지만, **한 번에 다 시키면 품질↓ → 개별 생성 권장**, 텍스트 변수는 명시 필요.
5. 토큰=최소 단위(레고 블록), 변수=이름 붙인 참조 → 한 곳만 고치면 전체 반영. 단 **가벼운 페이지엔 디자인 시스템이 불필요**할 수 있다.
