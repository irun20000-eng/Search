# 앱을 공장처럼 찍어내는 12가지 핵심 꿀팁

> 한 줄 요약: 한 달에 앱 30개(하루 3개)를 만든 비결은 "코딩을 빨리"가 아니라 **AI가 쉬지 않고 일할 환경(=앱 공장)**을 먼저 만드는 것. **장비 투자(M5 맥북)** → **개발자 계정** → **터미널+cmux로 3개 동시 빌드** → **코덱스 선택 + 권한 개방(자율주행)** → **Flutter(iOS·안드 한 코드)** + **모노레포(부품 재사용)** → **CLAUDE.md/AGENTS.md에 원칙 기록** → **로드맵 + `/goal`로 단계별 자율주행** → **토큰 절약(세션 리셋)** → **개인정보처리방침·지원 페이지(Netlify/Vercel)**. 핵심은 **반복 제거·재사용·위임**의 시스템.

## 1. 개요 — 앱 공장이란 · [0:00](https://youtu.be/93wC8kJJYjs?t=0)
- **3줄 요약**
  - 한 달에 앱 30개 = **하루 3개**씩. 비결은 코딩 속도가 아니라 **AI가 일할 수 있는 환경**을 먼저 만드는 것.
  - 이 환경을 **'앱 공장'**이라 부른다.
  - iOS 앱을 만들어 앱스토어에 올리려면 **결국 맥이 필요**(안드로이드만이면 윈도우도 가능).
- **핵심 인용**
- **내 질문**
- "코딩 속도가 아니라 환경" — 우리 video2post도 매번 손으로 하지 않고 **레시피(SKILL)+파이프라인**을 갖춘 게 곧 '노트 공장'이다.

## 2. 장비 — M5 맥북 & 싸게 사는 3가지 · [0:17](https://youtu.be/93wC8kJJYjs?t=17)
- **3줄 요약**
  - AI 코드 생성은 빠른데 **빌드(코드→실행 가능한 앱 변환)**가 느리면 흐름이 끊긴다. 그래서 **M5 맥북 프로 14인치·18코어·48GB**(400만 원↑)로 투자.
  - 14인치 선택 이유: 16인치는 성능은 좋지만 **들고 나가기 싫어서**.
  - 싸게 사는 3법: ① **당근마켓**(미개봉·중고, 사양 선택 어려움) ② **쿠팡**(할인·빠른 배송, 인기 재고 빨리 소진) ③ **애플 교육 스토어**(학생·교직원 할인, 커스텀 사양은 배송 지연).
- **핵심 인용**
- **내 질문**
- 병목이 '생성'이 아니라 '빌드/검증'이라는 지적이 날카롭다 — 우리도 자막 '수집'이 병목이었지 노트 '작성'이 아니었다.

## 3. 앱 개발자 등록 — 애플·구글 계정 · [2:11](https://youtu.be/93wC8kJJYjs?t=131)
- **3줄 요약**
  - iOS는 애플 아이디로 내 아이폰 무료 테스트 가능하나, **앱스토어 배포·타 기기 설치엔 애플 개발자 멤버십**(연 12만 9천 원, 배포 필요 시점에 등록).
  - 등록 시 **Apple Ads**도 같이(첫 등록 100달러 무료 크레딧).
  - 안드로이드는 **구글 플레이 개발자 계정**(최초 2만 5천 원). 개인 계정은 출시 전 테스트 조건이 까다로우니 **사업자면 DUNS 번호로 사업자 계정** 권장.
- **핵심 인용**
- **내 질문**
- "필요해질 때 결제"는 초기 비용을 미루는 실용 팁 — 검증 전 과투자 방지.

## 4. 터미널 & cmux — 3개 동시 빌드 · [2:56](https://youtu.be/93wC8kJJYjs?t=176)
- **3줄 요약**
  - 데스크톱 앱(클로드/코덱스)도 좋지만, **여러 작업 동시 실행·도구 기능 활용엔 터미널**이 유리. 맥은 **cmux** 추천.
  - cmux의 킬러 기능은 **푸시 알림** — AI가 작업을 끝내면 알려주니, 기다리며 화면만 보는 시간을 없앤다.
  - 실제로 **A·B·C 앱을 각 탭에서 동시 빌드**, 던져 놓고 끝난 것부터 확인. 앱 공장의 핵심 = **내가 쉬지 않는 게 아니라 AI가 쉬지 않게** 만드는 것.
- **핵심 인용**
- **내 질문**
- "대기 시간에 다른 일 위임" = 병렬화 — 우리도 여러 영상 자막을 병렬로 뽑을 수 있으면 좋겠다(단, 로컬 Chrome 의존이 제약).

## 5. AI 도구 선택 & 권한 열기 — 자율주행의 전제 · [3:53](https://youtu.be/93wC8kJJYjs?t=233)
- **3줄 요약**
  - 선택지는 **클로드 코드(Anthropic)** vs **코덱스(OpenAI)** — 둘 다 훌륭, 대개 큰 차이 없음. **긴 작업은 클로드**, **이미지(아이콘·스크린샷) 병행은 코덱스**가 편해 발표자는 코덱스 선택.
  - 기본 설정은 파일 수정·명령 실행·설치마다 **확인 요청** → 안전하지만 자율주행엔 불리. 개인 프로젝트는 **권한 개방**이 효율적.
  - 클로드 **Auto/Don't Ask Mode**, 코덱스 **Full Access Mode**. (회사·중요 코드는 주의.) 앱 공장은 승인 버튼을 계속 누르는 구조가 아니라 **중요 순간에만 판단**하는 구조.
- **핵심 인용**
- **내 질문**
- "도구 선택보다 환경" — 우리도 어떤 자막 경로냐보다 '안정적으로 굴러가는 파이프라인'이 본질이었다.

## 6. Flutter & 모노레포 — 재사용이 곧 속도 · [5:11](https://youtu.be/93wC8kJJYjs?t=311)
- **3줄 요약**
  - **Flutter**: 하나의 코드로 iOS·안드로이드를 함께 — 여러 앱을 빠르게 시작하기 좋다(가끔 네이티브 전용 코드 필요).
  - 모든 앱을 **모노레포**(하나의 저장소/작업실)로 관리 — 앱스토어 스크린샷·개인정보처리방침 링크·가격 설정·배포 스크립트·공통 디자인 같은 **반복 작업을 한 번 만들어 재사용**.
  - 잘 만든 디자인/기능은 **코드째 다른 앱으로 이식**(스크린샷 모방보다 정확). **속도는 재사용에서** 나온다.
- **핵심 인용**
- **내 질문**
- 모노레포=부품 재사용은 우리 build_gallery(공통 빌더로 노트→갤러리 재생성)와 정확히 같은 철학이다.

## 7. AI 참고 문서 — CLAUDE.md / AGENTS.md · [6:28](https://youtu.be/93wC8kJJYjs?t=388)
- **3줄 요약**
  - AI가 항상 참고할 문서를 만든다: 클로드는 **CLAUDE.md**, 코덱스는 **AGENTS.md** — 프로젝트 시작 시 **가장 먼저 읽는 안내문**.
  - 원칙을 명시: "배포 스크립트는 새로 만들지 말고 공통 재사용", "새 앱은 기존 디자인 시스템 먼저 확인", "개인정보처리방침은 공통 템플릿", "중복 코드 금지".
  - 이러면 **매번 같은 지시를 반복하지 않아도** 되고, 새 세션에서도 AI가 원칙을 이해. **기억을 머릿속이 아니라 AI가 읽을 문서로** 남겨야 한다.
- **핵심 인용**
- **내 질문**
- CLAUDE.md에 원칙을 박아 재사용하는 건 우리 LESSONS.md·프리플라이트 체크리스트와 완전히 같다 — 지식을 문서로 외재화.

## 8. 개발 어휘 & 자율주행(/goal) · [7:31](https://youtu.be/93wC8kJJYjs?t=451)
- **3줄 요약**
  - **개발 어휘**가 실력 — "앱 빨리 만들어줘"보다 "**모노레포 구조로 공통 배포 스크립트 재사용**하게 구성해줘"가 정확. AI 실력 = **질문 실력 = 어휘**.
  - 자율주행 핵심은 **골 명령(`/goal`)**: 목표를 정하면 달성까지 반복. 단, 무작정 "앱 만들어줘"는 엉망 → **먼저 로드맵 문서**(목적·핵심기능·디자인원칙·개발순서·출시 전 체크리스트)를 AI에게 작성시킨다.
  - 로드맵을 **1·2·3단계로 쪼개** `/goal 1단계 진행해줘`처럼 단계별로. 각 단계 후 확인·방향 수정(자기 전에 돌리고 아침에 점검 → **자는 동안에도 개발**).
- **핵심 인용**
- **내 질문**
- "정확한 어휘 = 정확한 지시"는 우리 노트가 ASR 용어를 정확 표기로 교정하는 것과 통한다 — 언어의 정밀함이 결과를 좌우.

## 9. 토큰 절약 — 세션 리셋 습관 · [9:33](https://youtu.be/93wC8kJJYjs?t=573)
- **3줄 요약**
  - 큰 작업이 끝나면 **세션을 닫고 새로 시작**한다. 이유는 **토큰**(AI가 글을 읽고 쓰는 사용량 단위).
  - 대화가 길어질수록 AI가 읽을 컨텍스트가 커져 **같은 일에도 토큰을 더 쓰고 속도도 느려진다**.
  - 그래서 필요한 내용만 **CLAUDE.md/AGENTS.md에 남기고** 새 세션 시작.
- **핵심 인용**
- **내 질문**
- "긴 컨텍스트 = 느림·비용" — 바로 우리 세션이 겪는 것. 중간중간 상태를 파일로 커밋하고 컨텍스트를 비우는 습관과 정확히 일치.

## 10. 앱 홈페이지 & 정리 — 개인정보처리방침·지원 · [10:10](https://youtu.be/93wC8kJJYjs?t=610)
- **3줄 요약**
  - 출시 필수: **개인정보처리방침 링크 + 지원(문의) 페이지**. 거창할 필요 없이 앱 속 방침 + 문의 이메일이면 충분. 호스팅은 **Netlify/Vercel**(무료) 또는 AWS.
  - 모르면 AI에게 "개인정보처리방침·지원 홈페이지 만들어 **Netlify/Vercel에 올리는 과정 단계별로** 도와줘"라고 시키면 파일 생성~배포까지 안내.
  - 전체 정리: 장비 투자 → 개발자 계정 → 터미널+cmux 동시작업 → 코덱스+권한개방 → Flutter+모노레포 → CLAUDE.md/AGENTS.md 원칙 → `/goal` 자율주행 → 세션 리셋. **전체 스크립트·모노레포 템플릿을 GitHub/설명란에 공개**.
- **핵심 인용**
- **내 질문**
- "반복 제거·재사용·위임"의 3원칙은 어떤 생산 파이프라인에도 통하는 보편 원리 — 우리 큐 처리에도 그대로 적용된다.

## TL;DR (5줄)

1. 한 달 30개 앱의 비결은 코딩 속도가 아니라 **AI가 쉬지 않고 일할 '앱 공장' 환경**을 만드는 것.
2. **장비(M5 맥북)** + **개발자 계정** + **터미널·cmux로 3개 동시 빌드**(푸시 알림으로 대기시간 제거).
3. **코덱스 선택 + 권한 개방(Full Access)** 로 자율주행, **Flutter**로 iOS·안드 한 코드, **모노레포**로 부품 재사용.
4. **CLAUDE.md/AGENTS.md**에 원칙을 기록해 반복 지시 제거, **로드맵 + `/goal`** 로 단계별 자율주행(자는 동안에도 개발), **세션 리셋**으로 토큰 절약.
5. 출시엔 **개인정보처리방침·지원 페이지**(Netlify/Vercel)가 필수. 핵심은 **반복 제거·재사용·위임**의 시스템.
