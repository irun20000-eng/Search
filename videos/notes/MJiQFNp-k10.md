# 코딩 몰라도 OK — 클로드로 유튜브 자동 요약 워크플로우 만들기

> 한 줄 요약: 구독 채널의 **전날 영상을 자동 수집→요약→노션 저장**하는 워크플로우를 클로드 코드로 만든다. 흐름: **① YT-DLP(무료 오픈소스)로 메타데이터+자막 수집**(공식 API는 한도·과금) **② channels.txt(추적 채널)·format.md(요약 형식)·output 폴더로 구조화** **③ collect 스크립트로 수집 로직을 고정**(매번 클로드가 고민 = 토큰 낭비, 스크립트가 경제적) **④ CLAUDE.md 인수인계서로 세션 종료 후에도 "어제 거 요약해 줘" 한 마디면 작동** **⑤ 노션 커넥터로 날짜별 저장 ⑥ 로컬 루틴 스케줄링으로 매일 아침 자동**. 핵심 습관: **처음부터 완벽 X → 써 보며 "더 편하게"를 반복해 다듬기**. ※ 이 프로젝트(video2post)와 사실상 동일한 파이프라인.

## 1. 목표 + 전체 흐름 · [00:00](https://youtu.be/MJiQFNp-k10?t=0)
- **3줄 요약**
  - 구독 채널이 10~20개면 매일 영상을 다 못 봄 → **전날 영상을 자동 감지·요약해 한 곳(노션)에** 모으기(요약만 보고 필요한 것만 링크로 시청).
  - 채널 주소만 넣으면 클로드가 어제 영상을 긁어 분석·요약해 노션에 날짜별 정리.
  - 전체 흐름: **영상 수집 → 클로드 요약 → 로컬/노션 저장 → CLAUDE.md 저장 → 스케줄링 자동화**.
- **핵심 인용**: "저는 유튜브 채널 주소만 넣어 놨을 뿐인데 말이죠."
- **내 팁**: 이 영상의 결과물이 바로 이 프로젝트 `video2post`가 하는 일 — 채널 목록·포맷·output·CLAUDE.md·스케줄까지 구조가 동일.

## 2. ★YT-DLP로 무료 수집★ · [03:02](https://youtu.be/MJiQFNp-k10?t=182)
- **3줄 요약**
  - **YT-DLP** = 유튜브 데이터를 받아오는 무료 오픈소스. 공식 API는 하루 한도+초과 시 과금이라 오픈소스가 유리.
  - 내부 원리를 몰라도 됨 — 클로드에 "YT-DLP로 이 영상의 제목·조회수·업로드일·URL·자막 가져와 줘"만 하면 메타데이터+자막을 텍스트로 수집.
  - **자막 데이터가 있으니** 영상을 직접 안 봐도 클로드가 전체 내용을 요약 가능 → 수집+요약을 붙이면 자동화.
- **핵심 인용**: "YTDLP는 오픈 소스이기 때문에 무료로 활용할 수 있습니다."
- **내 질문**: 이 프로젝트는 YT-DLP/공식 API가 막혀 Glasp 자막 스크레이프로 우회 중 — 환경에 따라 수집 경로가 달라진다는 점에서 이 영상의 '무료 수집' 전제가 늘 성립하진 않는 것 아닐까?

## 3. 구조화 — channels.txt · format.md · output · [04:36](https://youtu.be/MJiQFNp-k10?t=276)
- **3줄 요약**
  - 클로드에 **channels.txt(추적 채널 URL, 유튜브 핸들)**와 **output 폴더** 생성 요청.
  - **format.md(요약 형식)**: 그냥 요약하면 매번 제멋대로 → 제목·조회수·핵심요약·타임라인·한 줄 인사이트 등 **원하는 형식을 파일로 정의**하면 항상 같은 구조로 산출.
  - 형식·채널·저장위치는 전부 취향껏 수정 가능.
- **핵심 인용**: "이런 식으로 … 내가 원하는 형식대로 파일을 정의해 두면 매번 데이터가 수집될 때마다 항상 같은 구조로 나오게."
- **내 팁**: format.md로 산출 형식을 고정하는 건 이 프로젝트의 '노트 포맷(프론트매터+챕터+TL;DR)'과 정확히 같은 발상 — 형식 고정이 일관성의 핵심.

## 4. ★스크립트화 + CLAUDE.md 인수인계서★ · [06:40](https://youtu.be/MJiQFNp-k10?t=400)
- **3줄 요약**
  - **collect 스크립트**: "그냥 요약해 줘"도 되지만, 자동화하려면 **수집 로직을 스크립트 파일로 고정**해야 경제적 — 매번 클로드가 방법을 고민하면 토큰 낭비, 스크립트 실행이 저렴. (JSON으로 수집→format에 맞춰 output에 마크다운 저장, "어제 업로드분만, 없으면 스킵"으로 수정.)
  - **CLAUDE.md 인수인계서**: 세션이 끝나면 클로드는 이전 내용을 기억 못 함 → 프로젝트를 열 때마다 먼저 읽는 인수인계서 작성("collect 실행→결과 읽기→format으로 요약→output 저장"). 이후 **"어제 거 요약해 줘" 한 마디면 전 흐름 작동**.
  - 지시 없이 그냥 실행해도 동작하도록 규칙을 CLAUDE.md에 명시.
- **핵심 인용**: "매번 클로드가 알아서 고민하고 작업을 해오는 것보다 … 코드를 만들어 놓게 하고 그 코드를 실행시켜서 정보를 가져오는 것이 토큰 사용량을 비롯해서 여러모로 경제적."
- **내 질문**: 'CLAUDE.md 인수인계서 + 스크립트 고정'은 앞 영상(스펙주도개발 .planning/state.md, 그래프 엔지니어링 작업일지)과 같은 '결정을 파일로 남겨 재개'와 동일 아닐까? 이 프로젝트의 CLAUDE.md/build_gallery.py도 정확히 이 구조.

## 5. 노션 저장 + 스케줄링 + 반복 개선 습관 · [12:11](https://youtu.be/MJiQFNp-k10?t=731)
- **3줄 요약**
  - **노션 저장**: 클로드 데스크탑 설정→커넥터에서 노션 연결 → "결과를 노션에, 이 페이지에 날짜별로"(노션 페이지 ID 붙여넣기) → 날짜별 페이지에 포맷대로 정리. 바뀐 방식은 **CLAUDE.md도 업데이트**.
  - **반복 개선 습관(핵심)**: 마크다운 로컬 → "더 편한 방식 없을까" 고민해 노션으로 → 이 **"어떻게 더 편할까" 반복이 워크플로우를 내 입맛에 맞게 다듬음**. 처음부터 완벽 X, 써 보며 하나씩.
  - **스케줄링**: 불필요 파일 정리 후, 클로드 데스크탑 루틴(로컬 루틴)에 폴더·지침("어제 영상 수집해 노션 저장")·시간 지정. **로컬 루틴은 컴퓨터가 켜져 있어야** 동작(꺼지면 다음 시간대).
- **핵심 인용**: "처음부터 완벽하게 만들려고 하지 말고 써 보면서 하나씩 고쳐 나가시는 것을 추천드립니다."
- **내 팁**: '반복 개선 습관'은 이 프로젝트의 품질 루프(build→review→fix→반복)·LESSONS.md 누적과 정확히 같은 정신 — 워크플로우 자체가 진화 대상.

## TL;DR (5줄)

1. **목표**: 구독 채널의 **전날 영상 자동 수집→요약→노션 저장**(요약만 보고 필요한 것만 링크 시청).
2. **수집(★)**: **YT-DLP**(무료 오픈소스)로 메타데이터+자막 — 공식 API 한도·과금 회피, 원리 몰라도 자연어로.
3. **구조**: **channels.txt**(추적 채널) + **format.md**(요약 형식 고정) + **output** 폴더.
4. **자동화(★)**: **collect 스크립트로 수집 로직 고정**(토큰 절약) + **CLAUDE.md 인수인계서**로 세션 종료 후에도 "어제 거 요약해 줘" 한 마디.
5. **저장·스케줄**: **노션 커넥터**로 날짜별 저장 + **로컬 루틴 스케줄링**(PC 켜져 있어야)으로 매일 아침 자동. 핵심 습관은 **써 보며 반복 개선**. ※ 이 프로젝트와 동일한 파이프라인.
