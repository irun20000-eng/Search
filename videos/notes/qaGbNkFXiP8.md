# 사람 없이 자동으로 굴러가는 AI팀 | Hermes 칸반 멀티에이전트 구축

> 한 줄 요약: **헤르메스(Hermes) 칸반 멀티에이전트 시스템**을 구축하여 사람의 개입 없이 **에이전트 리치(Agent Reach)**로 X와 레딧의 실시간 트렌드를 수집하고, **오케스트레이터와 디스패처**가 부모-자식 작업 의존성을 자동으로 분할·전환하며, **크론(Cron) 스케줄러**를 통해 매일 아침 쇼츠 대본과 HTML 강의 교안을 완전 무인으로 생산하는 자동화 파이프라인 구축 전 과정을 상세히 설명한다.

## 1. ★AI 팀 협업 병목 해결과 에이전트 리치 도입★ · [00:00](https://youtu.be/qaGbNkFXiP8?t=0)
- **3줄 요약**
  - 단일 에이전트 위임 방식은 사람이 중간에서 데이터를 복사·붙여넣기해야 하므로 **인간 병목 현상**이 발생한다.
  - 팀 단위 자동 협업을 가능케 하는 **중앙 관리형 칸반 시스템**을 도입하여 프로세스를 자동화한다.
  - 단순 웹 검색으로 접근이 차단되는 X, 레딧 등의 데이터를 수집하기 위해 **에이전트 리치(Agent Reach)** 도구를 결합한다.
- **핵심 인용**: "팀원은 여러 명인데 일을 넘겨주는 사람은 저 하나인 겁니다 이러면 문제는요 제가 병목이 됩니다."
- **내 팁**: 에이전트 단독 수행 방식 대신 중앙 보드 기반 인수인계 시스템을 도입하여 인간 병목 현상을 해소한다.

## 2. 소셜 플랫폼 실시간 데이터 수집과 쿠키 인증 세팅 · [01:32](https://youtu.be/qaGbNkFXiP8?t=92)
- **3줄 요약**
  - 오픈소스 도구인 **에이전트 리치**는 프롬프트 명령 한 줄로 스킬 문서와 실행 엔진을 가상 서버에 설치한다.
  - 보안 강화를 위해 로그인 쿠키 정보를 프롬프트에 직접 넘기지 않고 **환경 변수(.env) 및 제이슨 크레덴셜**로 분리 설정한다.
  - 스킬 파일 내 라우팅 문서를 통해 **요청 플랫폼에 적합한 가이드**만 선택적으로 참조하도록 컨텍스트 크기를 최적화한다.
- **핵심 인용**: "에이전트 리치는 쉽게 말해서 AI 에이전트에게 인터넷을 제대로 읽어올 수 있는 능력을 쥐어주는 도구라고 봐주시면 되는데요."
- **내 질문**: 쿠키 기반 인증 방식 사용 시 세션 만료 기간에 따른 자동 재인증 모듈 구축 방안이 궁금하다.

## 3. ★헤르메스 칸반 보드의 핵심 메커니즘과 상태 흐름★ · [20:11](https://youtu.be/qaGbNkFXiP8?t=1211)
- **3줄 요약**
  - **칸반 보드**는 에이전트 중심이 아닌 보드가 중심이 되어 각 프로필 팀원에게 작업을 할당하고 공유하는 캔버스다.
  - 개별 작업 단위인 **테스크(Task)**와 부모-자식 의존 관계를 연결하는 **링크(Link)**로 작업 순서를 정의한다.
  - 작업 중간 실패 시 전체 프로세스가 사멸하지 않고 **보드 DB 기록**을 바탕으로 에러 지점부터 재실행이 가능하다.
- **핵심 인용**: "보드가 중심이 돼서 업무를 처리하고 또 일을 나눠준다는 그런 개념입니다."
- **내 팁**: 에이전트 파이프라인 설계 시 작업 실패 시 데이터가 날아가지 않도록 보드 DB에 각 단계 산출물을 즉시 기록한다.

## 4. 칸반 카드 5단계 상태와 오케스트레이터·디스패처 역할 · [34:08](https://youtu.be/qaGbNkFXiP8?t=2048)
- **3줄 요약**
  - 칸반 카드는 **Triage, Todo, Ready, In-Progress, Done**의 5단계 정밀 상태 변화 과정을 거쳐 관리된다.
  - **오케스트레이터(AI)**는 사용자의 거친 목표를 분석해 작업을 세부 분할하고 담당 프로필을 할당한다.
  - **디스패처(엔진)**는 부모 작업이 완료(Done)되면 대기 중인 자식 작업을 자동으로 레디(Ready) 상태로 승격시킨다.
- **핵심 인용**: "부모가 던에 있으면 다음 이어받아야 되는 그 자식을 레디 상태로 옮겨주는 작업만 해주는 애다라고 봐주시면 됩니다."
- **내 팁**: 작업을 나눌 때 부모-자식 의존 관계(Parent-Child)를 아이디 값으로 명확히 연결하여 오케스트레이터와 디스패처가 자동 제어하도록 유도한다.

## 5. ★트렌드 수집 스킬 정의 및 아티팩트 관리★ · [41:47](https://youtu.be/qaGbNkFXiP8?t=2507)
- **3줄 요약**
  - 리서치 프로필에 **트렌드 스카우팅 스킬**을 부여하고 5개 섹션 형태의 정형화된 출력 가이드를 작성한다.
  - 중구난방 저장 방지를 위해 각 프로필의 `soul.md`에 **아티팩트(Artifacts)** 폴더 경로 규격을 통일한다.
  - 수집된 트렌드 데이터는 브리핑 문서로 정리되어 후속 작업 프로필에 매끄럽게 전달되도록 시스템을 구축한다.
- **핵심 인용**: "각 프로필마다 이 산출물들은 규격을 지정해 줬거든요 아티팩트에 모이게끔 해 뒀습니다."
- **내 팁**: 각 프로필별 산출물이 난잡하게 저장되지 않도록 `artifacts` 폴더 규격을 고정하여 관리 효율성을 높인다.

## 6. 오케스트레이터 자동 작업 분할과 크론 기반 완전 자동화 · [48:42](https://youtu.be/qaGbNkFXiP8?t=2922)
- **3줄 요약**
  - 트리아지(Triage)에 목표 등록 시 **오케스트레이터**가 리서치, 교육, 유튜브 제작 팀으로 작업을 자동 할당한다.
  - 리서치 완료 후 **유튜브 쇼츠 대본**과 **HTML 강의 교안 슬라이드** 생성이 병렬 방식으로 진행된다.
  - 트리아지 카드 생성 절차를 **크론(Cron) 스케줄러**에 등록하여 매일 아침 완전 무인 자동화 시스템을 완성한다.
- **핵심 인용**: "이렇게 칸반으로 팀을 연결하고 또 크론까지 걸어서 매일 아침 자동으로 굴러가는 시스템을 만들어 봤습니다."
- **내 팁**: 구축된 칸반 파이프라인의 트리아지에 매일 아침 크론 스케줄러를 적용하여 무인 자동화 시스템을 완성한다.

## TL;DR (5줄)
1. **인간 병목 해소**: 수동 데이터 전달 대신 헤르메스 중앙 칸반 보드를 도입해 팀 간 자동 인수인계 체계를 구축한다.
2. **소셜 데이터 수집**: 에이전트 리치를 활용하여 보안 검색이 막힌 X와 레딧의 최신 기술 트렌드를 실시간 수집한다.
3. **칸반 구조화**: 작업(Task), 부모-자식 링크(Link), 상태(5단계)를 통해 작업 실패 시에도 안전한 지속성을 확보한다.
4. **역할 분담 자동**: AI 오케스트레이터가 작업을 분할하고 디스패처 엔진이 단계별 승격을 자동 제어한다.
5. **무인 시스템 완성**: 크론 스케줄러를 적용해 매일 아침 트렌드 분석, 쇼츠 대본, HTML 교안 생성을 완전 자동화한다.
