# 클로드로 코딩 1줄 없이 제작부터 배포까지 | 매일 하던 반복 업무, AI에게 넘겼습니다

> 한 줄 요약: 직장인의 반복 업무(회의 취합·출력)를 **코딩 1줄 없이** 실제 동작하는 웹앱으로 만들어 **URL 배포**까지. 흐름은 **3스테이지**: ①**정리**(목적·입력·출력·제약을 폼으로 받아 "이 양식으로 정리해줘") → ②**VS 코드+클로드 코드로 에이전트 구현**(데스크탑 앱보다 파일 확인·수정이 빨라 추천, 모델은 옵스) → ③**슈퍼베이스(DB)+버셀(배포)** 결합. 핵심 개념을 비유로: **버셀=파리바게트 매장(프론트, 도메인 URL)**, **슈퍼베이스=본사 공장(백엔드 DB, 내가 없어도 24시간 동작)**, **MCP=AI용 멀티탭/USB 규격**(외부 서비스를 한 규격으로 연결). 실전: **3사이트 로그인**(깃허브=코드 저장·버전관리[반드시 프라이빗] / 슈퍼베이스=DB / 버셀=배포), 프로젝트 아이디·MCP 토큰 발급(**.gitignore로 키 보호**), 로컬호스트로 먼저 확인 후 버셀 배포 → **URL만 있으면 누구나 접속**해 실시간 공동 편집(한글 복사·PDF 인쇄). 마무리: 화면만 보면 대부분 헤매니 **여러 번 유지보수**가 핵심.

## 1. ★스테이지1 — 무엇을 만들지 명확히 정리★ · [00:38](https://youtu.be/hmWSM6HMyZU?t=38)
- **3줄 요약**
  - 챗봇 대화만 하는 건 "오성급 뷔페서 샐러드만 먹는 것". 실제 동작하는 회의 시스템(실시간 투표·유관부서 핸드폰 의견 취합)을 구현.
  - 수강생에게 **가장 반복적·시간 드는 작업, 이상적 결과물, 단계별 워크플로우**를 물음. AI는 명확히 전달 안 하면 모호한 결과.
  - **목적·입력·출력·제약**을 폼으로 받아 "이 양식으로 정리해줘"로 규정 = 스테이지1.
- **핵심 인용**: "AI는 명확하게 전달해 주지 않으면 모호한 결과물을 생성하기 때문에… 목적, 입력, 출력, 제약 조건들을 정리해서."
- **내 팁**: '목적·입력·출력·제약 먼저'는 이 큐레이션 투쏠(매니페스트 기획)·에디스와 같은 기획 우선 — 도구만 다르고 앞단 정의가 공통 첫 단계.

## 2. ★스테이지2 — VS 코드+클로드 코드로 에이전트 구현★ · [02:06](https://youtu.be/hmWSM6HMyZU?t=126)
- **3줄 요약**
  - **VS 코드**(개발자 도구)로 구현 — 클로드 데스크탑 앱보다 **파일 확인·수정이 빠름**(데스크탑 앱은 무겁고 로딩 김). 폴더 세팅 후 **클로드 코드 익스텐션**(엔트로픽 공식) 설치, 터미널로 계정 연결.
  - 정리한 입력·출력·제약을 붙여 "이 내용으로 에이전트 만들어줘". 모델은 **옵스**(페이블>옵스>소넷>하이쿠, 세션 빨리 차면 소넷).
  - 비개발자는 **익스텐션**이 쉽고, 터미널(cmd 화면)이 가장 빠름.
- **핵심 인용**: "VS 코드를 사용할 수 있다면 굳이 클로드 데스크탑을 사용할 이유는 없다… 데스크탑 앱은 조금 더 무겁고."
- **내 질문**: 이 편은 큐레이션 디자이너 DK(데스크탑 앱 추천)와 반대 결 — DK는 시각 편집(브라우저 셀렉트), 레인은 파일 확인·속도. 목적에 따라 GUI vs 코드 편집기 선택 아닐까?

## 3. ★핵심 개념 비유 — 버셀·슈퍼베이스·MCP★ · [07:00](https://youtu.be/hmWSM6HMyZU?t=420)
- **3줄 요약**
  - 각자 PC에만 저장돼 공유 불가한 문제 → **슈퍼베이스 MCP 연결 + 버셀 배포**로 해결. 웹으로 남들이 들어오려면 **DB와 배포 사이트가 융합**돼야.
  - 비유: **버셀=파리바게트 매장**(손님이 빵 고르는 프론트엔드, 도메인 URL) / **슈퍼베이스=본사 공장**(백엔드 DB, 내 매장이 닫혀도 24시간 동작, PDF·문서·회원 이메일 보관). DB는 슈퍼베이스 or 네온.
  - **MCP = AI용 멀티탭/USB 연결 규격** — 메일·드라이브·캘린더를 각각 연결하던 걸 하나의 규격으로. AI에게 손발을 달아주는 열쇠.
- **핵심 인용**: "MCP는 AI용 멀티탭 또는 USB 연결 규격이라고 생각해 주시면 좋아요… AI에게 손과 발을 달아주는 열쇠."
- **내 팁**: 이 비유(매장/공장/멀티탭)는 비개발자에게 프론트·백·MCP를 설명하는 최고의 온보딩 — 이 갤러리 MCP 관련 편들의 개념 보조 자료로 유용.

## 4. ★실전 배포 — 3사이트 로그인 + 토큰·키 관리★ · [12:19](https://youtu.be/hmWSM6HMyZU?t=739)
- **3줄 요약**
  - **3사이트 로그인**: ①**깃허브**(코드 저장·버전관리·복구, 레포=폴더 **반드시 프라이빗**) ②**슈퍼베이스**(DB, 깃허브로만 연결) ③**버셀**(배포, 무료 Hobby, **임포트 깃 레포**).
  - 슈퍼베이스 **프로젝트 아이디**+**MCP 연결 토큰** 발급해 에이전트에 전달. 변경사항은 **커밋**(Ctrl+S 유사)으로 깃허브 저장.
  - ★**보안**: 토큰·키는 공유 금지, **.gitignore로 중요 키 보호**(클로드/코덱스는 채팅 입력도 위험하게 봄). 버셀 토큰은 한 번만 표시.
- **핵심 인용**: "깃 이그노어라고 하는 게, 중요한 키 같은 것들은 공유되지 않도록 정리를 해 두는 거라서."
- **내 질문**: '.gitignore·프라이빗 레포·토큰 1회 표시'는 이 프로젝트의 배포 보안(로컬 git·키 관리)과 같은 원칙 — 비개발자 자동화에도 보안 위생이 필수 아닐까?

## 5. 로컬 확인 → 버셀 배포 → 실시간 공유 + 유지보수 · [20:09](https://youtu.be/hmWSM6HMyZU?t=1209)
- **3줄 요약**
  - 배포 전 **로컬호스트로 먼저 띄워** 레이아웃·동작 확인(외부인은 못 들어옴). 매직 링크가 불편해 **팀 이메일 등록 방식**으로 변경(소규모는 편리함 우선, 보안은 유지보수로 강화).
  - **버셀 배포** 완료 → **URL만 있으면 누구나 접속**해 실시간 공동 편집. 회의체 생성·업무 추가·주차 취합, **한글 복사(양식 유지)·PDF 인쇄** 연결.
  - 화면만 보면 대부분 헤맴. 한 번에 만족 안 되니 **이미지 레퍼런스·캡처로 여러 번 유지보수**해 자기 것으로. (오늘 내용은 개인 업무와 100% 일치하진 않음)
- **핵심 인용**: "보통은 한 번에 만족하시지 않을 확률이 높아요. 여러 번 유지보수를 해 주시면 더 원하는 결과물의 형태로 가까워지기 때문에."
- **내 팁**: '로컬 확인→배포→반복 유지보수'는 이 프로젝트 품질 루프와 동일 — 배포는 끝이 아니라 반복 개선의 시작점.

## TL;DR (5줄)

1. **3스테이지**: ①목적·입력·출력·제약 정리 → ②VS 코드+클로드 코드 에이전트(옵스) → ③슈퍼베이스+버셀.
2. **개념 비유(★)**: 버셀=매장(프론트·URL), 슈퍼베이스=본사 공장(백엔드 DB 24시간), MCP=AI용 멀티탭/USB.
3. **3사이트**: 깃허브(코드·버전, 프라이빗)·슈퍼베이스(DB, 깃허브 연결)·버셀(배포, 깃 레포 임포트).
4. **보안(★)**: 프로젝트 아이디·MCP/버셀 토큰 발급, .gitignore로 키 보호, 커밋으로 변경 저장.
5. **배포·유지보수**: 로컬 확인→버셀 배포→URL만 있으면 누구나 실시간 공동 편집(한글 복사·PDF). 여러 번 유지보수가 핵심.
