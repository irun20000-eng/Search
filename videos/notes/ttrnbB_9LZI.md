# 옵시디언과 클로드 총정리 — 카파시 LLM 위키로 만드는 '회사 도서관(제2의 뇌)'

> 한 줄 요약: 카파시(Karpathy)의 **LLM 위키**(Raw 원본 / Wiki 정리 MD / Schema 규칙문서 3레이어)를 옵시디언+클로드 코드로 구현해 **'회사의 두뇌=도서관'**을 만드는 실전. 작업용 폴더에서 **확정본만** 도서관으로 승인 이동, AI 사서가 새벽에 자동 분류·위생검사, log.md로 모든 AI 접근 추적. 화면 녹화 확장으로 **업무 SOP 매뉴얼(클릭·이미지 캡처)**을 자동 생성해 위키에 적재 → 온보딩·인수인계 자동화. 핵심은 "개념보다 활용", "회사 맥락을 AI에 다 줘라".

## 1. LLM 위키란 + 카파시 · [0:32](https://youtu.be/ttrnbB_9LZI?t=32)
- **3줄 요약**
  - 대상: 1인 프리랜서·사업자 등 온라인 비즈니스 하는 모든 사람. 주제는 요청 많았던 'LLM 위키'.
  - **카파시** = 오픈AI·테슬라·앤트로픽 출신 AI 대가. 복잡한 개념을 실용적으로 정리하는 가이드로 유명, 두 달 전부터 '제2의 두뇌 만들기'로 국내 확산.
  - 기존: AI에 PDF/CSV를 **매번** 주고 요청. LLM 위키: 모든 자료를 하나의 **허브**로 만들고 AI를 붙임 → 매번 안 줘도 허브 기반으로 답 → 편리 + 할루시네이션↓.
- **핵심 인용**: "이 모든 것들을 하나의 약간 허브처럼 만들고 AI를 이제 갖다 붙이는 거죠."
- **내 질문**: '매번 컨텍스트 주입' → '지속 허브 참조'로의 전환은, 프롬프트 엔지니어링에서 지식 아키텍처링으로 무게가 옮겨가는 신호 아닐까?

## 2. 3레이어 구조 — Raw / Wiki / Schema · [2:56](https://youtu.be/ttrnbB_9LZI?t=176)
- **3줄 요약**
  - 위키(자료)와 LLM(AI)을 연결 — 클로드에 자료를 주면 클로드가 **'사서'**로 도서관에 정리.
  - 카파시 3레이어: ① **Raw**(원본 파일) ② **Wiki**(AI 정리 마크다운 MD) ③ **Schema**(claude.md·agents.md 규칙 문서). + index.md·log.md(탐색·기록).
  - 쓸수록 MD 자산이 쌓이고 MD끼리 연결돼 **업무 맥락**이 이어짐(과거 잘된 유튜브 원고·기획이 유기적으로 묶임). 확장성: 퍼플렉시티·외부 MCP 결합.
- **핵심 인용**: "로우는 원본 데이터, 위키는 AI가 정리한 자료(MD), 스키마는 claude.md·에이전트.md 같은 규칙 문서."
- **내 팁**: '원본 보존(Raw) + 파생 정리(Wiki) + 규칙(Schema)' 3단 분리는 어떤 개인 지식 시스템에도 이식 가능한 골격.

## 3. '회사 도서관' 운영 원리 — 확정본만 · [7:34](https://youtu.be/ttrnbB_9LZI?t=454)
- **3줄 요약**
  - **작업용 폴더**(초안)와 **도서관 폴더**(확정본) 분리 — 승인한 것만 도서관으로 이동("다 쓴 책만"). N폴더는 개인용.
  - AI가 직접 두뇌를 읽음: 슬랙의 헤르메스 에이전트, 클로드의 '김미사'가 도서관 접근 → 어떤 커뮤니케이션 툴에서든 접근.
  - **한 자료는 한 자리**(중복 금지), 애매하면 인박스 → **새벽에 AI 사서가 자동 분류**. 삭제 대신 낡은 건 레거시로.
- **핵심 인용**: "일을 하는 폴더가 따로 있고 기억하는 폴더가 따로 있고 개인용어 따로따로 있습니다."
- **내 질문**: '확정본만 도서관'이라는 규율이 위키의 신뢰도를 지키는 핵심 — 초안/확정의 경계를 사람이 승인하는 게 병목이자 품질장치 아닌가?

## 4. AI 사서 자동화 — 야간 정리·위생검사·추적 · [11:16](https://youtu.be/ttrnbB_9LZI?t=676)
- **3줄 요약**
  - 도서관 입구에 **AI용 안내판 + 사람용 지도**, `log.md`에 AI가 건드릴 때마다 기록 → 여러 AI가 써도 **추적 가능**.
  - **야간 사서**(새벽 인박스 정리), **위생 검사**(새벽 3:15 오래된 자료 검사→리포트·제안), 월요일 **주간 리포트** → 감독하 자동 운영.
  - "정답 없다 — 개인 목적에 맞게 편리하면 됨." 옵시디언 그래프뷰로 맥락 연결 시각화.
- **핵심 인용**: "야간 사서 새벽에 우리 인박스에 정리되어 있는 것들을 AI가 알아서 좀 정리를 하도록 구축."
- **내 팁**: 자동화는 '무인'이 아니라 **'감독하 자동'** — AI가 제안하고 사람이 승인하는 루프가 지속가능성의 열쇠.

## 5. 실제 구축 방법 — 폴더→VS Code→클로드 코드→회사정보 · [12:50](https://youtu.be/ttrnbB_9LZI?t=770)
- **3줄 요약**
  - ① 폴더 생성 → ② VS Code로 열기 → ③ 클로드 코드 실행(확장 or 터미널; 발표자는 클로드 코드 '앱'에서 **마이크로 음성** 작업, 이미지도 바로 읽음).
  - 카파시 깃허브 자료를 복사해 붙여넣고 "위키 만들자" → 3레이어(Raw/Wiki/claude.md) 자동 생성. "어디에 쓸 건가?"에 **'사업/회사 위키'** 선택.
  - 회사 위키는 **회사 정보·자료를 많이 줘야** 대표 수준으로 앎 — 노션 연동 임베딩, 구글 워크스페이스(시트·docs·드라이브) 접근 명령. index.md(카탈로그)·log.md 생성.
- **핵심 인용**: "우리 회사, 우리 비즈니스에 활용할 위키를 만드는 거면 당연히 필요한 건 우리에 대한 정보·자료·데이터를 많이 줘야."
- **내 질문**: 위키 품질 = 투입한 회사 맥락의 양·정합성. 민감정보(구글 드라이브 전체 임베딩)의 보안 경계는 어떻게 긋나?

## 6. ★업무 SOP 자동 생성 — 화면 녹화 확장 → 위키 적재★ · [18:25](https://youtu.be/ttrnbB_9LZI?t=1105)
- **3줄 요약**
  - 활용 핵심: 모든 업무 워크플로우를 **SOP(표준 업무 지침서)**로 세분화 기록. 화면 녹화 확장으로 '녹화 시작→실제 업무(스프레드시트·PDF·노션)→정지'.
  - '녹화 편집'이 클릭·이미지 캡처·설명을 **자동으로 업무 매뉴얼**로 정리 → 마크다운/PDF/노션 등으로 저장.
  - 압축 풀고 경로 복사 → "이 폴더 확인해서 위키에 추가해 줘" → 클로드가 **원본을 Raw 보존 + 파생 지식 페이지 생성**. 온보딩·인수인계·반복업무 자동화, 출처·맥락까지 이해된 고품질 답변.
- **핵심 인용**: "이게 이제 하나의 업무 인수인계의 매뉴얼이 되는 거예요."
- **내 팁**: 화면 녹화→자동 SOP는 '암묵지의 형식지화' — 사람이 하던 절차를 캡처+설명으로 굳혀 AI가 재현 가능한 지식으로 전환.

## 7. 비즈니스 위키 3원칙 + 3D 위키 전망 · [22:17](https://youtu.be/ttrnbB_9LZI?t=1337)
- **3줄 요약**
  - 3원칙: ① 대표/개인용 위키도 따로(기밀·공유 어려운 정보) ② 팀 공용 위키는 **지속가능한 운영 시스템**으로 ③ 회사 맥락을 AI가 파악하게 **다 줘라**(화면 녹화도 맥락 도구).
  - 완료 로그: 인제스트→파일 생성, 파생·카탈로그 정리, log.md 기록.
  - 전망: 슬랙+뒷단 DB의 모든 맥락(대화 로그)을 **위키화**해 **3D로 시각화**, 헤르메스 에이전트·프로젝트·MCP·스킬·AI 모델을 연동 준비 중.
- **핵심 인용**: "우리 회사 관점에서 모든 팀원들이 참고해야 하는 위키는 그 형태에 맞게끔 만드는 게 첫 번째로 중요."
- **내 질문**: '슬랙 대화 로그=맥락'이라는 관점은, 커뮤니케이션 자체를 지식 자산으로 재활용하는 발상 — 어디까지가 유용한 맥락이고 어디부터가 노이즈인가?

## TL;DR (5줄)

1. **개념**: 카파시 LLM 위키 = Raw(원본)/Wiki(정리 MD)/Schema(규칙) 3레이어를 옵시디언+클로드로 구현한 '회사 도서관(제2의 뇌)'.
2. **운영**: 작업용↔도서관 폴더 분리, **확정본만 승인 이동**, 한 자료 한 자리, 애매하면 인박스.
3. **자동화(감독하)**: log.md로 AI 접근 추적, 야간 사서 분류 + 새벽 위생검사·주간 리포트, 삭제 대신 레거시.
4. **구축**: 폴더→VS Code→클로드 코드→카파시 깃허브 자료로 3레이어 생성 → **회사 정보(노션·구글 워크스페이스)를 대량 임베딩**.
5. **핵심 활용(★)**: 화면 녹화 확장으로 **업무 SOP 매뉴얼을 자동 생성**해 위키에 적재 → 온보딩·인수인계·반복업무 자동화. 비즈니스 위키 3원칙: 개인용 병행 / 지속가능 시스템 / 회사 맥락 전부 주기.
