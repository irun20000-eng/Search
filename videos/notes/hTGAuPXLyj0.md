# 클로드로 홈페이지 만들기 전에 이건 꼭 보세요!

> 한 줄 요약: 클로드로 홈페이지를 만들면 **어디서 많이 본 디자인에 비슷비슷한 폰트·색상**이 나와 AI 티가 난다는 문제에서 출발해, 그것을 걷어내는 **방법 세 가지**를 화면 그대로 보여 주는 영상이다 — ① **피그마 MCP를 커넥터로 연결**해 클로드가 피그마에 시안을 만들게 하고 **폰트·이미지·컬러를 피그마에서 직접 고친 뒤 그 파일로 코딩을 시키면** 말로 수정을 요청할 때와 달라 **여러 번 고쳐야 하는 경우라면 시간과 토큰을 아끼는 데 도움이 되고**(MCP 호출 한도에 걸리면 **피그마를 열어 두고 컴퓨터로 직접 접근하게** 시킨다), ② **디자인 스킬 장착** — 앤트로픽이 만든 **프론트엔드 디자인** 스킬과 **57가지 UI 스타일·95가지 색상 팔레트·56가지 글꼴 조합**이 들어 있는 **UI UX 프로 맥스** 스킬을 설치해 쓰면 프롬프트만 넣었던 결과와 퀄리티가 다른 것 같다고 평하고, ③ **어워즈에서 레퍼런스 사이트를 찾아** 주소를 주고 **똑같이 만들지 말고 레이아웃·인터랙션·모션만 참고하라**고 요청하면 코딩 용어를 몰라도 인터랙션이 있는 사이트까지 만들 수 있다는 것이다.

## 1. ★왜 AI가 만든 티가 나는가★ · [00:00](https://youtu.be/hTGAuPXLyj0?t=0)
- **3줄 요약**
  - 클로드로 홈페이지를 만들어 보면 **어디서 많이 본 것 같은 디자인에 비슷비슷한 폰트와 색상**이 나오고, 어딘가 **AI가 만든 티**가 난다는 데서 영상이 출발한다.
  - **전문 디자이너가 제작한 사이트와 비교하면 뭔가 부족한 느낌**이 들었을 것이라고 짚는다.
  - 그래서 오늘 다룰 것은 **AI 티 안 나는 고퀄리티 홈페이지를 만드는 방법**이고, **총 세 가지**를 하나씩 보여 준다고 예고한다.
- **핵심 인용**: "어디서 많이 본 것 같은 디자인에 비슷비슷한 폰트랑 색상 어딘가 AI가 만든 티가 나는 홈페이지가 나오죠."
- **내 팁**: 세 방법은 겹쳐 쓰는 순서로 짜여 있다 — **피그마로 고칠 길을 열고 → 스킬로 기본 품질을 올리고 → 레퍼런스로 방향을 준다**. 하나만 고르려면 수정이 잦은 쪽은 1번, 한 번에 뽑고 싶은 쪽은 2·3번이 맞다.

## 2. 방법 ① 왜 피그마 MCP인가 — 커넥터로 연결하기 · [00:33](https://youtu.be/hTGAuPXLyj0?t=33)
- **3줄 요약**
  - 클로드에 홈페이지를 만들어 달라고 하면 **디자인부터 코딩까지 완료된 홈페이지**를 만들어 주는데, 불편한 점이 하나 있다. **디자인을 수정하기가 어렵다**는 것이다.
  - 폰트를 20포인트로 바꿔 달라거나 이미지를 오른쪽으로 조금 더 옮겨 달라는 식으로 요청하는 게 번거롭고, **수정할 때마다 클로드가 코드를 다시 작성해야 해서 시간도 토큰도 많이 든다**.
  - 그래서 **피그마 MCP를 연결**한다. 자막은 발표자가 클로드를 「클라우드」로 말한 대목을 여러 곳에 담고 있는데, 노트는 본문에서 클로드로 통일했다. 연결 경로는 클로드 프로그램에서 **프로필 → 설정 → 맨 아래 커넥터 → 탐색 → 피그마 검색 → 연결**이다(클로드를 아직 받지 않았으면 구글에서 클로드 다운로드를 검색해 설치한다). 연결하면 **클로드가 홈페이지 디자인을 피그마에 만들어 준다**.
- **핵심 인용**: "수정할 때마다 클로드가 코드를 다시 작성해야 하니까 시간도 오래 걸리고 토큰도 많이 사용하게 되죠."
- **내 팁**: 이 장의 이유는 **디자인 수정의 비용**이다. 한 번 뽑아 끝낼 페이지라면 커넥터를 붙이는 수고가 더 클 수도 있으니, **고칠 횟수가 여러 번 예상될 때** 1번 방법을 꺼내는 편이 맞다.

## 3. 피그마에 시안 만들기 — MCP 호출 한도에 걸릴 때 · [01:38](https://youtu.be/hTGAuPXLyj0?t=98)
- **3줄 요약**
  - 요청은 **무엇을 만들지 + 어떤 느낌으로 + 피그마 MCP로 시안을 보여 달라 + 내가 시안을 확인하고 코딩으로 구현하고 싶다**는 네 가지를 한 번에 적는 형태다. 영상에서는 병원 홈페이지를 예로 들고, 피그마의 어느 팀에 만들지 고르게 한다.
  - 실제로 돌리자 **MCP 호출 한도에 걸려 페이지를 만들지 못한다는 알림**이 떴다. 그때의 우회는 **피그마 프로그램을 열어 두고 클로드가 직접 컴퓨터로 접근해 만들게 하는 것**이다. 그러자 클로드가 컴퓨터에 접근해 **피그마 파일에 디자인을 직접 만들어** 냈다.
  - 결과물에 대해 **생각보다 시안 디자인을 굉장히 깔끔하게 잘 만들어 줬다**고 평하고, **무료 이미지를 써서 적절하지 않게 들어간 이미지들은 피그마에서 직접 바꿀 수 있다**고 덧붙인다.
- **핵심 인용**: "피그마 프로그램을 열어 놓을 테니 네가 직접 컴퓨터로 접근해서 만들어 줘."
- **내 질문**: 호출 한도 알림이 떴을 때의 우회가 **왜 통하는지**는 설명되지 않는다. 같은 알림이 반복될 때 기다려야 하는지, 열어 둔 피그마로 매번 넘겨야 하는지도 영상이 다루지 않는다.

## 4. 피그마에서 고친 뒤 그 파일로 코딩시키기 · [02:55](https://youtu.be/hTGAuPXLyj0?t=175)
- **3줄 요약**
  - 피그마로 시안이 만들어지면 좋은 점은 **원하는 폰트가 있으면 바로바로 변경할 수 있다**는 것이다. 말로 하나하나 요청하면 귀찮은 일을 **피그마에서 직접 수정해 훨씬 편해진다**고 말한다.
  - 원하는 부분을 다 고치고 **컬러나 배경 같은 것도 원하는 색으로 쉽게 바꿀 수** 있다. **디자인을 여러 번 수정해야 하는 경우라면 작업 시간과 토큰을 절약하는 데 도움이 된다**는 것이 이 방식의 이점으로 제시된다.
  - 피그마에서 충분히 수정해 완성한 다음에는 **현재 수정된 피그마 파일을 홈페이지로 코딩 구현해 달라**고 요청하면, 그 수정된 디자인으로 홈페이지가 구현된다.
- **핵심 인용**: "피그마로 시안이 만들어지면 좋은 게요. 내가 원하는 폰트가 있으면 폰트도 바로바로 변경이 가능하고요."
- **내 팁**: 순서가 핵심이다 — **고칠 것을 피그마에서 다 끝낸 뒤 한 번만 코딩을 시킨다**. 코딩을 먼저 시키고 거기서 고치기 시작하면 2장이 지적한 비용(코드 재작성·토큰)으로 되돌아간다.

## 5. 방법 ② 디자인 스킬 장착 — 프론트엔드 디자인과 UI UX 프로 맥스 · [03:44](https://youtu.be/hTGAuPXLyj0?t=224)
- **3줄 요약**
  - 클로드에 **디자인 스킬을 장착하면 훨씬 더 높은 퀄리티의 홈페이지 시안**을 받을 수 있다고 말한다. 설치법은 **「이 스킬 설치해 줘」라고 하고 스킬 주소를 붙여 넣는 것**이다(주소는 영상 더보기에 있다고 안내한다).
  - 첫 번째는 **프론트 엔드 디자인** 스킬이다. **클로드를 만든 앤트로픽 회사에서 만든 스킬**이라며(자막은 「엔트로픽」으로 잡았다), **흔한 글꼴을 사용하지 않고 평범하지 않은 독창적인 디자인을 해 준다고 한다**고 소개한다.
  - 두 번째는 **UI UX 프로 맥스** 스킬로, **57가지 UI 스타일과 95가지 색상 팔레트, 56가지 글꼴 조합**이 들어 있다. **만들고자 하는 사이트에 적합한 디자인을 알아서 찾아 적용**해 주는 것이고, 같은 방식으로 주소를 붙여 설치한 뒤 **플러그인 저장**을 누르면 클로드에 저장된다.
- **핵심 인용**: "그래서 흔한 글꼴을 사용하지 않고 평범한 디자인이 아닌 독창적인 디자인을 해준다고 합니다."
- **내 팁**: 스킬 소개는 전언 형태로 지나간다. 두 스킬이 각각 무엇을 바꾸는지는 다음 장의 결과 하나로만 확인되니, 쓸 때는 **스킬을 하나씩 켜 보고 결과를 비교**하는 쪽이 어느 쪽이 듣는지 알기 쉽다.

## 6. 스킬을 켜고 실제로 만들어 비교하기 · [04:53](https://youtu.be/hTGAuPXLyj0?t=293)
- **3줄 요약**
  - 로고 디자인 회사 홈페이지를 예로 **두 스킬을 활용해 제작해 달라**고 요청한다. 요청문에는 **폰트와 컬러, 레이아웃을 전문가처럼 구현해 달라**는 것과 **디자인 에이전시에서 제작한 것처럼 완성도 높은 결과물을 만들어 달라**는 조건이 함께 들어간다.
  - 완성된 결과를 열어 보고 **기존에 프롬프트만 넣었던 홈페이지와는 퀄리티가 좀 다른 것 같다**고 평한다. **애니메이션도 들어가 있다**는 점을 눈에 보이는 차이로 든다.
  - 정리하면서 **스킬을 활용해 디자인을 해서 그런지 기존의 템플릿처럼 만들어 준 것과는 차이가 있는 것 같다**고 말한다.
- **핵심 인용**: "기존에 프롬프트만 넣었던 홈페이지랑은 퀄리티가 좀 다른 거 같아요."
- **내 질문**: 비교는 **화면을 보며 다른 것 같다고 말하는 데서** 끝난다. 같은 주제로 스킬 없이 만든 결과와 무엇이 어떻게 다른지는 말로만 짚고 지나가, 차이가 어디서 왔는지는 영상만으로 가릴 수 없다.

## 7. 방법 ③ 어워즈에서 레퍼런스 찾기 · [05:41](https://youtu.be/hTGAuPXLyj0?t=341)
- **3줄 요약**
  - **두 가지 스킬만으로는 좀 부족한 느낌이 있을 것**이라며 마지막 방법을 꺼낸다. **어워즈 레퍼런스를 넣으면 굉장히 퀄리티가 달라진다**는 것이다(사이트 주소는 영상 더보기에 있다고 안내한다).
  - 발표자가 고른 레퍼런스는 **화면을 내리면 애니메이션이 들어가고 인터랙션이 있는 사이트**다.
  - 그 **사이트 주소를 복사해 클로드에 요청**하는 것이 이 방법의 전부다. 다음 장에서 그 요청문과 결과를 그대로 보여 준다.
- **핵심 인용**: "제가 알려드린 두 가지 스킬만으로는 좀 부족한 느낌이 있으실 거예요. 자 마지막으로 이 어워즈 레퍼런스를 넣으시면 굉장히 퀄리티가 달라집니다."
- **내 팁**: 레퍼런스는 **스크롤에 따라 무엇이 움직이는지**가 보이는 사이트를 고르는 것이 요령으로 읽힌다. 정지 화면만 예쁜 곳을 주면 다음 장에서 참고하라고 적을 **인터랙션·모션**이 애초에 없다.

## 8. ★레퍼런스는 베끼지 않는다 — 레이아웃·인터랙션·모션만★ · [06:14](https://youtu.be/hTGAuPXLyj0?t=374)
- **3줄 요약**
  - 요청문은 두 겹이다. 먼저 **법무법인 홈페이지를 만들 것이고 이 사이트를 참고하라**고 하면서 **단 똑같이 만들지 말고 레이아웃·인터랙션·모션만 참고해 달라**고 못 박는다.
  - 다음으로 **기존에 만들어져 있던 법무법인 사이트 주소**를 주며 **이 사이트에서는 내용만 참고하고 디자인은 세련되면서 신뢰감이 드는 느낌으로 새로 만들어 달라**고 요청한다. 이미지는 **상업적 이용이 가능한 무료 이미지를 사용해 달라**는 조건을 붙인다.
  - 결과물은 **스크롤을 내릴 때마다 인터랙션이 작동하고 배경 컬러가 바뀌며 애니메이션이 들어간** 페이지였고, 미리 첨부한 이미지들이 그 자리에 들어갔다. 그래서 **코딩 용어를 모르는 사람도 레퍼런스 사이트를 넣으면 인터랙션 사이트까지 만들 수 있다**고 정리한다.
- **핵심 인용**: "단 똑같이 만들지 말고 레이아웃, 인터랙션, 모션만 참고해 줘."
- **내 팁**: 요청문이 **참고할 것(레이아웃·인터랙션·모션)과 가져올 것(내용)과 새로 만들 것(디자인)을 각각 다른 출처에 배정**한 점이 이 장의 알맹이다. 레퍼런스를 줄 때 이 세 칸을 적어 두면 비슷하게 만들어 달라고 뭉뚱그릴 때와 결과가 달라진다.

## 9. 정리 — 말로만 설명하지 말고 보여 주기 · [07:34](https://youtu.be/hTGAuPXLyj0?t=454)
- **3줄 요약**
  - 맺으며 **클로드에게 홈페이지 제작을 맡길 때 말로만 설명하는 것보다 이미지나 사이트 주소를 보여 주면 퀄리티가 달라진다**고 요지를 밝힌다.
  - 다시 한번 정리하는 세 가지는 **① 피그마에 디자인 구현하기 ② 스킬 추가하기 ③ 레퍼런스 사이트 추가하기**다.
  - **다음 주에는 클로드로 PPT 만드는 방법**을 예고하며 닫는다. 끝에 홈페이지 제작 문의 안내가 붙는다 **(홍보 구간 — 학습 내용과 분리)**.
- **핵심 인용**: "다시 한번 정리를 해 볼까요? 첫 번째 피그마에 디자인 구현하기, 두 번째 스킬 추가하기, 세 번째 레퍼런스 사이트 추가하기입니다."
- **내 질문**: 세 방법의 효과는 모두 **발표자가 화면을 보며 내린 인상**으로 평가된다. 로딩 속도나 모바일에서의 모양처럼 눈에 덜 보이는 품질은 영상이 확인하지 않는다.

## TL;DR (5줄)
1. **문제**: 클로드로 만든 홈페이지는 **많이 본 디자인에 비슷비슷한 폰트·색상**이라 AI 티가 난다. 그걸 걷어내는 방법 세 가지를 차례로 보여 준다.
2. **피그마 MCP**: 커넥터에서 피그마를 연결하면 클로드가 **피그마에 시안을 만들고**, 폰트·이미지·컬러를 **피그마에서 직접 고친 뒤 그 파일로 코딩**시킬 수 있어 **여러 번 수정해야 하는 경우라면 시간과 토큰을 아낀다**. 호출 한도에 걸리면 **피그마를 열어 두고 직접 접근하게** 시킨다.
3. **디자인 스킬**: 앤트로픽이 만든 **프론트엔드 디자인** 스킬과 **57가지 UI 스타일·95가지 색상 팔레트·56가지 글꼴 조합**이 든 **UI UX 프로 맥스** 스킬을 주소로 설치해 함께 쓴다.
4. **레퍼런스**: **어워즈**에서 인터랙션이 있는 사이트를 골라 주소를 주고 **똑같이 만들지 말고 레이아웃·인터랙션·모션만 참고하라**고 적는다. 내용은 기존 사이트에서, 디자인은 새로 만들게 역할을 나눈다.
5. **결론**: **말로만 설명하지 말고 이미지나 사이트 주소를 보여 주면 퀄리티가 달라진다**. 단, 세 방법의 효과는 모두 발표자가 화면을 보고 내린 인상으로만 비교된다.
