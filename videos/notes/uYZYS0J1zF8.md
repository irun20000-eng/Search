# 클로드 코드 강의 이걸로 끝내세요 | 한 번에 자동으로 돌아가는 원샷 프롬프트 공개

> 한 줄 요약: "프롬프트를 잘 쓰는 단계"를 넘어, 클로드 코드로 **내가 없어도 매일 스스로 일하는 운영 시스템**을 만든다. 메모리·스케줄·태스크·채널·커넥터·퍼미션을 **원샷 프롬프트 하나**로 세팅(그 프롬프트조차 AI가 작성)하고, 결과는 마크다운·구글 시트·텔레그램으로 분리 저장. 예시는 투자 비서지만 구조는 어디든 복제 가능.

## 2. AI 자동화 시스템 구조도 · [1:28](https://youtu.be/uYZYS0J1zF8?t=88)
- **3줄 요약**
  - 흐름은 하나: 클로드 코드가 **매일 핵심 이슈 정리 → 주간 흐름으로 확장 → 숫자는 구글 시트 → 핵심만 텔레그램 → 전체는 아카이브**. 즉 "만들고·쌓고·보내고·남긴다".
  - 이를 가능케 하는 클로드 코드의 4요소: **메모리**(기준·맥락 기억) · **스케줄 태스크**(정해진 시간에 자동 실행) · **채널**(텔레그램 등 외부 전달) · **커넥터**(구글 시트·텔레그램에 직접 연결).
  - **퍼미션 / Allowed Tools**는 시스템이 중간에 안 멈추게 하는 안전장치 — 없으면 자동화가 아니라 '반자동'이 된다.
- **핵심 인용**
- **내 질문**
- 메모리·스케줄·채널·커넥터·퍼미션이 클로드 코드 안에서 "하나의 흐름"으로 묶이는 게 핵심인데, 각 요소가 실제로 어떤 설정 파일/기능에 대응될까? (5장 파일 구조에서 일부 확인)

## 3. [핵심] 원샷 프롬프트의 비밀 · [3:03](https://youtu.be/uYZYS0J1zF8?t=183)
- **3줄 요약**
  - 원샷 프롬프트 안에 든 건 복잡한 기술이 아니라 **3가지**: ① **뭘 만들지**(내일 9시 일일 브리핑, 매주 월 9:10 주간 리포트, 결과를 md·시트·텔레그램으로 분리 저장) ② **어떤 기준으로**(투자 스타일·포트폴리오·워치리스트·브리핑 필수 항목) ③ **결과물 구조까지**(파일 구조·런북·시트 스키마·텔레그램 규칙, 자격증명 없을 때 placeholder 처리).
  - 즉 "리포트 하나 써줘"가 아니라 **앞으로 계속 돌아갈 시스템 자체를 만들어 달라**는 프롬프트.
  - 결정적 반전: **그 긴 프롬프트조차 AI가 만들어 준다** — 내가 자동화하고 싶은 걸 자연어로 구체적으로 말하면, AI가 세팅 프롬프트를 먼저 써준다.

## 5. 자동 생성된 폴더·파일 구조 분석 · [6:54](https://youtu.be/uYZYS0J1zF8?t=414)
- **3줄 요약**
  - **CLAUDE.md** = 프로젝트의 운영 기준서(두뇌) — 브리핑·주간 리포트 작성 방식, 유지할 원칙. **config/secrets.env(예시)** = 구글 시트 ID·텔레그램 봇 토큰·채팅 ID를 넣는 환경 파일.
  - **data/** = 매일 참고할 기준 데이터(investor_profile=투자 성향, portfolio.csv=보유 종목, watchlist.csv=감시 기준). **docs/** = 그대로 따라 하면 구글 시트·텔레그램 연결을 끝내는 **실행 가이드(수동 셋업 안내서)**.
  - **prompts/** = 데일리/위클리 런북·텔레그램 요약 규칙(품질 유지 매뉴얼). **reports/** = 결과 저장소(daily/weekly).
- **핵심 인용**
- **내 질문**
- CLAUDE.md(기준) / data(데이터) / prompts(런북) / docs(연결 가이드)로 나눈 건 컨텍스트 엔지니어링의 "역할별 파일 분리"와 동일 — 우리 파이프라인의 notes/assets/SKILL 분리와도 통한다.

## 6. 일일 투자 브리핑 실행 & 텔레그램 알림 · [9:30](https://youtu.be/uYZYS0J1zF8?t=570)
- **3줄 요약**
  - 예약 작업의 '데일리 인베스트먼트 브리핑'을 수동으로 미리 실행 → 클로드 코드가 저장된 기준·런북으로 본문 생성 → **마크다운 저장 + 구글 시트에 핵심 수치 한 줄 누적 + 텔레그램 핵심 요약 전송**을 한 번에.
  - **3매체 분리**: 텔레그램=빠른 확인(시장요약·지표·포트폴리오 영향·리스크·액션만 압축), 마크다운=상세 원문 보고서, 구글 시트=누적 관리 대시보드.
  - 처음 세팅 땐 퍼미션을 다 안 열어둬서 중간 승인이 뜨는데, 이건 AI가 뭘 하려는지 **안전하게 확인**하는 단계라 오히려 필요.
- **핵심 인용**
- **내 질문**
- '요약(텔레그램)·상세(md)·누적(시트)' 3분리는 이 영상 시리즈 전체의 반복 패턴 — 정보의 '소비 속도'에 맞춰 매체를 나누는 원칙으로 일반화할 수 있겠다.

## 7. '반자동'을 '완전 자동'으로 — 권한(Permissions) 설정 · [12:13](https://youtu.be/uYZYS0J1zF8?t=733)
- **3줄 요약**
  - 예약 작업을 실행해도 중간 승인이 끼면 결국 매번 사람이 개입 = 반자동. 그래서 **"이 스케줄이 매일 승인 없이 자동 실행되도록 Allowed Tools를 설정해 줘"**라고 자연어로 요청.
  - 핵심은 **모든 권한을 여는 게 아니라, 예약 작업에 필요한 범위만** allow로 명시(settings.local.json의 permissions에 allow 형태로).
  - 스케줄만으론 반자동, **Allowed Tools + Permission까지 끝내야** 비로소 사람 없이 굴러가는 완전 자동.
- **핵심 인용**
- **내 질문**
- "필요한 범위만 allow"는 안전과 자동화의 절충 — 우리 하네스 노트의 "호출 전 사용자 승인" 가드레일과 정반대 지점에서, 신뢰 구간을 어디까지 열지가 관건.

## 8. 주간 포트폴리오 리포트 자동 실행 시연 · [13:16](https://youtu.be/uYZYS0J1zF8?t=796)

- **핵심 인용**
- **내 질문**
