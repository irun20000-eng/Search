# 수동 프롬프트는 이제 그만 — 노트북LM으로 프롬프트 자동 선택 업무 자동화

> 한 줄 요약: **구글 시트에 프롬프트 모음집**(제목·내용, 카테고리별)을 만들어 제미나이 노트북(NotebookLM)에 소스로 넣고, **노트북 설정에 규칙**("상황에 맞는 프롬프트 자동 선택, 애매하면 역질문, 사용한 프롬프트 기록")을 심으면 — 텍스트만 붙여넣고 실행해도 AI가 알맞은 프롬프트를 스스로 골라 적용한다. 파일 하나에 수백 개를 넣어도 **RAG(색인→검색→생성)**가 관련성 높은 단 1개만 뽑아 컨텍스트 과부하 없이 정확. 애매하면 역질문. ★필수 주의: 메모리 사용 OFF★(대화 맥락 뒤섞임 방지).

## 1. 문제 — 프롬프트 관리가 또 하나의 업무 · [00:00](https://youtu.be/WxQpKSvZFkw?t=0)
- **3줄 요약**
  - AI로 시간을 아끼려는데 완벽한 프롬프트 만드느라 시간을 다 쓰고, 다음에 못 찾아 또 처음부터 → 'AI 쓰는 일'이 업무가 됨.
  - 회의록·이메일마다 메모장 열고 스크롤·복사·붙여넣기 하는 비효율을 버림.
  - 대안 = AI가 상황을 파악해 **맞는 프롬프트를 스스로 꺼내 쓰는 시스템**.
- **핵심 인용**: "AI를 사용하는 일 자체가 또 하나의 업무가 돼 버린 경험."
- **내 질문**: 프롬프트 자산이 흩어질수록 관리 비용이 커지는데, '중앙 저장 + 자동 선택'이 개인 프롬프트 라이브러리의 정답 아닐까?

## 2. 구축 3단계 — 시트·노트북·설정 · [01:45](https://youtu.be/WxQpKSvZFkw?t=105)
- **3줄 요약**
  - ① **구글 시트** '프롬프트 모음'(A열 제목·B열 내용), 많으면 **카테고리별 분류**(고객응대/문서생성/SNS 등). 한 번에 다 안 써도 되고 **드라이브 동기화**로 최신 반영.
  - ② **제미나이 새 노트북**('프롬프트 자동 최적화') → 소스 추가로 그 시트 연결(소스 1개).
  - ③ **노트북 설정** 규칙: "상황에 맞는 프롬프트 자동 선택, 애매하면 마음대로 말고 질문, 실행 시 맨 윗줄에 사용한 프롬프트 기록."
- **핵심 인용**: "질문이 들어오면 상황에 가장 적절한 프롬프트를 자동 선택하되 … 애매하면 나에게 질문해 줘."
- **내 팁**: '사용한 프롬프트를 기록'하게 하면 자동 선택이 맞는지 검증 가능 — 자동화의 투명성 장치.

## 3. 데모 — 텍스트만 넣으면 자동 적용 + 연속 호출 · [04:30](https://youtu.be/WxQpKSvZFkw?t=270)
- **3줄 요약**
  - 진상 리뷰 텍스트를 붙여넣고 **실행만** → '파손 및 보상 안내 프롬프트' 자동 표시 + 정중한 매뉴얼 답변 1초 완성('사과문 써 줘' 없이).
  - 행정직: 포트홀 민원 → '공공기관 정중한 답변' 프롬프트로 하십시오체 초안.
  - **연속 호출**: "보도자료도 작성" → 방금 내용으로 보도자료 양식 변환, "상급자 보고 요약" → 1페이지 보고서. 복붙 없이 짧은 대화만으로 연속 진행.
- **핵심 인용**: "제가 사과문 써 줘, 파손 프롬프트 가동해 줘 같은 말을 단 한 마디도 안 했는데 말이죠."
- **내 질문**: 대화 맥락을 이어가며 다음 프롬프트를 자동 적용하는 건, 프롬프트 체이닝을 사용자가 의식하지 않게 만든 것 — 자동화의 이상적 UX 아닐까?

## 4. ★왜 정확한가 — RAG 3단계★ · [07:19](https://youtu.be/WxQpKSvZFkw?t=439)
- **3줄 요약**
  - 일반 챗봇은 수백 개 지시를 한 번에 넣으면 **컨텍스트 윈도우 과부하**로 정확도↓. 제미나이 노트북은 **RAG**로 해결.
  - RAG 3단계: ① **색인(인덱싱)** — 시트 프롬프트를 줄 단위로 쪼개 '데이터 도서관'화 ② **검색(리트리벌)** — 질문과 연관성 높은 **단 1개** 프롬프트만 뽑음(전체를 통째로 안 읽음) ③ **생성** — 그 1개만 AI에 배달.
  - 파일에 수백 개가 있어도 실질적으로 **완벽한 1개만** 밀어주므로 혼란 없이 정확.
- **핵심 인용**: "레그 시스템이 … 실질적으로는 단 한 개의 완벽한 프롬프트만 AI에게 밀어 주기 때문에."
- **내 팁**: '파일 하나에 다 넣어도 되는' 이유가 RAG — 앞 영상(Aiden)의 NotebookLM '소스 기반 답변'과 같은 원리로 프롬프트를 관리한 응용.

## 5. 애매하면 역질문 + ★메모리 OFF 필수★ · [10:08](https://youtu.be/WxQpKSvZFkw?t=608)
- **3줄 요약**
  - 애매한 입력("헤드폰 런칭 기념")엔 맘대로 생성 않고 **"다음 중 하나를 선택해 주세요"라고 역질문** → 선택하면 그 형식으로 생성(대형 사고 방지).
  - **치명적 주의: 노트북 설정에서 '메모리 사용'을 반드시 OFF** — 메모리는 이전 대화 맥락을 기억해, 켜두면 A사 회의 내용이 다음 B사 회의와 뒤섞이는 오류.
  - 매번 새 도화지 상태에서 프롬프트만 깨끗이 뽑아 개별 적용하도록 메모리 OFF.
- **핵심 인용**: "지금처럼 프롬프트 자동 선택으로 쓸 때는 이 기억력이 오히려 독이 됩니다."
- **내 질문**: '메모리'가 어떤 작업엔 필수고 어떤 작업엔 독이라는 건, 자동화 설계에서 상태(state)를 언제 유지·초기화할지가 핵심 결정이라는 뜻 아닐까?

## TL;DR (5줄)

1. **목표**: 프롬프트를 매번 찾아 복붙하는 대신, AI가 상황에 맞는 프롬프트를 스스로 골라 쓰게.
2. **구축**: 구글 시트 '프롬프트 모음'(제목·내용, 카테고리) → 제미나이 노트북 소스 연결 → 노트북 설정에 자동선택·역질문·기록 규칙.
3. **사용**: 텍스트만 붙여넣고 실행 → 알맞은 프롬프트 자동 적용, 이어서 대화하면 연속 호출(보도자료·요약).
4. **정확도(★)**: RAG(색인→검색→생성)가 수백 개 중 **관련성 높은 1개만** 뽑아 컨텍스트 과부하 없이 정확.
5. **주의(★)**: 애매하면 역질문, **메모리 사용은 반드시 OFF**(대화 맥락 뒤섞임 방지). 드라이브 동기화로 시트 최신 반영.
