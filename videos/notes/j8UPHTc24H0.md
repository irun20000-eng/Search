# [헤르메스 강의 1] 일 잘하는 헤르메스 만드는 법 (폴더 설정, 성격 설정)

> 한 줄 요약: 헤르메스 에이전트가 실무에서 못 하는 이유는 **메모리 시스템(SOUL.md·AGENTS.md·USER.md)을 안 잡아서**다. 설정 없이 "강남 삼겹살 맛집 10개 찾아줘"를 시키면 LLM 특성상 **구글→다이닝코드에서 영어 파일명으로 대충 저장**한다. 해법은 ① 기존 결과를 **아카이브로 격리**, ② **AGENTS.md**에 파일명/폴더 규칙·검색 규칙(네이버·리뷰 감정분석·예약 컬럼)을 **한글 강제·볼드 강조**로 정의, ③ 프롬프트로 **성격(꼼꼼한 맛집 조사관)**을 설정해 USER.md에 저장. 핵심 원리는 **LLM 어텐션** — SOUL.md/AGENTS.md는 프롬프트 **맨 앞에 항상 실려 강조**되므로(Lost in the Middle의 반대) 앞단 프롬프트를 엔지니어링해야 한다.

## 1. 오늘 할 것 & '골(goal)' 개념 · [0:00](https://youtu.be/j8UPHTc24H0?t=0)
- **3줄 요약**
  - 오늘 실습: **네이버에서 강남구·역삼구 삼겹살 맛집** 수집을 헤르메스에게 시킨다(브라우저 커넥트로 연결).
  - 헤르메스의 **골(goal)** 키워드 = **목표에 도달할 때까지 작업을 반복**(맛집 10개면 10개 찾을 때까지).
  - 첫 지시: "연결된 브라우저로 강남·역삼 삼겹살 맛집 각 10개를 수집해 파일에 저장해줘".
- **핵심 인용**
- **내 질문**
- '골=목표까지 반복'은 영상8의 `/goal`, 우리 ralph 루프와 같은 개념 — "완료 조건까지 자동 반복"이 에이전트의 공통 패턴이다.

## 2. 설정 없이 첫 시도 — 왜 대충 하는가 · [1:36](https://youtu.be/j8UPHTc24H0?t=96)
- **3줄 요약**
  - 설정이 없으면 헤르메스는 **구글에 검색 → 다이닝코드**에 들어가 파이썬 스크립트로 정보를 긁어 10개를 채운다.
  - 이유: **LLM은 평균적(평준화된) 행동**을 한다 — 외국인 기준 검색은 보통 구글, 상위 노출은 다이닝코드.
  - 결과 CSV는 정리는 됐지만 **영어 파일명(알아보기 힘듦) + 다이닝코드 단일 소스(일반적이지 않음)** — "직원이 이렇게 보고하면 못 받아들인다".
- **핵심 인용**
- **내 질문**
- "LLM은 평균으로 수렴"은 영상4(AI 디자인이 다 비슷)와 같은 통찰 — 그걸 벗어나려면 **명시적 규칙으로 방향을 강제**해야 한다.

## 3. 메모리 시스템의 중요성 — 아카이브 격리 · [4:38](https://youtu.be/j8UPHTc24H0?t=278)
- **3줄 요약**
  - 헤르메스가 골을 "달성"했다지만, 발표자는 에이전트를 끄고 그 결과물을 **아카이브 폴더로 격리**한다(아카이브 = 에이전트가 **보지 않는 파일**).
  - 그리고 프로젝트에 **AGENTS.md**를 넣는다 — SOUL.md뿐 아니라 **AGENTS.md도 매우 중요**.
  - 발표자는 "한국에서 헤르메스를 가장 많이 쓴 사람 손가락 안"이라며, **메모리 관리가 핵심**임을 강조.
- **핵심 인용**
- **내 질문**
- "안 보게 할 파일은 아카이브로 격리"는 컨텍스트 위생 — 우리도 처리 완료분을 processed로 옮겨 큐를 깨끗이 유지하는 것과 같다.

## 4. LLM 어텐션 원리 — 앞단이 강조된다 · [6:11](https://youtu.be/j8UPHTc24H0?t=371)
- **3줄 요약**
  - 헤르메스가 GPT(발표자는 **GPT-5.5**)에 보내는 메시지는 한 줄이 아니라, **맨 앞에 SOUL.md + AGENTS.md가 항상 함께** 실린다(무조건 한 번은 감).
  - **LLM의 'Lost in the Middle'** — 가운데 내용은 잘 잊지만 **첫/마지막은 강조**된다. 그래서 SOUL.md는 제일 앞(강조), AGENTS.md도 상대적으로 앞.
  - 대화가 쌓여 압축(컨텍스트 압축)이 일어나도 이 둘은 앞단에 남아 **어텐션(attention)**을 받으므로, **앞단 프롬프트를 엔지니어링**해야 한다(단, 너무 길면 안 됨).
- **핵심 인용**
- **내 질문**
- "Lost in the Middle → 앞/뒤 강조"는 프롬프트 배치의 핵심 원리 — 중요한 규칙일수록 맨 앞(또는 맨 끝)에 두라는 실전 지침이다.

## 5. AGENTS.md (1) — 파일명·폴더 규칙, 강조 표기 · [8:21](https://youtu.be/j8UPHTc24H0?t=501)
- **3줄 요약**
  - **파일명 규칙**: 조사 결과는 `음식명.csv`(예: `삼겹살.csv`). **폴더 규칙**: 각 지역구별 **한글 폴더**(강남/역삼) 생성 후 하위에 `음식명.csv` 저장.
  - Markdown 헤더(`#`, `##`)로 섹션 구조화, **공통 규칙**에 "**반드시 한글로 작성, 영어 사용 금지**"를 **볼드(`**`)로 강조**.
  - 강조를 하는 이유: **LLM이 이런 마크다운 포맷을 많이 학습**해 볼드를 '강조'로 인식하기 때문 — 중요한 규칙엔 강조 표기를 넣는다.
- **핵심 인용**
- **내 질문**
- "볼드 = LLM이 아는 강조"는 우리 노트/규칙 작성에도 적용 — LESSONS의 **prevention-rule**을 볼드로 강조하면 재로드 시 더 잘 지켜질까?

## 6. AGENTS.md (2) — 검색 규칙 & 아카이브 미열람 · [10:57](https://youtu.be/j8UPHTc24H0?t=657)
- **3줄 요약**
  - **검색 규칙**: ① 반드시 **www.naver.com**에서 시작 ② **네이버 지도** 활용 ③ **평점·리뷰의 사용자 감정을 분석**해 정말 맛있는 집인지 특징 기입.
  - **예약 가능 여부**를 CSV의 한 **컬럼(열)**으로 — '열'이 오해될 수 있어 "컬럼"으로 명확히 표기.
  - 중요 규칙: **"아카이브 폴더는 절대 열어보지 않습니다"** — 격리한 옛 결과가 프롬프트에 섞여 혼동 주는 걸 방지.
- **핵심 인용**
- **내 질문**
- "열 대신 컬럼으로 명확히"는 영상8의 '개발 어휘'와 통한다 — 모호어를 없애는 게 정확한 지시의 핵심이다.

## 7. 성격(톤) 설정 — USER.md에 저장 · [13:29](https://youtu.be/j8UPHTc24H0?t=809)
- **3줄 요약**
  - 헤르메스를 **`-r` 옵션**(승인 권한을 안 물음=자동 승인, 선호에 따라 선택)으로 실행 후 **성격을 설정**.
  - 프롬프트: "당신은 **맛집 조사관**으로서 꼼꼼히 조사하는 성격 — 리뷰까지 자연어 분석해 정말 맛집인지 정리하고 **HTML/CSV로 깔끔하게 전달**하는 성격". → 헤르메스가 **메모리 도구**로 이를 저장.
  - 저장 위치: 내 선호는 **USER.md**(에이전트가 적어둔 사용자 선호), 성격도 설정 요청 — **USER.md도 프롬프트에 실린다**(에이전트가 저장한 건 결국 우리 프롬프트에 들어감).
- **핵심 인용**
- **내 질문**
- SOUL/AGENTS/USER.md가 모두 '프롬프트에 실리는 지속 메모리'라는 구조 — 우리 CLAUDE.md·memory·LESSONS와 정확히 같은 계층이다.

## 8. 재실행 결과 — 확 달라진 헤르메스 · [16:11](https://youtu.be/j8UPHTc24H0?t=971)
- **3줄 요약**
  - (복잡한 작업 시 헤르메스는 **스킬을 자동 생성/삭제**한다.) 재실행하니 헤르메스가 **플랜을 세우고 네이버(지도)부터 시작**(이전엔 구글).
  - 결과: **한글 폴더(강남/역삼) → `삼겹살.csv`** 구조로 저장. **AGENTS.md를 명시적으로 안 넣었는데도 읽었고**, SOUL.md의 '꼼꼼함'대로 여러 소스를 교차 검색.
  - **리뷰 감정 분석**("단체석·회식 언급 많고 반찬 알참, 고기 만족도 높음 → 추천")과 **예약 가능 여부 컬럼**(가능/확인 필요)까지 지시대로 반영.
- **핵심 인용**
- **내 질문**
- 규칙 문서를 한번 심으면 매 프롬프트에 자동 반영된다 — 반복 지시를 없애는 이 구조가 곧 "일 잘하는 에이전트"의 핵심이다.

## 9. AGENTS.md는 직접 작성 권장 + 마무리 · [20:49](https://youtu.be/j8UPHTc24H0?t=1249)
- **3줄 요약**
  - **AGENTS.md는 여러분이 직접 적으라** — 에이전트에게 이걸 쓰게 시키면(논문상으로도) 평균적으로 좋은 결과를 못 얻는다. 노션 적듯이 **프로젝트 규칙을 사람이 정의**.
  - 그 폴더에서 실행되는 헤르메스는 **반드시 이 파일을 읽고** 그 위에 작업을 쌓는다.
  - 정리: **SOUL.md 설정 + 디렉토리(폴더) 운영 + AGENTS.md 정의** 세 가지가 헤르메스를 실무형으로 만든다.
- **핵심 인용**
- **내 질문**
- "규칙은 에이전트가 아니라 사람이 쓰라"는 조언이 인상적 — 자동화하되 **방향(규칙)은 사람이 쥔다**는 우리 default 품질 루프와 같다.

## TL;DR (5줄)

1. 헤르메스가 실무에서 못 하는 이유는 **메모리 시스템(SOUL.md·AGENTS.md·USER.md) 미설정** — 설정 없으면 구글→다이닝코드에서 영어 파일명으로 대충 저장한다.
2. **골(goal)** = 목표 도달까지 반복. LLM은 평균 행동을 하므로 **명시 규칙으로 방향을 강제**해야 한다.
3. 원리는 **LLM 어텐션**: SOUL.md/AGENTS.md는 프롬프트 **맨 앞에 항상 실려 강조**(Lost in the Middle의 반대) → 앞단 프롬프트를 엔지니어링.
4. **AGENTS.md**에 파일명/폴더 규칙 + 검색 규칙(네이버·리뷰 감정분석·예약 컬럼)을 **한글 강제·볼드 강조**로 정의, 옛 결과는 **아카이브로 격리**.
5. 프롬프트로 **성격(꼼꼼한 조사관)**을 USER.md에 저장 → 재실행 시 네이버 시작·한글 폴더·리뷰 분석으로 확 달라짐. **규칙은 에이전트가 아니라 사람이 직접** 작성 권장.
