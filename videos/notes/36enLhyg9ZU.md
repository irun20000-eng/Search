# 이제 클로드 코드가 SNS도 관리해줍니다 (클로드 코드 X 쓰레드 자동 발행)

> 한 줄 요약: **안티그래비티 + 클로드 코드**로 쓰레드 자동 발행 플로우를 만든다. 핵심 태도는 **"바이패스로 알아서 해" 대신 Plan 모드로 계획부터"**(대충 던지면 결과가 똥). 토큰은 앞 영상(방구석컴퍼니 스레드)과 같은 경로 — 메타 개발자 센터에서 **앱 생성(Threads API Access) → 역할에 'Threads Tester' 추가 → 폰 쓰레드 앱에서 초대 수락(대기중→연결됨) → 그래프 API 탐색기에서 액세스 토큰 발급**. 그 토큰과 **앱 시크릿**을 클로드 코드에 주면 **장기 토큰 변환·글 발행·리플라이 체인(메인글+댓글 이어달기)까지 알아서 구현**(Node.js, .env 저장은 보안 주의). **슬래시 `/loop`로 N분·하루 간격 자동 발행**까지.

## 1. 계획부터 — Plan 모드 (바이패스 금물) · [00:00](https://youtu.be/36enLhyg9ZU?t=0)
- **3줄 요약**
  - 지난 편(리서치 에이전트로 쓰레드 기획)에서 더 나아가 **자동 발행**까지. 도구는 **안티그래비티**에 확장으로 클로드 코드.
  - 뉴 세션 → **Plan 모드로 전환** → "쓰레드 자동 발행 플로우 계획부터 세워 줘".
  - 예전엔 바이패스로 "알아서 해"만 던졌더니 **결과가 똥** → 이제 **계획부터 세우고 진행**.
- **핵심 인용**: "그냥 바이패스 모드로 … 보냈더니 똥이 되더라고요 … 계획부터 세우고 진행."
- **내 팁**: '계획 먼저(선명확화)'는 앞 영상(스펙주도개발, 잭피디 '질문해 줘')과 정확히 같은 결론 — 대충 던지면 품질이 무너진다.

## 2. 계획 확답 + 스택 선택 · [01:50](https://youtu.be/36enLhyg9ZU?t=110)
- **3줄 요약**
  - 클로드가 되묻는 항목에 답: **쓰레드 API 이용**(관련 정보 직접 제공), 콘텐츠는 테스트 텍스트, **앱·액세스 토큰은 아직 없음**, 실행은 **수동**(자동은 `/loop`로도 가능하나 이번엔 발행 원리 시연), 언어 **Node.js**.
  - 계획을 세우는 동안 병렬로 **토큰 발급 작업**을 진행.
- **핵심 인용**: "이 영상의 목적은 쓰레드 발행이 클로드 코드를 통해서 어떻게 할 수 있는지."
- **내 질문**: 계획 세우는 동안 사람이 병렬로 토큰 발급 — 사람·AI 작업을 겹쳐 시간을 아끼는 방식 아닐까?

## 3. ★토큰 발급 — 앱·Threads Tester·초대 수락★ · [03:03](https://youtu.be/36enLhyg9ZU?t=183)
- **3줄 요약**
  - 메타 개발자 센터 → 내 앱 → 앱 만들기(**Threads API Access**, 비즈니스 미연결). 앱 역할→**사람 추가로 'Threads Tester'**에 내 쓰레드 아이디 연결(상태 '대기 중').
  - 폰 **쓰레드 앱**: 설정→계정→**웹사이트 권한→초대 수락** → 대시보드 새로고침하면 **대기중→연결됨**.
  - 도구→**그래프 API 탐색기**에서 앱을 페이스북이 아닌 **Threads로 바꾸고** "액세스 토큰 생성" → 토큰 복사.
- **핵심 인용**: "위에 있는 저 테스터 말고 저 아래 스레드 테스터 … 수락은 폰 스레드 앱에서."
- **내 팁**: 이 절차는 앞 영상(방구석컴퍼니 스레드)과 완전히 동일 — Threads Tester(아래 섹션)와 폰 앱 수락이 공통 함정. 도구가 클로드 코드/그래프 탐색기로만 다름.

## 4. ★클로드가 장기 토큰·발행·리플라이 체인 구현★ · [06:42](https://youtu.be/36enLhyg9ZU?t=402)
- **3줄 요약**
  - 클로드 코드에 토큰 주고 "장기 토큰으로 변환 후 사용" → 클로드가 **앱 시크릿 요청**(메타 앱→기본 설정→앱 시크릿 코드 복사·제공) → **단기→장기 토큰 교환·사용자 ID 조회**를 알아서 처리, **.env에 저장**(노출 금지, 배포 시 보안 조치).
  - **테스트 발행 성공** → 쓰레드에 "첫 자동 발행 테스트" 게시. 예전 n8n으로 고생했던 걸 클로드 코드로 쉽게 연결.
  - 심화: 캡처 예시를 주고 **"메인 게시물 아래에 댓글을 이어 달기(리플라이 체인)"** 구현 → 타이밍 딜레이·에러 자가 디버깅 후 "메인글+댓글" 자동 발행 성공.
- **핵심 인용**: "제가 맨 초반에 힘들게 만들었던 장기 토큰 변환까지 이렇게 알아서 잘 해 주게 됩니다."
- **내 질문**: 앞 영상은 완성 프로그램을 배포받는 방식, 이 영상은 **클로드 코드가 그 자리에서 코드를 생성**하는 방식 — 같은 목표를 '받기 vs 만들기'로 대비되는 것 아닐까?

## 5. 슬래시 /loop 자동 발행 + 보안 유의 · [10:03](https://youtu.be/36enLhyg9ZU?t=603)
- **3줄 요약**
  - 더 자동화하려면 **슬래시 `/loop`** 걸어 "N분 간격/하루마다 이런 내용 발행해 줘" → 손쉽게 반복 발행.
  - 리플라이 체인으로 메인글+댓글 자동 발행(에러도 클로드가 스스로 디버깅). 콘텐츠 제작 시간 절약이 목적.
  - **보안 주의**: 토큰·앱 시크릿이 담긴 **.env는 노출 금지**, 배포 시 보안 조치 선행.
- **핵심 인용**: "슬래시하고 루프 걸면 … 한 시간마다 하루마다 루프를 걸어서 발행."
- **내 팁**: `/loop` 반복 발행은 앞 영상(코워크 스케줄 예약, 유튜브 요약 루틴)과 같은 '스케줄 자동화' 계열. .env 보안 강조는 자격증명 취급 원칙과 일치.

## TL;DR (5줄)

1. **도구·태도**: **안티그래비티+클로드 코드**로 쓰레드 자동 발행. **Plan 모드로 계획부터**(바이패스로 던지면 결과가 똥).
2. **토큰(★)**: 메타 개발자 센터 앱 생성(Threads API Access) → 역할에 **Threads Tester**(아래 섹션) → 폰 쓰레드 앱 **초대 수락** → 그래프 API 탐색기서 토큰 발급.
3. **구현(★)**: 토큰+**앱 시크릿**을 클로드 코드에 제공 → **장기 토큰 변환·사용자 ID 조회·글 발행**을 알아서(Node.js, .env 저장).
4. **심화**: 캡처 예시로 **리플라이 체인**(메인글+댓글 이어달기) 구현 — 타이밍 딜레이·에러 자가 디버깅.
5. **자동화·보안**: **슬래시 `/loop`**로 N분·하루 간격 자동 발행. **.env 노출 금지**, 배포 시 보안 선행.
