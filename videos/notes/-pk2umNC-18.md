# orca로 멀티 에이전트 graph 만드는 방법은? (그래프 엔지니어링 오케스트레이션)

> 한 줄 요약: **그래프 엔지니어링 = 하나의 루프로 충분하지 않을 때** 여러 특화 에이전트(노드)를 관계(엣지)로 연결한 것 — **루프 엔지니어링을 포함**하는 상위 개념. 예전 랭그래프의 노드가 이제 **클로드 코드·코덱스**로 대체됐고, 각 노드는 루프일 수도 아닐 수도 있다. **오르카(Orca) IDE의 오케스트레이션**으로 구현: **오케스트레이터(메인 세션)**가 여러 **워커 터미널**에 작업을 디스패치. 실습 — 클로드 코드(오케스트레이터)가 **코덱스 5개 터미널에 허깅페이스 블로그 5글 병렬 요약(T1~5)→6번이 종합해 트위터용 글 작성(T6)→7번이 검토(T7)**, 반려 시 T6 재실행. 사람 검토(T7)를 AI 자동 판단으로 바꾸는 것도 프롬프트로 가능. 설치는 온보딩 체크리스트의 **Enable Orca CLI + 스킬**.

## 1. 그래프 엔지니어링이란 (용어 배경) · [00:00](https://youtu.be/-pk2umNC-18?t=0)
- **3줄 요약**
  - 그래프 엔지니어링은 새 용어가 아니라 원래 있던 용어(그래프 RAG·랭그래프 아키텍처 등)인데, **오픈클로드 제작자 피터 스타인버거가 X에 "루프냐 그래프냐"** 글(7/18경)로 재점화.
  - 지금의 그래프 엔지니어링 = **에이전트가 동작하는 방식**에 대한 것.
  - 오르카로 이 흐름을 만들어 실행하는 기능을 시연.
- **핵심 인용**: "지금 나오고 있는 그래프 엔지니어링이라고 하는 거는 에이전트가 동작하는 방식에 대한 내용."
- **내 팁**: 이 프로젝트 갤러리엔 이미 ZeroCho의 '그래프 엔지니어링 5분 설명'이 있음 — 이 영상은 그 개념을 **오르카로 실제 구현**하는 실습편.

## 2. ★루프 vs 그래프 — 포함 관계★ · [01:07](https://youtu.be/-pk2umNC-18?t=67)
- **3줄 요약**
  - **그래프 엔지니어링 = 하나의 루프로 충분하지 않을 때** 수행하는 작업. 여러 특화 에이전트를 **노드**로, 그 관계를 **그래프(엣지)**로 연결 → 부모 노드 끝나면 자식 노드 실행.
  - **루프 엔지니어링**(하위): 트리거(스케줄·메일·PR)→계획→실행→검토(종료 조건, 최대 횟수 제한)→반복. 클로드 코드 `/loop`·goal, 코덱스 goal, 크론잡.
  - **그래프는 루프를 포함** — 랭그래프처럼 **스테이트(딕셔너리) 기반 분기·회귀**. 노드 하나가 클로드 코드/코덱스가 될 수 있고, 루프 노드일 수도 정리만 하는 노드일 수도.
- **핵심 인용**: "그래프 엔지니어링은 하나의 루프로 충분하지 않을 때 수행할 수 있는 작업."
- **내 질문**: '노드=에이전트, 엣지=관계, 그래프⊃루프'는 앞 영상(ZeroCho 그래프 엔지니어링)과 정확히 같은 정의 — 두 영상이 개념·구현으로 상보적 아닐까?

## 3. 구현 도구 + 오르카 오케스트레이션 개념 · [04:22](https://youtu.be/-pk2umNC-18?t=262)
- **3줄 요약**
  - 구현은 기존 프레임워크로도 가능: **n8n·랭그래프·오토젠(그래프플로우)·구글 ADK·클로드 코드 워크플로우즈** — 다 원래 있던 도구.
  - 더 간단한 대안이 **오르카(Orca) IDE**(여러 에이전트를 동시 관리하는 IDE). 설치: 온보딩 체크리스트→**Enable Orca CLI**→에이전트 오케스트레이션 선택→**CLI+스킬 설치**(다른 에이전트 있으면 추가, 심볼릭 링크).
  - 구조: **오케스트레이터**(명령을 처음 내리는 메인 세션) + 여러 **워커**(클로드 코드·코덱스·키미 등). 오케스트레이터가 워커에 작업 디스패치.
- **핵심 인용**: "오케스트레이터가 있습니다. 명령을 처음 내리게 되는 그 메인 세션이 오케스트레이터."
- **내 팁**: 오르카는 이 프로젝트 갤러리의 앞 영상(로치 ADE 오르카 소개)의 그 도구 — 이번은 오케스트레이션 기능 심화.

## 4. ★실습 — 블로그 5글 병렬 요약→트윗 작성→검토 그래프★ · [07:06](https://youtu.be/-pk2umNC-18?t=426)
- **3줄 요약**
  - 목표 그래프: 허깅페이스 블로그 **최신 5글을 코덱스 5개 터미널이 병렬 요약(T1~5)** → **6번 노드가 종합해 관심 주제 1개 선택·트위터 글 작성(T6)** → **7번 노드가 검토(T7)**, 반려 시 T6 재실행.
  - 클로드 코드를 **오케스트레이터**로, `/orchestration` 스킬 지정 후 자연어 지시(식별자 T6·T7 지정, T1~5는 AI가 알아서 번호 매김). `orca skills get orchestration`으로 CLI 명령 주입.
  - 오케스트레이터가 **터미널 5개 생성→디스패치**, 완료 대기(업데이트 창은 2번 눌러 스킵). T6가 바톤 받아 종합, T7 새 터미널이 사람 검토 요청.
- **핵심 인용**: "지시를 한 이후로 아무것도 건들지 않았는데 알아서 이렇게 루프도 타고 검토도 하고 다시 되돌아가는."
- **내 질문**: 오케스트레이터→워커 디스패치 병렬 팬아웃은 앞 영상(롱폼 영상 서브에이전트, 코워크 디스패치)과 같은 오케스트레이션 — 오르카는 이를 IDE 터미널로 시각화한 것 아닐까?

## 5. 검토·분기(회귀) + 사람↔AI 검토 선택 · [13:37](https://youtu.be/-pk2umNC-18?t=817)
- **3줄 요약**
  - T7 검토에서 사람이 "더 자세히·비전문가도 이해하게" 피드백 반려 → 오케스트레이터가 **T6 재실행**(피드백 전달) → 수정본을 T7이 재검토 → 승인 시 종료. **터미널 간 데이터가 오케스트레이터를 통해 왕복**.
  - 이게 곧 **그래프**(T1~5 요약 → T6 종합 → T7 검토, 반려 시 T6로 회귀하는 분기). 화려한 그래프 UI는 없어도 흐름 자체가 그래프.
  - **검토(T7)는 사람 or AI 선택 가능**: 프롬프트에 "네가 기준에 따라 판단해"라고 주면 코덱스/클로드가 자동 판단. 노드 하나를 루프로 만들려면 "조건 만족까지 반복"으로 지시.
- **핵심 인용**: "이 7번 단계는 다른 에이전트가 직접 자동으로 하도록 구성하는 것도 가능하다."
- **내 팁**: '검토 노드를 사람↔AI로 전환'은 이 프로젝트의 품질 루프(사람 검수 vs verifier 에이전트)와 같은 선택지 — 신뢰도에 따라 human-in-the-loop 조절.

## TL;DR (5줄)

1. **정의(★)**: **그래프 엔지니어링 = 하나의 루프로 부족할 때** 여러 에이전트(노드)를 엣지로 연결. **루프를 포함**하는 상위 개념(랭그래프 노드가 이제 클로드 코드·코덱스).
2. **도구**: 기존 n8n·랭그래프·오토젠·ADK·클로드 워크플로우즈로도 되지만, **오르카 IDE 오케스트레이션**이 간단(Enable Orca CLI+스킬 설치).
3. **구조**: **오케스트레이터**(메인 세션)가 여러 **워커 터미널**(코덱스·클로드 등)에 작업 디스패치.
4. **실습(★)**: 블로그 **5글 병렬 요약(T1~5)→종합·트윗 작성(T6)→검토(T7)**, 반려 시 T6 회귀. 자연어 지시로 T1~5는 자동 추론.
5. **검토**: T7은 **사람 or AI** 선택(프롬프트로), 노드를 루프로도 구성 가능. 흐름 자체가 곧 그래프(분기·회귀 포함).
