# 클로드 디자인 2.0, 완전히 달라졌습니다 (4단계 총정리)

> 한 줄 요약: 클로드 디자인 2.0은 **① 크레딧 효율 개선(켜자마자 녹지 않음) ② 캔버스 직접 편집(피그마처럼 클릭 수정) ③ 디자인 시스템 등록 ④ 클로드 코드와 양방향**으로 완전히 달라졌다. 좋은 디자인을 뽑는 **4단계**: **1단계 그냥 시킨다**(흔함) → **2단계 레퍼런스를 보여준다**(가들리·드리블·Awwwards 캡처, 피그마 키트 첨부) → **3단계 추출한다**(Firecrawl로 내 사이트/잘 만든 사이트의 색·폰트·**규칙**을 긁어와 디자인 시스템 등록) → **4단계 전문가 감각을 스킬로 설치**(taste 스킬 + 인터랙션 디테일 스킬). 산출물은 **실제 코드**라 공유 버튼으로 클로드 코드로 넘겨 제품화.

## 1. 무엇이 달라졌나 — 2.0의 4대 변화 · [00:00](https://youtu.be/c-ny7pegVHI?t=0)
- **3줄 요약**
  - 클로드 디자인 = 클로드로 웹사이트·프로토타입·슬라이드·애니메이션을 만드는 도구(디자인·코딩 몰라도 됨). 1.0은 **켜기만 해도 크레딧이 녹아** 대부분 며칠 쓰다 접음.
  - 2.0의 4대 변화: **①크레딧 효율↑ ②캔버스 직접 편집(피그마처럼) ③디자인 시스템 등록 ④클로드 코드와 양방향**.
  - 특히 캔버스 직접 편집이 핵심 — 오타 하나 고치는 데 클로드를 부르지 않아도 됨.
- **핵심 인용**: "캔버스에서 직접 편집이 됩니다. 더 이상 오타 하나 고치는데 클로드를 부르지 않고 피그마처럼 클릭해서."
- **내 팁**: '켜자마자 크레딧이 녹는다'는 1.0의 진입장벽 → 2.0 효율 개선은 앞 영상(힉스필드 '생성만 크레딧')의 비용 관리와 같은 결.

## 2. 1·2단계 — 그냥 시키기 → 레퍼런스 보여주기 · [01:34](https://youtu.be/c-ny7pegVHI?t=94)
- **3줄 요약**
  - **1단계(그냥 시킨다)**: 템플릿+간단 프롬프트 → 나쁘진 않지만 흔하고 특색 없음("예쁘게 해 주세요" 한 마디 던진 것과 같음).
  - **2단계(보여준다)**: "미니멀·따뜻한 느낌"은 말로는 간극이 큼 → **시각 자료를 던져** 간극 제거. 소스: **가들리(Godly)·드리블·Awwwards** 캡처, **피그마 커뮤니티 '디자인 키트'**(무료, 클로드 디자인이 피그마 파일 첨부 지원).
  - 레퍼런스를 첨부하니 색감·레이아웃이 그에 맞게 변경. 폰트·텍스트·색상은 **편집 메뉴로 직접**, 큰 수정만 코멘트로 영역 찍어 클로드에 요청.
- **핵심 인용**: "말로 설명하지 말고 보여줘라 … 시각적으로 던질 수 있다면 그 간극이 사라지겠죠."
- **내 팁**: '말 대신 레퍼런스'는 앞 영상(잭피디의 드리블/Awwwards 캡처)과 완전히 동일 — 디자인 의도 전달의 공통 해법.

## 3. ★3단계 — Firecrawl로 브랜드·규칙 추출★ · [04:34](https://youtu.be/c-ny7pegVHI?t=274)
- **3줄 요약**
  - **Firecrawl**(웹사이트를 AI가 읽기 좋게 정리해 가져오는 도구, 무료 플랜 있음)을 **커스텀 커넥터**로 연결(설정→커넥터 추가, MCP 서버 주소 V2 앞에 API 키 삽입).
  - **내 사이트** 주소만 주면 색·폰트·톤을 그대로 가져와 **브랜드 가이드 문서 없이** 내 브랜드에 맞는 페이지 생성.
  - **잘 만든 남의 사이트**도 추출 가능 — 클로드가 그 사이트의 **코드를 읽어** '왜 예쁜지(규칙)'를 가져옴. 포인트는 **생김새가 아니라 좋아 보이게 만드는 규칙**. 추출한 브랜드/규칙은 **디자인 시스템으로 등록**해 재사용.
- **핵심 인용**: "우리가 가져오는 건 그 사이트의 생김새가 아니라 그 사이트를 좋아 보이게 만드는 규칙이거든요."
- **내 질문**: Firecrawl로 '규칙 추출'은 앞 영상(잭피디의 21st.dev 컴포넌트, 힉스필드 브랜드 가이드 시트)의 '재료 자산화'와 같은 발상 — 추출→디자인 시스템 등록으로 자산화.

## 4. ★4단계 — 전문가 감각을 스킬로 설치★ · [07:24](https://youtu.be/c-ny7pegVHI?t=444)
- **3줄 요약**
  - 1~3단계는 재료를 '가져다줌', 4단계는 **전문가 감각을 아예 설치** — 이걸 가능케 하는 게 **스킬**(전문가 노하우를 미리 써 둔 작업 지침서).
  - **① taste 스킬**(깃허브 스타 6만+, AI의 뻔한 디자인 방지): 레이아웃 실험성·애니메이션 정도를 **다이얼 3개**로 조절 → 개성 있는 구성.
  - **② 인터랙션 디테일 스킬**(Vercel·Linear 출신, 매일 보는 UI 컴포넌트 제작자가 배포): "요소는 무에서 튀어나오면 안 된다", "애니메이션 0.3초 넘기면 답답" 같은 미세 판단이 코드로 정리 → 버튼 hover/press 반응·스크롤 등장 등 몸으로 느껴지는 디테일.
- **핵심 인용**: "클로드한테 전문가의 감각을 아예 설치해 버리는 거예요. 이걸 가능하게 만드는 게 바로 스킬입니다."
- **내 팁**: '스킬로 전문가 감각 설치'는 앞 영상들(잭피디 frontend-design/UIUX 프로맥스, 힉스필드 스킬 5개)과 정확히 같은 패턴 — 역량을 스킬로 주입.

## 5. 4단계 요약 + 포지셔닝(코드 → 제품화) · [09:40](https://youtu.be/c-ny7pegVHI?t=580)
- **3줄 요약**
  - 4단계 순서: **①그냥 시킨다 → ②레퍼런스 보여준다 → ③브랜드·규칙 추출 → ④전문가 감각 스킬 설치**. 단계마다 더 좋은 재료를 줄수록 결과↑.
  - 포지셔닝: 클로드 디자인은 **디자이너 대체가 아님**(전문가는 자기 워크플로우가 편함) — **디자이너와 개발자 사이의 간격**을 메우는 제품(클로드 코워크와 같은 맥락).
  - 산출물은 **전부 실제 코드** → 회원가입·결제·DB를 붙여 제품화하고 싶으면 **공유 버튼 하나로 클로드 코드로 내보내기**. "디자인은 여기서 끝나지만 제품은 코드에서 시작".
- **핵심 인용**: "디자이너와 개발자 사이에 그 간격을 메우려고 나온 제품입니다. 클로드 코워크가 나온 이유랑 정확히 같은 맥락."
- **내 질문**: '디자인(코드)→클로드 코드로 제품화'는 앞 영상(잭피디의 GitHub→Vercel 배포)과 이어지는 파이프라인 — 디자인과 개발이 하나의 코드 흐름으로 연결되는 것 아닐까?

## TL;DR (5줄)

1. **2.0 변화**: ①크레딧 효율↑ ②**캔버스 직접 편집**(피그마처럼) ③디자인 시스템 등록 ④클로드 코드와 양방향 — 1.0의 진입장벽 해소.
2. **1·2단계**: 그냥 시키면 흔함 → **레퍼런스를 보여준다**(가들리·드리블·Awwwards 캡처, 피그마 무료 키트 첨부).
3. **3단계(★)**: **Firecrawl**로 내 사이트/잘 만든 사이트의 색·폰트·**규칙**을 추출 → **디자인 시스템 등록**해 재사용(무료 플랜, 커스텀 커넥터).
4. **4단계(★)**: **스킬로 전문가 감각 설치** — taste 스킬(다이얼 3개로 뻔함 방지) + 인터랙션 디테일 스킬(hover/press/스크롤 등장).
5. **포지셔닝**: 디자이너 대체가 아니라 **디자이너·개발자 사이**를 메움. 산출물은 실제 코드 → **공유 버튼으로 클로드 코드로 내보내 제품화**.
