# 무조건 이렇게 저장하세요! 옵시디언 + Claude + VS Code — 폴더 3개면 끝납니다

> 한 줄 요약: 벡터 DB 없이 **폴더 3개(RAW·DOCS·index.md)**와 **폴더별 CLAUDE.md**만으로 값싸고 단순한 RAG=개인 지식 시스템을 만든다. **같은 폴더**를 VS Code(클로드 작업용)와 옵시디언(읽기·관리용)이 동시에 바라보고, RAW에 막 던지면 Claude가 DOCS로 정리하고 index를 갱신 → 점점 자라는 세컨브레인.

## 1. 당신의 메모 2,000개가 쓸모없는 이유 · [0:00](https://youtu.be/blnnF9ubEVo?t=0)
- **3줄 요약**
  - AI로 매일 콘텐츠를 무수히 만들고 화면 여러 개 띄워 마구 생성하는 게 우리 현실 — 그런데 정리가 안 되면 쌓이기만 한다.
  - 이번 주제: 생성형 AI 시대에 꼭 필요한 **개인 지식 시스템**을 옵시디언·VS Code·클로드로 구축하는 법.
  - 핵심 구조 미리보기: VS Code(왼쪽)와 옵시디언(오른쪽)이 **같은 폴더**를 바라보고, 폴더마다 `CLAUDE.md`로 규칙을 둔다.
- **핵심 인용**
- **내 질문**
- 이 영상이 말하는 "개인 지식 시스템"이 바로 우리가 쓰는 옵시디언 세컨브레인(Insight Miner) 구조 그 자체 — 우리 `000-수집` 폴더 운영에 그대로 대입 가능하지 않나?

## 2. Obsidian + Claude = 10배 싼 RAG · [0:45](https://youtu.be/blnnF9ubEVo?t=45)
- **3줄 요약**
  - 정리 안 된 자료 더미는 **AI 건강도 해친다** — 요청이 오면 자료를 찾아 헤매며 토큰을 과소비하고 결과 품질도 떨어진다.
  - 보통 이걸 해결하는 RAG는 **복잡한 벡터 DB**가 필요해 돈·노력이 많이 들어 개인엔 부담.
  - 대안: 벡터 DB 없이 **폴더 구조만으로** AI가 데이터를 읽고 쓰게 만드는 값싼 RAG.
- **핵심 인용**
- **내 질문**
- "정리 안 된 볼트 = 토큰 과소비 + 품질 저하"는 우리 LESSONS의 컨텍스트 엔지니어링과 같은 통찰 — 폴더 구조 자체가 AI의 컨텍스트 절약 장치.

## 3. 도서관 비유 — 3단계 폴더 구조 · [2:10](https://youtu.be/blnnF9ubEVo?t=130)
- **3줄 요약**
  - **RAW** = 창고(인박스). 웹 자료·과거 작업물 등 콘텐츠가 생기면 **무조건 여기에 던진다**.
  - **WIKI(DOCS)** = AI가 RAW에서 문서를 가져와 잘 정돈·재구성해 읽기 쉽게 만드는 공간.
  - **index.md** = 리셉션/인포메이션 데스크. 새 세션·다른 AI가 와도 "그 파일 어디 있나요?"를 먼저 묻는 곳. 이렇게 **3개 폴더(공간)** 구조가 필요.
- **핵심 인용**
- **내 질문**
- RAW(원본)·DOCS(재구성)·index(안내)의 3분리는 우리 video2post의 assets(원문 자막)·notes(정리본)·gallery(인덱스)와 **정확히 같은 3단 구조**다.

## 4. 같은 폴더, 두 개의 창 — VS Code ↔ Obsidian · [4:30](https://youtu.be/blnnF9ubEVo?t=270)
- **3줄 요약**
  - 옵시디언 = 로컬 마크다운을 읽고 쓰는 노트 에디터(서버가 아닌 **로컬 컴퓨터 기반**), VS Code = 클로드와 연동돼 AI가 작업하는 공간.
  - 목표: 자료를 **마크다운 파일**로 만들어 두면, VS Code(AI 작업)와 옵시디언(편안한 읽기·관리)이 **같은 폴더**를 동시에 본다.
  - 즉 옵시디언은 사람을 위한 도구, VS Code는 컴퓨터(AI)를 위한 도구.
- **핵심 인용**
- **내 질문**
- "같은 폴더를 두 창이 본다"는 우리가 Drive 폴더(작업)↔옵시디언 볼트(노트)를 나눈 것과 닮았다 — 한 폴더를 공유하면 더 단순해질까?

## 5. Raw → Wiki → Master Index 실전 데모 · [7:00](https://youtu.be/blnnF9ubEVo?t=420)
- **3줄 요약**
  - 폴더에서 클로드 코드 실행 → "개인 지식 시스템(RAW·정리본·index.md)을 구축하려 한다"만 말해도 AI가 의도를 파악해 폴더 구조를 제안.
  - **"옵시디언으로 관리할 거다"라고 알려주는 게 핵심** — 그러면 AI가 일반 링크 대신 **위키링크**, 각 노트 상단에 **YAML 프론트매터**(태그·소스·생성일)를 쓰도록 설계를 바꾼다.
  - RAW에 다양한 원본(유튜브·독서 메모·음성 메모 등)을 넣고 **"정리해줘"** → DOCS 문서와 index.md가 자동 갱신, 옵시디언 그래프 뷰로 연결 확인.
- **핵심 인용**
- **내 질문**
- "옵시디언으로 관리한다"는 한마디가 출력 포맷(위키링크·프론트매터)을 바꾼다 — 우리 노트가 이미 프론트매터를 쓰니, 위키링크로 노트 간 연결을 더 적극적으로 걸면 그래프가 살아날 듯.

## 6. 토큰 비교 + 폴더별 CLAUDE.md = 다른 인격 · [11:30](https://youtu.be/blnnF9ubEVo?t=690)
- **3줄 요약**
  - **핵심은 `CLAUDE.md`** — 폴더마다 둘 수 있고, 클로드 코드가 그 폴더에서 일할 때 **가장 먼저 읽는 작업 매뉴얼**.
  - 예: RAW의 CLAUDE.md = "원본 그대로 보관, 임의 수정 금지, 최소 프론트매터" / DOCS의 CLAUDE.md = "원본을 소화해 내 언어로 재구성". 같은 AI라도 폴더 규칙에 따라 **다른 인격**처럼 동작.
  - 상위 폴더에도 CLAUDE.md를 둬 전체 가이드라인 제공 → 어떤 AI가 와도 폴더 규칙대로 작업.
- **핵심 인용**
- **내 질문**
- "폴더별 CLAUDE.md = 다른 인격"은 우리 video2post의 SKILL/LESSONS(작업 규칙)와 같은 발상 — 볼트의 `000-수집/011-보고따라해`에도 전용 CLAUDE.md를 두면 처리 규칙이 고정될까?

## 7. 정리 + 오늘의 CTA · [13:30](https://youtu.be/blnnF9ubEVo?t=810)
- **3줄 요약**
  - 옵시디언은 색상(클로드 사랑 → 주황색)·CSS·폰트(명조체)로 취향껏 스타일링 가능, 플러그인도 무수히 많음.
  - 진짜 핵심은 꾸미기가 아니라 **"이 두 도구로 어떤 그릇(체계)을 만들 것이냐"** — 작업 환경을 세팅해두면 AI가 스스로 공간을 관리하는 작업 파트너가 된다.
  - 이렇게 쌓인 게 **세컨브레인**. 다음 영상에서 한 단계 더 깊이 다룰 예정.
- **핵심 인용**
- **내 질문**
- "그릇(체계)을 먼저 만든다"는 우리가 파이프라인·갤러리·LESSONS를 먼저 세운 것과 같다 — 다음 영상(심화)도 큐에 넣어볼 가치.

## TL;DR (5줄)

1. **문제** — 정리 안 된 자료 더미는 AI가 찾아 헤매며 토큰 과소비 + 품질 저하.
2. **해법** — 벡터 DB 없이 **폴더 3개(RAW 창고 · DOCS 재구성 · index.md 안내데스크)**로 값싼 RAG=개인 지식 시스템.
3. **두 창, 한 폴더** — VS Code(클로드 작업) ↔ 옵시디언(읽기·관리)이 같은 폴더를 공유.
4. **CLAUDE.md가 핵심** — 폴더마다 두는 작업 매뉴얼. 폴더 규칙에 따라 AI가 다른 인격처럼 동작(RAW=보관만, DOCS=재구성).
5. **운영** — RAW에 막 던지고 "정리해줘" → AI가 DOCS·index 자동 갱신. 위키링크·YAML 프론트매터로 옵시디언 그래프가 자라는 세컨브레인.
