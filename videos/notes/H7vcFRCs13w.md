# 어디까지 갈지 감도 안 오는 Claude, 고퀄리티 모션그래픽 제작법부터 영상 생성 AI와 비교까지 총정리해 봤습니다.

> 한 줄 요약: 요즘 돌아다니는 모션그래픽 영상이 영상 AI가 아니라 **클로드가 코드를 짜고 그 코드를 렌더링한 결과**라는 데서 출발해, 디자이너가 **싱글 프롬프트 한 줄 → 공개된 상세 프롬프트 → 레퍼런스 영상 분석 → 이미지 에셋 + 코드 조합**까지 단계를 올려 가며 직접 만들어 보고 영상 생성 모델 결과와 눈으로 비교한 실험 기록이다. 싱글 프롬프트로는 **20분에 쇼릴 한 편**이 나오지만 코드로 만든 티가 나고 단조로웠으며, 같은 프롬프트를 영상 생성 모델에 넣으면 **한글 텍스트가 뭉개졌다**(크레딧은 **미니맥스 330 · 시덴스 1650**). 반면 **플랫 일러스트레이션 스타일은 영상 생성 모델이 훨씬 낫고 생성도 5분 정도로 짧았다**. **모션 용어까지 디테일하게 지시한 프롬프트 하나**를 넣으면 코드 쪽 결과도 몇 단계 올라가고, 레퍼런스 영상을 **구간·프레임 단위로 분석시키면** 원하는 연출을 재현할 수 있으며, 마음에 든 스타일은 **전역 스킬로 저장**해 재사용하고 **하이퍼프레임·리모션**으로 만들면 레이어별 수정이 된다. 마지막으로 **분석 → 계획 → 생성 → 검수 4단계** 프롬프트로 페이퍼 콜라주 스타일을 만들었는데 15초에 **2시간·670크레딧**, 1분짜리에는 **3시간 넘게** 걸려 효율 문제를 남겼고, 결론부는 **일러스트·캐릭터·복잡한 움직임은 영상 생성 모델**을 권하고, 코드 쪽은 **글자가 깨지지 않고 수정이 쉽다는 장점**으로만 꼽는다. 영상 스스로 **스폰서가 영상 생성 플랫폼 뉴테이크이고 유료 광고가 포함됐다**고 밝힌다.

## 1. ★코드로 짠 모션그래픽은 영상 생성 모델과 출발점이 다르다★ · [00:00](https://youtu.be/H7vcFRCs13w?t=0)
- **3줄 요약**
  - 요즘 돌아다니는 모션그래픽 영상들이 **영상 AI가 만든 것이 아니라 클로드가 코드를 짜고 그 코드를 영상으로 렌더링한 것**이라는 사실에서 출발한다. 영상 생성 모델은 **픽셀을 통째로 그려 내는 레스터 방식**인데 클로드는 **좌표와 숫자, 즉 코드로 설계도를 짜는 방식**이라 출발점부터 다르다고 정리한다.
  - 그래서 글자 하나, 도형 하나 움직이는 것도 **어디에 놓을지·얼마나 크게·얼마나 빠르게·몇 초에 등장할지를 모두 코드로 적어 줘야** 한다. 발표자는 이것이 파워포인트에서 날아오기 효과를 넣는 것과 비슷해 보여서 **「도형 몇 개 날아다니는 파워포인트 애니메이션 비싼 버전」이 나오는 게 아닐까** 의심했다고 털어놓는다.
  - 또 모션그래픽은 화려함이 아니라 **타이밍·이징·리듬·글자 가독성**을 봐야 하는 분야라 전부 코드로 구현하면 오히려 어색하고 딱딱해지지 않을까 우려했는데, 막상 해 보니 **잘 나오는 영상과 영 안 나오는 영상이 갈렸고** 그 경계를 직접 만들어 보며 찾는 것이 이 영상의 목적이라고 밝힌다.
- **핵심 인용**: "근데 이게 영상 AI가 만든게 아니고요. 클로드가 코드를 짜고 그 코드를 영상으로 렌더링한 겁니다."
- **내 팁**: 뒤에서 계속 쓰이는 **레스터(픽셀을 그린다) / 코드(좌표와 숫자로 설계한다)** 구분을 여기서 잡아 두면, 10장에서 글자가 뭉개지는지, 수정이 쉬운지가 왜 갈리는지 그대로 읽힌다.

## 2. 싱글 프롬프트 한 줄로 쇼릴 만들기 — 20분 결과물과 BPM 보강 · [01:52](https://youtu.be/H7vcFRCs13w?t=112)

  - 설정에서 당부하는 것이 둘이다. **모델은 오퍼스 5.5**를 고르고, 자막이 「출론 성능」이라 적은 설정을 **무조건 높음 이상**으로 둬야 한다는 것이다. 결과물은 **약 20분** 걸려 지정한 폴더에 들어왔고, 구독자수·조회수·영상 수·다루는 툴을 그래픽으로 시각화해 넣고 지난 영상들을 카드로 보여 준다.
  - 평가는 반반이다. 싱글 프롬프트로 20분에 만든 것 치고는 괜찮지만 **보자마자 코드로 만든 티가 살짝 나고**, 텍스트와 그래픽 요소로만 채워져 **비주얼이 단조롭고** 모션도 디테일하게 보면 아쉽다. 특히 배경음악이 AI가 만든 듯한 단조로운 전자음이어서, **음원을 직접 찾아 내려받고 그 음원의 BPM과 박자 강조 타이밍까지 분석해 비트에 맞춰 텍스트와 모션이 나오도록** 다시 지시하니 박자감이 살아나 키네틱 모션에 가까워졌다.

## 3. 같은 프롬프트를 영상 생성 모델로 — 뉴테이크 MCP와 크레딧 비교 · [04:06](https://youtu.be/H7vcFRCs13w?t=246)

- **핵심 인용**: "크레딧 사용 내역을 확인해 보면 미니맥스 H3가 330크레딧, 시덴스 2.5가 1650 크레딧을 소모한 것을 확인할 수 있습니다."

## 4. ★코드와 영상 생성 모델의 장단점, 그리고 잘 쓴 프롬프트 하나의 힘★ · [06:41](https://youtu.be/H7vcFRCs13w?t=401)
- **3줄 요약**
  - 먼저 코드와 영상 생성 모델의 장단점을 정리한다. 모션그래픽에서 자주 쓰이는 **플랫 일러스트레이션 스타일은 영상 생성 모델이 훨씬 잘** 만들고 생성 시간도 **대략 5분** 정도로 짧았지만 글자가 뭉개졌다. 코드 쪽은 움직임이 다소 아쉬웠으나 **프롬프트로 해결 가능해 보였고**, **그래픽·텍스트가 깨지지 않고 수정이 쉽다**는 점이 좋았다.
  - 다음 단계는 **잘 작성된 프롬프트**다. 여기서 「잘 쓴」이란 직접 모션그래픽 디자이너가 된 것처럼 **이징·카메라 무빙·타이밍·컬러까지 하나하나 디테일하게 지시**하는 것인데, 관련 지식이 없으면 어렵다. 그런데 **클로드로 뽑은 결과물과 그 프롬프트를 모아 놓은 사이트들이 생겨서**, 마음에 드는 것을 누르면 프롬프트가 통째로 공개돼 있어 복사해 붙이기만 하면 된다.
  - 결과는 **UI 완성도·그래픽·모션이 몇 단계씩 올라가** 코드로 만들었다고 말하지 않으면 모를 수준이었다. **이징**(움직임이 부드럽게 속도를 바꾸며 멈추는 느낌)이 살아 있고 클릭할 때 반응하는 마이크로 애니메이션도 들어갔으며, 움직이는 중에도 텍스트 가독성이 유지됐다. 같은 프롬프트를 **GPT 계열 모델**에도 넣어 봤는데(자막은 모델명을 「GPT6 아스트라」로 적고 설명란 타임라인은 「GPT」라고만 쓴다) 구성은 비슷했으나 **이징이 덜 들어가 모션이 뻣뻣하고 마이크로 애니메이션이 빠져**, 모션 센스는 여전히 오퍼스 5.5 쪽이 한 수 위로 봤다.
- **핵심 인용**: "마음에 드는 거 하나 누르면 오른쪽에 프롬프트가 아주 상세하게 통째로 공개되어 있습니다."
- **내 팁**: 영상은 **아스키 아트·픽셀 아트·드로잉·리소그래프·스톱 모션·다빈치 스케치·잉크 번짐**처럼 **규칙과 과정으로 잘 정의되는 스타일**이 코드가 특히 잘 만드는 쪽이라고 꼽는다. 싱글 프롬프트로 시도할 때 이 목록 안에서 고르면 성공률이 올라간다.

## 5. 레퍼런스 영상을 분석시켜 내 스타일로 만들기 · [09:39](https://youtu.be/H7vcFRCs13w?t=579)
- **3줄 요약**
  - 공개된 프롬프트를 쓰는 방식의 한계는 **기존 프롬프트를 그대로 두고 내 정보를 뒤에 덧붙이는 구조라 연출과 구성이 그대로**라는 점이다. 게다가 정말 괜찮은 모션그래픽은 디자이너가 애프터이펙트 같은 툴로 만든 것이 대부분이라 **애초에 프롬프트가 없다**. 그래서 **레퍼런스 영상을 AI에게 직접 분석시키는** 쪽으로 넘어간다.
  - 요즘 AI는 브라우저를 직접 돌아다닐 수 있어 **링크 하나만 줘도 알아서 영상을 분석**한다. 발표자는 한 채널의 영상을 골라(자막은 채널명을 「매틱스 미디어」로 적는다) 앞 5분만 보고 **이 스타일을 다른 내용에 쓰고 싶다**고 물었다. 그 레퍼런스를 두고 아이콘은 필요한 곳에만, **포인트 컬러 하나만** 쓰고 **그레이를 튀지도 죽지도 않게 아주 잘 쓴다**고 짚는다.

AI는 레퍼런스를 스크린 캡처로 떠서 분석하는데 **캡처가 촘촘할수록 분석이 잘 되고**, 그래서 프롬프트에 **전 구간·인트로 구간처럼 구간별 시간대를 정해 프레임 단위로 분석해 달라고** 요청한다. 그 결과 컬러·타이포그래피·카드 아이콘 스타일·배경·타임라인맵과 프레임 단위 모션까지 담긴 분석이 나왔고, 이를 바탕으로 지난 영상의 키네틱 타이포그래피 스크립트를 주고 설명 영상을 만들게 했다. 내레이션은 구글 AI 스튜디오에서 API 키를 받아 **제미나이 무료 TTS**로 넣었다. 1차 결과는 음성·배경·디자인이 깔끔했지만 **카메라가 거의 움직이지 않고 전환이 밋밋하며 장면을 잇는 일관된 요소가 없어 슬라이드 넘기는 느낌**이어서, 그 두 가지를 피드백으로 주자 영상미가 크게 개선됐다.
- **핵심 인용**: "그래서 프롬프트를 작성하실 때 전 구간이라든지 인트로 구간 또는 구간별 시간대를 정하고 프레임 단위로 디테일하게 분석을 해 달라 요청하는 겁니다."

2. **단계별 품질**: 싱글 프롬프트 한 줄은 20분에 쇼릴 한 편을 뽑지만 코드로 만든 티가 나고 단조로웠고, 이징·카메라·타이밍·컬러까지 지시한 상세 프롬프트를 넣자 결과가 몇 단계 올라갔다.
3. **코드 대 영상 생성 모델**: 플랫 일러스트는 영상 생성 모델이 훨씬 낫고 생성도 5분 정도로 짧았지만 한글 텍스트가 뭉개졌으며, 크레딧은 미니맥스 쪽 330 · 시덴스 쪽 1650으로 비싼 쪽이 한글에서 더 나빴다.
4. **레퍼런스와 재사용**: 레퍼런스 영상을 구간·프레임 단위로 촘촘히 분석시키면 원하는 연출을 재현할 수 있고, 다듬은 스타일은 전역 스킬로 저장해 재사용하며 하이퍼프레임·리모션으로 만들면 레이어별 수정이 된다.
5. **비용과 결론**: 분석 → 계획 → 생성 → 검수 4단계로 이미지 에셋과 코드를 결합하니 15초에 2시간·670크레딧, 1분짜리에는 3시간이 넘게 걸려, 일러스트·캐릭터·복잡한 움직임은 영상 생성 모델에 맡기는 쪽이 낫다는 결론으로 닫는다.
