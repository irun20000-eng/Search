# 바이브코딩할 때 기획력이 부족하다면 (바이브코딩 필수템 · 매니페스트)

> 한 줄 요약: 바이브코딩 결과물이 망하는 진짜 이유는 **"해줘"만 하고 기획을 안 해서** — 5턴·12턴 대화로 기능을 즉흥 추가하면 **코드가 꼬이고 재설계 지옥**에 빠진다(AI는 눈앞의 요청만 보고 다음을 모른다). 해법은 **앞단 기획을 세세히 먼저 주는 것**(데이터·예약 로직·예외처리·안 할 범위·소셜로그인 세부까지). 이를 도와주는 툴이 **매니페스트(Manifest)**: 질문지로 시작 → **PRD 문서**(실시간 수정) → **기능 명세서**(AI 생성+승인) → ★**거북이 아이콘으로 이중 검토**(개발·사업·UX/UI·QA·보안 관점에서 빠진 점·보안·연동 실패 공백을 짚음) → **유저 플로우**(브레인스토밍→그래프) → **와이어프레임**(데스크톱/모바일). 완성한 기획을 ★**AI와 연결(MCP)**로 클로드 코드·코덱스·GPT에 넘겨 "매니페스트 MCP로 계획 세워줘"→플랜 모드로 구현. 디자인은 **디자인 MD 사이트**에서 골라 카피해 보강. 추천 대상: **회사 ERP를 AI로 만들려는 사람**은 반드시 매니페스트로 기획 후 넘어가라.

## 1. ★핵심 문제 — "해줘"만 하면 재설계 지옥★ · [00:00](https://youtu.be/w5XO8zYGJ2Y?t=0)
- **3줄 요약**
  - 많은 사람이 AI에게 "해줘·구현해줘·계획해줘"라고 **말만** 함 → 바이브코딩 결과물이 나빠짐. 지금 시대엔 앞단계인 **기획(계획)**이 제일 중요.
  - 기획 없이 시작하면: 자동응답봇 구현→5턴째 캘린더 연동 수정→12턴째 노쇼 관리 추가 → **코드가 전부 꼬이고** 원한 기능이 안 나옴 → 재설계 지옥.
  - AI는 **눈앞의 요청만 보고** 다음에 뭘 만들지 이유가 없음. 즉흥 추가는 모호해지고 **곧 버그**. 로그인 방식 등을 AI가 임의 추측.
- **핵심 인용**: "12번째 대화 가게 됐을 때 또 노쇼 관리도 만들어야 돼라고 입력하면 코드가 전부 다 꼬여 버립니다."
- **내 팁**: 이 갤러리 orca·루프 엔지니어링·스펙주도개발(큰돌) 편이 강조한 '설계 먼저'와 정확히 같은 결 — 기획을 코드보다 앞세우는 게 공통 원칙.

## 2. ★해법 — 세세한 앞단 기획을 먼저 준다★ · [01:44](https://youtu.be/w5XO8zYGJ2Y?t=104)
- **3줄 요약**
  - 기획을 먼저 주면: 고객 데이터(이름·연락처·예약이력·노쇼 횟수·테이블), 예약 로직(**캘린더 API 연동 전제**), 예외처리(**노쇼 2회 이상 예약 버튼 숨김**)를 미리 설계 → 페이블·코덱스가 **확장 가능한 구조**로 계획.
  - 세세함이 중요: "소셜 로그인(구글·카카오·네이버) + 기본 아이디·아이디 찾기·회원가입"처럼 구체적으로.
  - 실전 기획 = 무엇을 만들지·데이터 저장·예외 케이스·**안 할 범위**까지 세우는 것.
- **핵심 인용**: "AI는 눈앞의 요청만 보고 판단하죠. 다음에 뭘 만들어야 될지 이유가 없습니다."
- **내 질문**: '안 할 범위까지 명시'는 이 갤러리 스펙주도개발(SDD)·루프 엔지니어링의 종료 조건과 같은 스코프 통제 — 기획이 곧 AI의 컨텍스트 경계 아닐까?

## 3. ★매니페스트 — PRD → 기능 명세 → 이중 검토★ · [03:29](https://youtu.be/w5XO8zYGJ2Y?t=209)
- **3줄 요약**
  - **매니페스트(Manifest)**: 기획을 도와주는 AI 툴. 질문지/자료 추천/기존 AI 연동/빈 프로젝트로 시작. 질문지로 하면 목표·타겟·용도를 물어 **PRD 문서**(한줄 정의·목표·배경·해결·차별) 생성(실시간 수정 가능).
  - PRD 기반 **기능 명세서**를 플로우로 확인, 핵심 기능은 AI 생성 or 직접 선택 → **승인**으로 하나씩 확정. 내가 표현 못한 것까지 도출.
  - ★**이중 검토**(거북이 아이콘): **개발·사업·UX/UI·QA·보안 관점**에서 심각/주의/제한으로 빠진 점 지적(연동 실패 시 공백, 데이터 보관·삭제 정책 부재, KPI 치우침). 해결 버튼 or 채팅으로 보완.
- **핵심 인용**: "개발·사업·UX UI 디자인·QA·보안 관점에서 검토를 합니다… 내가 빼먹은 부분이 없는 건가."
- **내 팁**: '작성(기획) ↔ 별도 관점 검토'는 이 프로젝트 품질 루프의 authoring≠review 원칙과 동일 — 매니페스트가 기획 단계에 리뷰 레인을 내장한 셈.

## 4. ★유저 플로우 + 와이어프레임★ · [13:05](https://youtu.be/w5XO8zYGJ2Y?t=785)
- **3줄 요약**
  - **유저 플로우 생성**: 캔버스에서 기능 브레인스토밍 먼저 → 진입(로그인→회원가입→메인 대시보드→레이아웃 편집→위젯 관리)·행동(필터·새로고침·기간 선택)을 **그래프**로 한눈에.
  - **와이어프레임**: 데스크톱/모바일 선택+유저 플로우 기반으로 로그인·회원·대시보드 프레임을 깔끔하게 생성(기존엔 핀터레스트 캡처를 클로드 코드에 줬던 걸 대체).
  - 여기까지가 PRD→기능명세→유저플로우→와이어프레임의 **기획 4종 세트**.
- **핵심 인용**: "핀터레스트 캡처해서 클로드 코드에게 많이 주었습니다. 근데 매니페스트 내부에서는 와이어프레임을 바로 고를 수가 있어요."
- **내 질문**: 매니페스트의 와이어프레임·플로우는 이 큐레이션 에디스(클로드 디자인 와이어프레임)와 겹치는 산출물 — 기획 전용 툴 vs 디자인 툴, 어디서 뼈대를 잡을지가 선택지 아닐까?

## 5. ★AI 연결(MCP)로 넘겨 구현 + 디자인 MD 보강★ · [16:30](https://youtu.be/w5XO8zYGJ2Y?t=990)
- **3줄 요약**
  - ★**AI와 연결**(우측 상단): GPT·클로드·코덱스·안티그래비티에 넘김. 클로드는 **터미널에서 MCP로 연결**(명령어 복사→클로드 코드 MCP 설정).
  - "매니페스트 MCP로 ERP 대시보드 구현 계획 세워줘, 유저플로우·기능명세·와이어프레임 보고, 계획은 **페이블5**로" → 클로드 코드가 **플랜 모드**로 기획→코덱스·옵스로 구현.
  - 디자인이 아쉬우면 **디자인 MD 사이트**에서 원하는 디자인(엔트로픽 등)을 골라 **디자인 MD를 카피**해 "디자인은 이 MD로" 추가. 회사 ERP를 AI로 만들려는 사람에게 강력 추천(요금 부담 적음).
- **핵심 인용**: "AI와 연결을 통해서 GPT나 클로드나 코덱스, 안티그래비티 이런 데 전부 다 넘길 수가 있어요. MCP를 통해서 연결."
- **내 팁**: '기획 툴 → MCP → 코딩 에이전트'는 이 큐레이션 모빈 MCP(Eric Park)·오르카와 같은 MCP 파이프라인 — 기획 산출물을 표준 인터페이스로 실행 도구에 넘기는 패턴.

## TL;DR (5줄)

1. **문제(★)**: "해줘"만 하고 즉흥 추가 → 코드 꼬임·재설계 지옥. AI는 눈앞 요청만 봄.
2. **해법(★)**: 데이터·로직·예외·안 할 범위까지 **세세한 앞단 기획**을 먼저.
3. **매니페스트**: 질문지→PRD(실시간 수정)→기능 명세(AI+승인)→★**이중 검토**(개발·사업·UX·QA·보안).
4. **산출물**: 유저 플로우(그래프)+와이어프레임(데스크톱/모바일)까지 기획 4종.
5. **실행(★)**: **AI와 연결(MCP)**로 클로드 코드·코덱스에 넘겨 플랜 모드 구현. 디자인은 디자인 MD로 보강. ERP 만들 사람 필수.
