# 클로드 코드 + 블로그 자동화 프로그램 만들기 — 웹 브라우저 자동화 원리 · GPT API · 모델 선택 가이드

> 한 줄 요약: 클로드 코드에게 "Electron으로 GUI + Playwright로 실제 브라우저를 띄워 키 스트로크로 입력"이라는 키워드를 주고 네이버 블로그 자동화 프로그램을 즉석 개발하는 과정. 로그인(헤더 위장·비번 마스킹) → GPT API로 글 생성(.env에 키 보관) → 키 스트로크로 에디터 입력까지. 핵심 교훈은 **모델 선택(리즈닝 유무·가격 100배 차이)**과 **"공부 목적·휴먼 터치·양산 금지"**라는 윤리 가드레일.

## 1. 인트로 — 왜 브라우저 자동화 방식인가 · [0:00](https://youtu.be/B_n38HKtBF4?t=0)
- **3줄 요약**
  - 네이버 블로그 자동화를 클로드 코드로 만든다. 도구는 Warp 터미널 + 클로드 코드.
  - 핵심 방식: **실제 웹브라우저를 띄워 버튼을 찾고 키 스트로크를 직접 날려** 글을 쓰게 함(캡차 등 로그인 장벽까지 자동화하려면 이 방식이 맞음).
  - 클로드 "2배 토큰 이벤트" 막날이라 토큰을 왕창 쓰며 시연.
- **핵심 인용**: "에이전트는 방향이고 미래 흐름이기 때문에 피할 수는 없다."
- **내 질문**: "버튼 클릭"이 아니라 "키 스트로크 주입"을 택한 건, 결국 사람의 물리 입력을 흉내 내는 게 가장 범용적이기 때문 아닐까?

## 2. 플랜 모드 + 핵심 키워드 주입(Electron·기능별 탭) · [1:25](https://youtu.be/B_n38HKtBF4?t=85)
- **3줄 요약**
  - `mkdir 네이버블로그` → `claude --dangerously-skip-permissions` → **Shift+Tab으로 플랜 모드**로 설계부터 논의.
  - **반드시 넣을 키워드**: "Electron으로 프로그램을 만들고 **기능별 탭**을 만든 뒤 각 기능에 맞는 코드를 작성한다."
  - 반복 작업은 스킬로 쪼개고, 스킬이 많아지면 **AGENTS.md**로 조직화하는 흐름까지 예고.
- **핵심 인용**: "기능별로 탭을 만든 뒤 그 기능에 맞는 코드를 작성해서 자동화를 꾀할 거야."
- **내 팁**: 빈 폴더에서 시작할 때 '아키텍처 키워드(Electron/탭 구조)'를 플랜 단계에서 못박아야 산출물 구조가 흔들리지 않는다.

## 3. 로그인 자동화 — 헤더 위장 + 비번 마스킹 · [2:26](https://youtu.be/B_n38HKtBF4?t=146)
- **3줄 요약**
  - 로그인 URL과 **입력 폼(form)**을 "네가 알아서 찾아"라고 지시. 자동화 브라우저는 헤더에 자동화 표식이 있어 네이버가 차단 → **"헤더에 사람처럼 값을 채워서 보내 줘"**로 우회.
  - 아이디·비번은 채팅에 직접 노출하지 않고 **일렉트론 프로그램의 로그인 탭 입력창**으로 받음.
  - 비번 입력 폼은 **별표(*)로 가려진 값으로 시각화** 처리 요청(시연·재사용 시 노출 방지).
- **핵심 인용**: "웹 브라우저 헤더에는 사람처럼 값을 좀 채워서 보내 줘."
- **내 질문**: 헤더 위장은 명백히 네이버 ToS 회피인데, 발표자가 반복해서 "공부 목적"을 강조하는 건 이 회색지대를 인지하기 때문 — 실무 재현 시 법적/약관 리스크를 어떻게 볼 것인가?

## 4. Playwright 채택 + 바이브 개발 → 로그인 성공 · [4:49](https://youtu.be/B_n38HKtBF4?t=289)
- **3줄 요약**
  - 브라우저 자동화 라이브러리는 **Playwright** 채택, 렌더러 UI는 **HTML/CSS/바닐라 JS**(리액트 미도입).
  - 로그인 정보는 저장 안 하고 매번 입력, 창은 테스트 위해 **보이게(headed)**. 플랜 → 바로 implementation.
  - 실행하니 실제 브라우저를 띄우고 **키 스트로크로 아이디·비번 입력** → 로그인 성공.
- **핵심 인용**: "냅다 브라우저를 띄우고 키 스트로크 입력하는 방식으로 아이디와 비밀번호를 입력하는 걸 볼 수 있습니다."
- **내 팁**: 로그인 후엔 버튼을 클릭할 필요 없이 **글쓰기 리다이렉트 URL로 바로 이동**시키는 게 알림 팝업 등 부작용이 적다.

## 5. GPT API 연결 — 글 생성 두뇌 + .env 키 보관 · [7:57](https://youtu.be/B_n38HKtBF4?t=477)
- **3줄 요약**
  - 글을 대신 써 줄 '두뇌' = **OpenAI GPT API**. platform.openai.com에서 카드 등록 후 **5달러 충전**(한글 5만 자 생성해도 1달러도 안 씀), 'Create secret key'로 발급.
  - 키를 클로드 채팅에 넣으면 위험 → **VS Code로 프로젝트 폴더에 숨김 파일 `.env` 생성**해 키를 직접 넣음. 프로그램이 실행 시 이 값을 읽음.
  - 지시: "글 쓰는 주체는 GPT API, 키는 `.env`에서 읽고, **프롬프트 입력 → 글 생성 단계까지만** 먼저 개발하자."
- **핵심 인용**: "이 키를 여기 채팅(클로드 코드)에다가 '내 키는 이거야'라고 얘기하면 … 별로 좋지가 않습니다."
- **내 질문**: 클로드 코드 채팅에 시크릿을 노출하지 않기 위해 `.env`+VS Code 수기 입력을 고집하는데, 팀 협업이라면 이보다 secret manager가 맞지 않나?

## 6. ★모델 선택 가이드 — 리즈닝 유무와 가격 100배 차이★ · [12:19](https://youtu.be/B_n38HKtBF4?t=739)
- **3줄 요약**
  - **번호가 높다고 좋은 게 아니다.** 'Compare models'로 **리즈닝(reasoning) 유무**를 확인 — 리즈닝 모델은 중간에 혼자 생각해 **느리고 훨씬 비쌈**.
  - 예: 미니급은 입력 100만 토큰당 **$0.4**, 리즈닝 모델은 **$30**(약 75배); 출력도 $1.6 vs $180 수준.
  - 블로그 글 생성은 고수준 작업이 아니므로 **GPT-4.1 mini** 채택 + "웹 검색으로 올바른 코드 사용법 확인 후 적용해 줘"(모델별 API 코드 상이) 지시.
- **핵심 인용**: "이 번호가 높다고 무조건 우리한테 좋지 않을 수 있다는 거예요."
- **내 팁**: 태스크 난도에 모델을 맞춰라 — 단순 생성엔 mini(빠르고 저렴), 리즈닝은 비용·지연이 수십 배라 남발 금지.

## 7. 키 로드 이슈 + 글 생성 성공 · [14:29](https://youtu.be/B_n38HKtBF4?t=869)
- **3줄 요약**
  - 코드 작성 후 `.env`(혹은 `.env.example`)에 **실제 `OPENAI_API_KEY` 수기 입력** → 저장.
  - 첫 시도에서 "키 설정 안 됨" → **프로그램이 시작 시 env를 로드**하므로 껐다 재실행하면 인식됨(Caps Lock/오타로 인한 로그인 실패도 관찰).
  - 재실행 후 프롬프트("바로바로 바이브 코딩 앤 커서 AI 도서 홍보 글") → **GPT-4 mini로 제목·본문 생성 성공**.
- **핵심 인용**: "프로그램을 실행할 때 이걸 로드하기 때문에 … 껐다가 프로그램을 다시 실행해 보겠습니다."
- **내 질문**: env를 런타임 시작 시 한 번만 로드하는 구조라, 개발 중 키 변경 때마다 재시작이 필요한 마찰 — hot-reload나 설정 UI가 더 낫지 않을까?

## 8. 에디터에 키 스트로크로 입력 + 마무리 · [17:05](https://youtu.be/B_n38HKtBF4?t=1025)
- **3줄 요약**
  - "'글 입력' 버튼을 추가해 제목·본문을 **키 스트로크로 네이버 에디터에 입력**, 속도는 올려도 됨"(빠른 타이핑은 서버 부하 아님) → 자동화 완성.
  - **복붙 대신 키 스트로크**를 쓴 이유: 붙여넣기는 에디터 양식(서식)이 깨지는 경우가 많음. (개행이 2줄로 되는 등 디테일은 사용자가 보정.)
  - 최종적으로 '발행 버튼까지 눌러 마무리'도 시킬 수 있으나, **임시 저장/비공개** 활용을 권장.
- **핵심 인용**: "복붙 방식으로 하게 되는 경우에 양식이 깨진 일이 되게 많아요."
- **내 팁**: 서식 보존이 필요한 리치 에디터 자동화는 클립보드 붙여넣기보다 키 스트로크가 안정적일 수 있다.

## 9. 윤리·전망 — 공부 목적·휴먼 터치·양산 금지 · [17:59](https://youtu.be/B_n38HKtBF4?t=1079)
- **3줄 요약**
  - 자동화하더라도 **자기 블로그에 맞게 수정하는 '휴먼 터치'는 필수**(발행·검수를 사람이 책임).
  - **글 양산·어뷰징 금지** — 상업성 강한 네이버 블로그, "어차피 다 네이버에서 검열할 것".
  - 전망: 번역·맞춤법 검사처럼 자동화 기능이 플랫폼 안에 흡수될 수 있음 → 원리를 공부해 두는 관점으로 접근하라.
- **핵심 인용**: "언제나 그 휴먼 터치를 하셔서 사람이 이 안에 들어가 있어야 되거든요."
- **내 질문**: '휴먼 터치 필수'가 실효성 있는 가드레일이 되려면, 도구 설계 차원(예: 발행 전 강제 리뷰 단계)에서 강제하는 게 낫지 않을까?

## TL;DR (5줄)

1. **아키텍처**: Electron(기능별 탭 GUI) + Playwright(실제 브라우저) + GPT API(글 생성). 클로드 코드 플랜 모드에서 이 키워드를 못박고 바이브 개발.
2. **로그인**: 자동화 표식 회피 위해 "헤더를 사람처럼" 지시, 비번은 별표 마스킹, 로그인 후 글쓰기 URL로 리다이렉트.
3. **키 보안**: 시크릿은 채팅에 넣지 말고 **VS Code로 `.env`에 수기 입력** → 프로그램이 런타임에 로드(변경 시 재시작 필요).
4. **모델 선택(★)**: 번호 높다고 좋은 게 아니다 — **리즈닝 유무로 속도·가격이 수십 배** 차이. 단순 글 생성엔 GPT-4.1 mini.
5. **입력·윤리**: 복붙은 서식 깨져서 **키 스트로크 입력**, 속도는 올려도 됨. 단 **공부 목적·휴먼 터치·양산 금지**가 핵심 가드레일.
