# 구글 또 앞서가네요.. 안티그래비티 최신업데이트~! 신규 플랜기능과 서브에이전트 구축방법 총정리~!

> 한 줄 요약: 구글 **안티그래비티 2.0** 의 업데이트를 화면으로 따라가며 정리한다(화자가 인트로에서 예고한 것은 다섯 가지인데, 윈도우 직접 설치는 영상에 끝까지 나오지 않고 로컬 모델은 오프라인 구동이 된다는 설명까지만 나온다). **슬래시 플랜**을 치면 에이전트가 즉각 작업하지 않고 전체 실행 계획을 단계별로 적어 주어 불필요한 단계를 지우거나 지침을 고친 뒤 승인할 수도 있고, **골뱅이(@) 맨션**으로 리서치·작성·QA 에이전트를 직접 불러 화자가 「말 전달 게임」이라 부르는 전달 왜곡을 건너뛸 수 있다는 것이 화자의 설명이다. **커스터마이제이션 탭의 플러그인 스토어**에서 구글 드라이브·캘린더를 더하기 한 번으로 붙이고, **제미나이 3.8 플래시 신규 하네스**로 파일 수정 출력 토큰이 40% 절감됐다고 소개하지만, 화자는 같은 자리에서 답변 실수가 아직 많으니 간단하고 확실한 업무만 맡기라고 덧붙인다.

  - 2.0 이 그 **헛발질을 원천 차단하는 장치**로 내놓은 것이 **플랜 모드**와 **서브에이전트 제어법**이라고 정리한다.

- **핵심 인용**: "그래서 에이전트한테 일 맡겨 놓고 자 10분 뒤에 왔더니 이상한 거 코드를 짜거나 이상한 거 만들어 놔서 멘붕 오신 적명이 있을 겁니다."
- **내 팁**: 영상은 성능 향상(완성도 6%·토큰 절감)도 함께 내세우지만, 플랜 모드와 맨션의 무게는 **잘못된 방향으로 작업이 폭주하는 것을 막는 쪽**에 있다. 품질이 아쉬워 떠났던 도구라면 이 관점으로 다시 재어 보는 편이 맞다.

## 2. ★플랜 모드 — 작업 전에 실행계획서를 먼저 받는다★ · [02:57](https://youtu.be/bZYnihtB1qM?t=177)

  - 결과는 오른쪽에 **실행 계획서**로 나오고, 목표·세부 진행 단계·주요 확인 및 검토 사항이 단계별로 적힌다. 사용자는 **불필요한 단계를 삭제**하거나 **세부 지침을 수정한 뒤 실행을 승인**할 수도 있다고 화자가 설명한다(단계를 지우는 화면은 영상에 나오지 않는다).
  - 권한 쪽에는 **상시 검토 · 자동 검토 · 소규모 작업 스킵**을 두어 작업 속도와 균형을 맞출 수도 있겠다고 말한다(무엇과 균형을 맞추는지는 화자가 더 밝히지 않는다).

- **내 팁**: 화자는 **무슨 질문을 해야 할지 떠오르지 않을 때**를 플랜 모드의 쓸모로 든다. 명령이 막연할수록 계획서를 먼저 받아 그 단계 목록을 지시문으로 되돌려 쓰는 쪽이 낫다.

## 3. ★골뱅이 맨션으로 서브에이전트를 직접 부른다★ · [07:15](https://youtu.be/bZYnihtB1qM?t=435)
- **3줄 요약**
  - 종전 구조는 메인 에이전트가 하위 작업자에게 지시를 **전달**하는 방식이어서 요구 사항이 왜곡되는 문제가 많았다고 화자는 말한다. 2.0 은 **골뱅이(@)** 로 하위 에이전트를 직접 호출해 그 단계를 건너뛴다.
  - 골뱅이를 누르면 **룰스**와 **컨버세이션**이 뜨고, 그 자리에 **리서치 에이전트 · 작성(라이터) 에이전트 · 검수(QA 인스펙터) 에이전트**를 호출명으로 등록할 수 있다. 등록은 **마크다운 형식**의 스킬 규격에 맞춰 이뤄진다.
  - 등록한 리서치 에이전트에 바이브 코딩으로 수익화한 사례를 조사하라고 맡기자 핵심 요약·세부 조사·레퍼런스가 붙은 보고서가 나왔고, 이어 작성 에이전트를 불러 기획서와 보고서를 쓰게 한다. 화면에 뜬 리서치 에이전트의 지시문은 **목표 구체화 → 다각도 정보 수집 → 팩트 체크 → 요약·핵심 발견 → 레퍼런스 출처 → 후속 단계** 순이다.
- **핵심 인용**: "기존에는 메인 에이전트에게 지시를 내리면 메인 에이전트가 하위 작업자에게 지시를 전달하는 말 전달 게임 구조로 인해서 요구 사항이 왜곡되는 문제가 많았다는 거죠."
- **내 질문**: 등록한 호출명은 어디에 저장되어 새 대화에서도 남는가. 영상은 새 채팅을 열어 이미 등록해 둔 QA 인스펙터가 불린다는 것은 보여 주지만, 그 정의 파일의 위치나 편집 방법은 다루지 않는다.

## 4. 스킬과 에이전트는 다른 것 — 3단계로 엮는다 · [14:00](https://youtu.be/bZYnihtB1qM?t=840)
- **3줄 요약**
  - 화자는 **스킬 = 하나의 도구**, **에이전트 = 외부 인력 한 명**으로 갈라 설명한다. 둘은 같은 채팅창에서 각각 슬래시와 골뱅이로 불린다.
  - 그래서 **조사 → 글쓰기 → QA 인스펙터 검수** 3단계로 이어 붙이면 산출물의 완성도를 더 높일 수 있다고 권한다.
  - 이렇게 되면서 **자막이 「제스」라 부르는 것이나 비서를 따로 등록하거나 프롬프트를 복사·붙여넣기 하는 방식이 필요 없어졌다**는 것이 화자의 정리다. 영상은 이것을 **클로드 코드와 「아스트라」**(자막 표기)가 이미 하던 방식에 안티그래비티가 합류한 것으로 본다.
- **핵심 인용**: "스킬 기능은 말 그대로 하나의 도구라고 생각하시면 되고 에이전트 같은 경우는이 폴더 하나의 외부 인력을 도입하는 거라고 보시면 되겠습니다."
- **내 팁**: 작성 에이전트가 내놓은 계획서에 적힌 **런칭 한 달 만에 130만 원** 같은 숫자는 영상의 주장이 아니라 **에이전트가 생성한 문서의 내용**이다. 화면에 떴다는 이유로 실적처럼 읽지 말 것.

## 6. 제미나이 3.8 플래시 신규 하네스 — 그리고 화자가 인정한 한계 · [18:05](https://youtu.be/bZYnihtB1qM?t=1085)

## TL;DR (5줄)
1. **플랜 모드**: 슬래시 플랜을 치면 즉각 실행 대신 단계별 실행계획서가 나오고, 단계를 지우거나 지침을 고친 뒤 승인할 수도 있다고 화자는 설명한다(지우는 화면은 나오지 않는다).
2. **골뱅이 맨션**: 리서치·작성·QA 에이전트를 호출명으로 등록해 직접 부르면, 메인 에이전트를 거치며 요구가 왜곡되던 「말 전달 게임」을 건너뛸 수 있다는 것이 화자의 설명이다.
3. **스킬 ≠ 에이전트**: 스킬은 도구 하나, 에이전트는 외부 인력 한 명 — 조사·작성·검수 3단계로 엮으라는 것이 화자의 권유다.
4. **플러그인 스토어**: 커스터마이제이션 탭에서 구글 드라이브·캘린더를 더하기 한 번으로 붙이고, 구글이 큐레이션한 도구만 올라와 있다고 소개한다.
5. **수치와 한계**: 신규 하네스로 파일 수정 시 출력 토큰 40% 절감·완성도 6% 향상을 들지만 컨텍스트 한도는 100만 → 13만이고, 화자 스스로 답변 실수가 많아 간단한 업무만 맡기라고 말한다.
