# 내가 본 걸 전부 기억하고 답까지 해주는 노트 — 옵시디언 + NotebookLM 세컨드 브레인

> 한 줄 요약: **'읽어 주는 역할'은 NotebookLM, '연결·보관 역할'은 옵시디언**에 맡겨 세컨드 브레인을 만드는 실전. 하나의 노트북=하나의 주제로 자료 3개(유튜브·논문·웹)를 넣고 **공통점→근거→차이점** 3단 질문으로 인사이트를 뽑고(출처 인용으로 할루시네이션 방지), **PARA(행동 기준 분류)** 볼트에 **내 언어로 요약+원문+태그**로 남기고 `[[백링크]]`로 연결. 나중엔 내 노트를 다시 노트북 소스로 올리는 **순환**으로 쓸수록 똑똑해진다.

## 1. 저장만 하고 못 찾는 이유 — 인트로 · [0:00](https://youtu.be/ZKJz6QNDPU0?t=0)
- **3줄 요약**
  - 읽은 기사·저장한 PDF·본 영상이 어디 있는지·무슨 내용인지 대부분 잊음 — "모으는 것까지는 누구나, 문제는 필요한 순간 못 꺼냄".
  - 오늘은 NotebookLM + 옵시디언을 연결해 리서치를 한 곳에 모으고 AI에게 질문까지 하는 시스템 구축.
  - 기능 소개가 아니라 **실제 주제 하나(집중력 관리법)**로 처음부터 끝까지 제작.
- **핵심 인용**: "문제는 한참 뒤에 그 정보가 딱 필요해진 순간 다시 꺼내지 못한다는 거죠."
- **내 질문**: 수집(input)은 쉬운데 인출(retrieval)이 병목 — 내 지식 시스템의 진짜 실패 지점도 '검색·재발견'에 있지 않나?

## 2. 왜 함께 쓰나 — 읽어주는 역할 vs 보관하는 역할 · [0:45](https://youtu.be/ZKJz6QNDPU0?t=45)
- **3줄 요약**
  - 노트앱은 **수동적 저장소**(찾아보지 않으면 잊힘). 해결 개념 = **세컨드 브레인**(티아고 포르테) — 기억·보관은 외부에 맡기고 뇌는 생각에 집중.
  - 필요한 두 역할: ① **읽어 주는 역할**(대신 읽고 비교하고 근거로 답) ② **보관 역할**(검색·연결되고 서비스에 종속 안 됨).
  - 노트앱이 수동적이었던 건 '읽어 주는 역할'이 빠졌기 때문 → NotebookLM에 그 역할을, 옵시디언에 보관을.
- **핵심 인용**: "기억하고 보관하는 일은 외부 시스템에 맡기고 뇌는 생각하는 데만 집중하는 것."
- **내 팁**: 도구 선택을 '기능'이 아니라 '역할 분담'으로 설계 — 읽기(NotebookLM)와 보관(옵시디언)의 분리가 이 시스템의 축.

## 3. NotebookLM 시작 + 주제 정하기 · [2:50](https://youtu.be/ZKJz6QNDPU0?t=170)
- **3줄 요약**
  - NotebookLM = 내가 넣은 자료 기반으로 답 → **할루시네이션↓ + 모든 답에 출처**. 설치 없이 브라우저+구글 로그인, '새로 만들기'.
  - 화면 3분할: 왼쪽 **소스**(자료) / 가운데 **채팅**(질문·답, 자료 기반) / 오른쪽 **스튜디오**(인포그래픽·슬라이드·오디오 결과물). "왼쪽 넣고→가운데 묻고→오른쪽 만든다".
  - **하나의 노트북=하나의 핵심 주제**(공통점 많을수록 답이 날카로움). 발표자는 '집중력 관리법'.
- **핵심 인용**: "하나의 노트북은 하나의 핵심 주제에 집중하는 것이 좋습니다."
- **내 질문**: '노트북=주제 하나' 원칙은 RAG의 컨텍스트 응집성과 같은 논리 — 잡다한 소스를 한 곳에 섞으면 답이 흐려진다.

## 4. 자료 넣기 — 유튜브·논문·웹 3종 · [4:45](https://youtu.be/ZKJz6QNDPU0?t=285)
- **3줄 요약**
  - 자료가 답 품질을 결정 → **직접 고른 자료**. 기준: 비슷한 내용 반복은 무의미, "이 자료가 내 질문·결과물에 도움될까" 자문.
  - 3종 투입: ① 유튜브(칼 뉴포트의 딥워크 재점검) ② PDF(25년 Behavioral Science 논문 — 자율휴식/포모도로/플로우타임 비교) ③ 웹(포모도로 실전 가이드).
  - 추가 시 자동 요약 + **추천 질문 3개** 생성(감 안 잡힐 때 유용, 단 그것만으론 부족).
- **핵심 인용**: "어떤 자료가 들어오느냐가 답변의 품질을 결정하기 때문에 직접 고른 자료를 넣어 보겠습니다."
- **내 팁**: 상충하는 관점(포모도로 옹호 vs 비판 논문)을 일부러 함께 넣어야 '차이점 질문'이 살아난다.

## 5. ★질문하는 법 — 공통점 → 근거 → 차이점 3단★ · [6:50](https://youtu.be/ZKJz6QNDPU0?t=410)
- **3줄 요약**
  - 질문 품질이 답 품질을 좌우. 순서: ① **공통점**(자료들이 입 모아 말하는 것=뼈대) ② **근거 파고들기**(궁금한 것 하나를 구체적으로 왜) ③ **차이점**(자료들이 갈리는 진짜 논쟁 지점).
  - 답변의 작은 숫자 = **인용** → 클릭하면 소스에서 근거가 강조 표시(원문 확인, 할루시네이션 방지의 핵심).
  - 실제 결과: 공통점(자기 방해가 외부 방해보다 해로움) → 근거(판단 자체가 뇌 부담) → **차이점(포모도로 효과 정면충돌, 논문 결론="정답 없음, 성격·난이도 따라 다름")**.
- **핵심 인용**: "자료 세 개를 넣고 차이점을 물었더니 그 주장이 어디까지 사실이고 어디부터 논쟁인지가 한 눈에 드러난 거죠."
- **내 질문**: '공통점→근거→차이점'은 어떤 리서치에도 쓸 수 있는 범용 질문 프레임 — 이 3단을 습관화하면 AI 리서치의 깊이가 달라지지 않을까?

## 6. 옵시디언 설치 + 볼트 + PARA 구조 · [11:13](https://youtu.be/ZKJz6QNDPU0?t=673)
- **3줄 요약**
  - obsidian.md에서 OS에 맞게 설치. **볼트**(보관함)=노트·연결이 담기는 공간, 실체는 내 컴퓨터 폴더 + **일반 텍스트(마크다운)** → 서비스가 사라져도 기록은 남음(종속 없음).
  - 담기 전 **구조부터**: 티아고 포르테의 **PARA**. 노트를 '주제'가 아니라 **'행동(언제 쓰는가)'** 기준으로 분류(주제별 폴더는 필요한 순간 정보가 흩어짐).
  - **Project**(마감·결과물 있는 진행 일) / **Area**(마감 없이 꾸준히 관리) / **Resource**(관심 주제·언젠가 쓸 자료) / **Archive**(끝난 것 치워둠). + Inbox 임시 폴더.
- **핵심 인용**: "이게 무엇에 관한 노트인가가 아니라 내가 이 노트를 언제 쓰는가를 기준으로 정리해요."
- **내 팁**: '집중력 관리법'은 지금 프로젝트가 아니라 관심 주제 → **Resource**에 저장(추후 관련 프로젝트 생기면 이동).

## 7. ★노트 작성법 + 백링크 + 순환★ · [16:17](https://youtu.be/ZKJz6QNDPU0?t=977)
- **3줄 요약**
  - 옮길 것 선별 3기준: 다시 찾아볼까 / 다른 생각과 이어질까 / 내 생각을 바꿨나. 제목은 출처가 아니라 **인사이트 자체**로. 본문은 **복붙 금지** → **내 언어로 요약·내 생각** + 아래에 원문·출처 + **태그**.
  - 노트끼리 `[[대괄호]]` **링크** → 문장 안에 '왜 연결됐는지'까지 남고, **백링크(양방향)**로 어느 쪽을 열든 생각이 따라옴. 수백 개 쌓이면 '아이디어끼리 서로를 부르는 그물망'.
  - **순환**: 옵시디언 노트(마크다운)를 다시 NotebookLM 소스로 올려(질문 관련 태그·폴더만) "내가 연결 못한 패턴은?" → NotebookLM이 내 생각을 읽고 답 → 결과를 다시 옵시디언에. 쓸수록 똑똑해짐.
- **핵심 인용**: "복사 붙여 넣기로 채우지 않는 겁니다. 내가 소화하지 않은 문장은 몇 달 뒤에 봐도 남의 글이거든요."
- **내 질문**: '내 언어로 재작성'이 핵심 노동인데, AI 시대에 이 '소화' 단계까지 자동화하면 그건 더 이상 나의 세컨드 브레인이 아니게 되지 않을까?

## TL;DR (5줄)

1. **역할 분담**: NotebookLM = 읽어 주는 역할(자료 기반 답+출처), 옵시디언 = 연결·보관 역할(마크다운, 종속 없음).
2. **NotebookLM**: 노트북 하나=주제 하나, 직접 고른 자료 3종(상충 관점 포함) 투입, 화면 3분할.
3. **질문 3단(★)**: 공통점(뼈대)→근거 파고들기→차이점(논쟁 지점). 인용 클릭으로 원문 확인.
4. **PARA 구조**: 주제가 아니라 **행동 기준** — Project/Area/Resource/Archive(+Inbox). 관심 주제는 Resource.
5. **작성·순환(★)**: 인사이트로 제목, **내 언어 요약+원문+태그**, `[[백링크]]`로 그물망. 내 노트를 다시 노트북 소스로 올리는 순환으로 쓸수록 똑똑해짐.
