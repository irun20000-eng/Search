# 읽을건 많은데 시간이 없다고? AI 웹 스크레이핑으로 1인뉴스 만들기

> 한 줄 요약: **n8n**과 HTML 처리에 특화된 **지나 AI 리더(Jina AI Reader)**, 그리고 **OpenAI 스트럭처드 아웃풋(Structured Outputs)**을 결합하여, RSS 미지원 웹 커뮤니티에서 불필요한 크롤링 코드 없이 게시물 목록을 정밀 수집하고, LLM 기반 관련도 점수 필터링을 거쳐 **개인 맞춤형 1인 아침 뉴스레터를 디스코드로 매일 자동 발행**하는 시스템 구축법을 제시한다.

## 1. ★지나 AI 리더(Jina AI Reader) 기반 노코드 웹 스크레이핑 혁신★ · [00:00](https://youtu.be/T5va0A7wvHk?t=0)
- **3줄 요약**
  - 기존 셀레늄(Selenium)이나 뷰티풀수프(BeautifulSoup) 코딩 없이 URL만으로 웹 텍스트를 추출한다.
  - **지나 AI 리더**는 복잡한 웹 문서를 LLM이 분석하기 최적화된 마크다운 구조로 자동 변환한다.
  - 지연 로딩 페이지의 경우 **타겟 셀렉터(Target Selector)** 옵션으로 특정 클래스 로딩을 기다려 추출한다.
- **핵심 인용**: "복잡한 웹페이지를 GPT나 클로드 같은 언어 모델이 처리하기 좋은 형태로 바꿔 준 것입니다."
- **내 팁**: 스크레이핑 대상 웹페이지의 구조가 변경되더라도 코드 전면 수정 없이 타겟 클래스명 하나만 교체하여 대응한다.

## 2. 작가 기반 콘텐츠 소비의 한계와 개인화 큐레이션 필요성 · [01:48](https://youtu.be/T5va0A7wvHk?t=108)
- **3줄 요약**
  - 구글 검색이나 플랫폼 알고리즘 추천을 넘어 특정 작가와 커뮤니티 중심의 정보 소비는 여전히 중요하다.
  - 하지만 구독 채널과 관심 매체가 과도하게 늘어나면서 **정보 과부하 및 탐색 피로**가 발생한다.
  - 작가의 분류 기준에 종속되지 않고 **나만의 관점과 필터링 기준**으로 정보를 재정렬하는 자동화가 필요하다.
- **핵심 인용**: "새로운 기술을 작가 기반의 정보 습득에 적용하면 생산성을 크게 높일 수 있습니다."
- **내 질문**: 텍스트 중심 커뮤니티 외에 이미지나 표가 다수 포함된 기술 블로그의 경우 지나 AI 리더의 데이터 손실률이 어느 정도인지 궁금하다.

## 3. ★RSS 및 HTTP 요청 노드를 활용한 n8n 데이터 수집 파이프라인★ · [04:45](https://youtu.be/T5va0A7wvHk?t=285)
- **3줄 요약**
  - RSS 지원 사이트는 **RSS 트리거 노드**를 연결하여 최신 게시물 정보를 즉각 추출한다.
  - RSS 미지원 커뮤니티(예: 파이토치 한국 커뮤니티)는 **HTTP Request 노드**와 지나 AI 리더 API를 결합한다.
  - 정기 실행 크론 트리거를 배치하여 **매일 아침 24시간 이내의 신규 글**만 자동 수집한다.
- **핵심 인용**: "우리가 관심 있는 페이지의 글 목록을 최소한의 코드로도 쉽게 가져올 수 있습니다."
- **내 팁**: n8n HTTP 노드 설정 시 헤더 값과 지나 AI API를 적절히 바인딩하여 백그라운드 크롤링 안정성을 확보한다.

## 4. ★스트럭처드 아웃풋(Structured Outputs) 기반 JSON 파싱과 시간 필터링★ · [10:43](https://youtu.be/T5va0A7wvHk?t=643)
- **3줄 요약**
  - **OpenAI 스트럭처드 아웃풋** 스키마를 정의하여 불필요한 사족 없이 제목, 링크, 날짜만 정확한 JSON으로 추출한다.
  - **스플릿(Split) 노드**로 개별 게시물을 쪼갠 뒤 **날짜·시간(Date & Time) 노드**로 24시간 이내 데이터만 선별한다.
  - 머지(Merge) 노드를 통해 시간 조건에 부합하는 유효 게시물만을 다음 파이프라인으로 전달한다.
- **핵심 인용**: "스트럭처드 아웃풋을 사용하면 이런 것들이 나오지 않도록 보장할 수 있습니다."
- **내 팁**: LLM 응답의 환각과 사족을 방지하기 위해 반드시 JSON 스키마를 강제하는 스트럭처드 아웃풋을 적용한다.

## 5. LLM 점수 기반 관심도 스코어링 및 디스코드 웹훅 자동 발송 · [13:45](https://youtu.be/T5va0A7wvHk?t=825)
- **3줄 요약**
  - 게시물 제목을 평가하여 거대언어모델(LLM) 관련성에 따라 **4점 만점의 사지선다 점수**를 부여한다.
  - 필터 노드를 통해 **4점 만점 기준을 통과한 핵심 게시물**만을 최종 선별한다.
  - 복수 소스(긱뉴스, 파이토치)를 에디트 노드로 병합하여 **디스코드 웹훅 채널**로 리포트를 자동 전송한다.
- **핵심 인용**: "저는 이 점수가 4점 만점에 4점인 경우에만 디스코드로 보내도록 할 것입니다."
- **내 팁**: 뉴스레터 필터링 시 LLM에 점수와 함께 판단 이유를 작성하게 하면 디버깅 및 프롬프트 튜닝이 수월해진다.

## TL;DR (5줄)
1. **지나 AI 리더**: 복잡한 웹페이지를 LLM 분석에 최적화된 마크다운 텍스트로 즉각 변환하여 수집한다.
2. **타겟 셀렉터**: 동적 로딩 웹사이트도 특정 클래스 타겟 셀렉터를 지정해 누락 없이 크롤링한다.
3. **스키마 강제**: OpenAI 스트럭처드 아웃풋을 적용해 제목·링크·날짜를 정형화된 JSON 데이터로 추출한다.
4. **LLM 관심도 필터**: 수집된 글의 주제 적합성을 AI가 4점 척도로 채점하여 최상위 게시물만 선별한다.
5. **디스코드 자동 발행**: 매일 아침 정해진 시간에 선별된 뉴스 목록을 디스코드 채널로 무인 자동 전송한다.
