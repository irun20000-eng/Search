# AI 디자인의 신세계, 피그마 메이크 실전 활용법 5가지 총정리!

> 한 줄 요약: 피그마 공식 튜토리얼에서 뽑은 **피그마 메이크 실무 5원칙**. ①**첫 프롬프트에 4요소**(무엇을·타겟 디바이스·핵심 기능·스타일/톤)를 앞쪽에 — 첫 프롬프트가 기초 공사. ②**오토레이아웃·레이어 네이밍이 정리된 디자인만 메이크가 이해** — 프레임 복사 시 오토레이아웃 필수. ③**한 번에 완성 안 됨 → 한 목적씩 작은 단위로 쪼개 반복 개선**(예: 히어로 배경 영상화를 3단계로). ④**디테일 다듬기 3방법**: 포인트 앤 에디트(간격·컨트라스트)·인라인 프롬프트(선택 요소만)·코드 직접 수정, 고급은 **가이드라인 파일**(코드 규칙·AI 행동 방식). ⑤**결과물을 디자인 자산으로 추출**(카피 디자인→피그마 붙여넣기, 빠진 이미지는 AI 더미로). 핵심 메시지: 메이크는 초보-숙련 격차를 줄이는 게 아니라 **기본기 가진 사람의 생산성을 폭발**시킴 — 차이는 툴 지식이 아니라 **구조 이해**.

## 1. ★원칙① 첫 프롬프트에 4요소를 앞쪽에★ · [00:00](https://youtu.be/ZAxrmoPm8AI?t=0)
- **3줄 요약**
  - 좋은 결과물을 뽑으려면 **메이크가 이해하기 좋은 상태**를 만들어야. 첫 프롬프트에 **①무엇을 만들지 ②타겟(디바이스) ③핵심 기능 ④스타일·톤**을 넣어라.
  - 첫 프롬프트가 **기초 공사** — 여기서 대충 쓰면 좋은 결과 어려움. 예: "웹 에이전시 랜딩 페이지, 히어로·서비스·연락처 섹션, 깔끔·전문적" (그냥 요청)은 기획서처럼 나옴.
  - 4가이드 반영본은 "중견 웹에이전시 반응형 랜딩, 애플 스토어 스타일 참고" + 참조 디자인을 붙여 요청 → 더 정확.
- **핵심 인용**: "첫 프롬프트가 기초 공사라서 여기서 대충 쓰면 좋은 결과물을 얻기가 어려워요."
- **내 팁**: '무엇·타겟·기능·톤'은 이 갤러리 VnMAgSd(오빠두엑셀 클로드 디자인)의 '콘텐츠 설계가 먼저'와 같은 원칙 — 도구만 바뀌고 프롬프트 설계 골격은 동일.

## 2. ★원칙② 오토레이아웃·레이어 네이밍이 메이크 이해의 전제★ · [02:00](https://youtu.be/ZAxrmoPm8AI?t=120)
- **3줄 요약**
  - 피그마 디자인 파일에서 프레임을 복사해 올 때 **오토레이아웃을 제대로 적용**해야. 메이크는 오토레이아웃이 안 됐거나 레이어 네임이 정리 안 된 디자인을 **잘 이해 못함**.
  - 참조로 HTML 피그마 플러그인으로 가져온 애플 스토어 디자인 파일을 붙이고 타겟·섹션·레이아웃·기술 요구사항까지 포함해 요청.
  - **메이크는 초보-숙련 격차를 줄이기보다 기본기 가진 사람의 생산성을 폭발**시키는 도구. 치트키로 쓰려면 결국 피그마 기본기부터.
- **핵심 인용**: "메이크는 오토레이아웃이 제대로 적용되지 않았거나 레이어 네임이 정리되지 않은 디자인은 잘 이해하지 못해요."
- **내 질문**: 'AI가 잘 읽는 구조로 입력을 정리'는 이 프로젝트의 노트 프론트매터·오토레이아웃과 같은 '기계가 파싱하기 좋은 형식' 원칙 아닐까?

## 3. ★원칙③ 한 목적씩 작은 단위로 쪼개 반복 개선★ · [03:22](https://youtu.be/ZAxrmoPm8AI?t=202)
- **3줄 요약**
  - **좋은 결과물은 한 번에 완성되지 않음**. 프롬프트로 틀을 만든 뒤 **한 번에 하나의 목적만, 작은 단위로 쪼개 반복**하면 전체 톤 유지하며 퀄리티 안정 상승.
  - 예: 히어로 배경 영상화를 3단계로 — 1단계 영상처럼 보이게 → 2단계 실제 영상 배경 → 3단계 실무 기준 추가.
  - 톤 조정도 "중간~어두운 명도, 파스텔 피하고 볼드한 그라데이션, 과감하지만 신뢰감"처럼 구체 재요청으로 수렴.
- **핵심 인용**: "한 번에 하나의 목적만 요청하고 작은 단위로 쪼개서 반복해서 개선하는 게 좋습니다."
- **내 팁**: '작은 단위 반복 개선'은 이 프로젝트 품질 루프(계획→제작→검수→수정 반복)와 동일 — 한 번에 완벽 대신 반복 수렴.

## 4. ★원칙④⑤ 디테일 다듬기 3방법 + 디자인 자산 추출★ · [05:01](https://youtu.be/ZAxrmoPm8AI?t=301)
- **3줄 요약**
  - **디테일 다듬기 3방법**: ①**포인트 앤 에디트**(요소 선택→간격·컨트라스트 빠르게) ②**인라인 프롬프트**(선택 요소만 프롬프트로) ③**코드로 직접 수정**. 고급은 **코드 탭에 가이드라인 파일 추가**(코드 스타일 규칙·AI 행동 방식·특정 요소 처리 기준)→내 스타일로.
  - 이전 버전 복귀는 **리스토어 디스 버전**.
  - **결과물을 디자인 자산으로 추출**: 우측 상단 **카피 디자인**→피그마 디자인 파일에 붙여넣기(레이어 안 보이면 확인·적용, 빠진 이미지는 피그마 AI 도구로 더미 삽입).
- **핵심 인용**: "코드 탭에서 가이드라인 파일을 추가하세요. 코드 스타일 규칙, AI가 지켜야 할 행동 방식… 메이크가 훨씬 더 내 스타일로 맞춰져요."
- **내 질문**: '가이드라인 파일로 AI 행동 규칙 고정'은 클로드 코드의 CLAUDE.md·디자인 시스템 등록과 같은 계열 — 도구마다 '규칙 파일'로 산출물을 통제하는 것 아닐까?

## 5. 결론 — 차이는 툴 지식이 아니라 구조 이해 · [06:22](https://youtu.be/ZAxrmoPm8AI?t=382)
- **3줄 요약**
  - 피그마 메이크는 강력하나 **코드·피그마 구조·디자인을 모르면 원하는 결과 내기 어려움**. 기본 구조 이해가 메이크를 잘 쓰는 전제.
  - 요즘처럼 AI 자동화 도구가 강해질수록 **차이를 만드는 건 툴을 많이 아느냐가 아니라 구조를 이해하고 있느냐**.
  - (영상 내 추천서: UXUI 디자이너를 위한 실무 피그마 — 오토레이아웃·컴포넌트·프로토타입·디자인 시스템을 실제 화면 예제로).
- **핵심 인용**: "결국 차이를 만드는 건 툴을 얼마나 많이 아느냐가 아니라 구조를 이해하고 있느냐입니다."
- **내 팁**: 이 결론은 큐레이션의 다른 피그마 편(디자이너 가든 기초 1시간)과 상보적 — 기초 구조를 다진 뒤 메이크로 생산성 폭발.

## TL;DR (5줄)

1. **첫 프롬프트 4요소(★)**: 무엇·타겟 디바이스·핵심 기능·스타일/톤을 앞쪽에. 첫 프롬프트=기초 공사.
2. **구조 정리(★)**: 오토레이아웃·레이어 네이밍이 된 디자인만 메이크가 이해. 프레임 복사 시 오토레이아웃 필수.
3. **쪼개서 개선(★)**: 한 번에 완성 안 됨 → 한 목적씩 작은 단위 반복(히어로 배경 영상화 3단계).
4. **다듬기 3방법+자산화**: 포인트앤에디트·인라인 프롬프트·코드 수정, 고급은 가이드라인 파일. 카피 디자인으로 피그마 자산 추출.
5. **결론**: 메이크는 기본기 가진 사람의 생산성을 폭발 — 차이는 툴 지식이 아니라 **구조 이해**.
