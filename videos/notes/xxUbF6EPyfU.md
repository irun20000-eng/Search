# Claude Code(클로드 코드) 서브에이전트 1초컷! 순식간에 전문 비서 만든다!

> 한 줄 요약: **Claude Code** 환경에서 메인 대화 세션의 **컨텍스트 윈도우**를 소모하지 않고 업무를 전문화하여 분임 처리하는 **서브에이전트**의 기본 개념을 정립하고, 프롬프트 명령을 통해 `.claude/agents` 폴더 내에 마크다운(.md) 정의 파일을 즉시 생성한 뒤, 구구단 웹 애플리케이션 개발 실습을 통해 작업 간 의존성 여부에 따라 **순차 파이프라인**과 **병렬 동시 실행** 및 복사본 병합 방식을 적절히 선택하여 개발 효율을 극대화하는 실전 활용법을 상세히 다룬다.

  - 생성된 서브에이전트는 프로젝트 폴더 내 `.claude/agents` 디렉터리에 **마크다운(.md) 파일** 형태로 자동 저장되어 관리된다.
  - 서브에이전트의 세부 작업 내용은 **컨텍스트가 완전히 분리**되어 메인 대화 세션으로 넘어오지 않으며 최종 완료 결과만 보고된다.

  - 사전 정의된 **CLAUDE.md** 컨텍스트가 존재하면 서브에이전트 생성 시 해당 규칙을 자동으로 참조하여 더 정교한 에이전트 정의 파일이 구성된다.

- **내 팁**: 서브에이전트를 요청할 때는 코드 점검 규칙, 성능 최적화 기준, UI 스타일 가이드 등 구체적인 점검 항목을 명시하면 훨씬 완성도 높은 `.md` 정의 파일이 생성된다.

- **내 팁**: 선행 작업의 결과물이 후속 작업의 필수 입력값이 되는 리팩토링이나 버그 수정 단계에서는 파이프라인 순서가 꼬이지 않도록 순차 실행을 명시해야 한다.

## 4. BTW 명령어를 통한 워크플로우 아키텍처 시각화 · [20:56](https://youtu.be/xxUbF6EPyfU?t=1256)
- **3줄 요약**
  - 메인 세션의 작업 진행 흐름을 방해하지 않고 부가 질문을 던질 수 있는 **BTW(By The Way)** 명령어를 활용할 수 있다.
  - BTW 질의를 통해 현재 백그라운드에서 구동 중인 서브에이전트의 **워크플로우 아키텍처 다이어그램**을 실시간으로 확인 가능하다.
  - 메인 에이전트와 서브에이전트 간의 독립적인 작업 처리 상태와 산출물 전달 경로를 다이어그램으로 시각화하여 점검할 수 있다.
- **핵심 인용**: "BTW 바이더웨이라고 해가지고 바이더웨이입니다 어 그런데 말이야 맥락과 관계없는 질문을 할 수가 있습니다 BTW 바이더웨이라고 어 이 워크플로우를 한번 도식화시켜서 아키텍처로 한번 보여 줄래 이렇게 한번 질문해 보는 거죠"
- **내 팁**: 서브에이전트가 복잡하게 연쇄 동작할 때 전체 실행 파이프라인의 병목이나 진행 상태를 파악하려면 BTW 기능을 활용해 아키텍처 구조를 점검하는 것이 효과적이다.

## 5. ★서브에이전트 병렬 작업과 파일 충돌 방지 전략★ · [24:03](https://youtu.be/xxUbF6EPyfU?t=1443)
- **3줄 요약**
  - 독립된 다중 기능(오답 노트, 타임어택 도전 모드, 보상 뱃지 시스템 등)을 동시에 추가할 때는 **병렬 실행 방식**으로 서브에이전트를 동시 구동한다.
  - 동일한 단일 파일(HTML)을 여러 에이전트가 동시 수정할 때 발생하는 파일 깨짐과 충돌을 방지하기 위해 각 에이전트가 **독립 복사본(Scratchpad)**을 생성하여 작업한다.
  - 모든 병렬 작업이 종료된 후 메인 시스템이 각 버전 간의 차이점(Diff)을 분석하여 최종 단일 파일(`merged.html`)로 자동 병합한다.
- **핵심 인용**: "서브에이전트는요 이 순차 작업으로 진행되는 게 있고 병렬 작업으로 진행되는 게 있습니다 이거 반드시 기억하셔야 됩니다 아주 중요합니다"
- **내 팁**: 병렬 에이전트 구동 시 메인 터미널에서 작업 도중 임의로 키를 입력하거나 프로세스를 중단시키면 병합 충돌이 발생할 수 있으므로 모든 복사본 작업과 Diff 병합이 완료될 때까지 대기하는 것이 안전하다.

## 6. 작업 의존성 판단 기준과 팀 에이전트 진화 방향 · [33:46](https://youtu.be/xxUbF6EPyfU?t=2026)
- **3줄 요약**
  - 작업 간 코드 파일이나 로직의 의존성 및 충돌 가능성이 있으면 **순차 작업**, 상호 독립적인 기능 구현이면 **병렬 작업**을 선택하는 것이 원칙이다.
  - 기존 서브에이전트는 메인에게만 단방향 보고를 수행하고 에이전트 간 상호 소통을 하지 않는 독립 전문가 구조를 가진다.
  - 향후 진화된 **팀 에이전트(Agent Team)** 시스템에서는 에이전트 상호 간 대화 및 메인 세션과의 실시간 중간 메시지 교환이 가능해진다.
- **핵심 인용**: "서브에이전트의 작업 내용을 보고 의존성이 있는지 판단하는 겁니다 그래서 의존성이 있으면 순차 작업 파일이 깨진다 충돌이 일어난다 순차 작업 그리고 서로 독립된 작업이다 뭐 기능 A B C 기능이 다르다 하면 병렬 작업으로 하는 것입니다"
- **내 팁**: 개발하려는 기능 단위가 서로 다른 컴포넌트인지 아니면 동일한 핵심 상태를 공유하는지 사전에 판단하여 순차와 병렬 실행 여부를 결정해야 파이프라인 오류를 줄일 수 있다.

## TL;DR (5줄)
1. **서브에이전트 역할**: Claude Code에서 특정 전문 분야를 위임받아 독립적으로 처리하는 하위 에이전트이다.
2. **컨텍스트 분리**: 세부 작업 과정이 메인 대화 세션에 누적되지 않고 최종 산출물 결과만 메인으로 전달된다.
3. **간편한 생성**: 자연어 프롬프트 명령 한 줄로 `.claude/agents` 경로에 마크다운 정의 파일이 즉시 구축된다.
4. **순차 및 병렬 실행**: 작업 간 의존성 여부에 따라 순차 파이프라인과 사본 기반 병렬 병합 방식을 전략적으로 활용한다.
5. **팀 에이전트 확장**: 에이전트 간 단방향 보고 구조에서 향후 상호 대화가 가능한 팀 에이전트 구조로 발전한다.
