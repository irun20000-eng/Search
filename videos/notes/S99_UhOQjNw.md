# 클로드 코드에 구글 연결하면 이런 일이 가능합니다 — 설치부터 실전까지 (GWS CLI)

> 한 줄 요약: **GWS CLI(Google Workspace Command Line Interface)** 하나를 설치하면 클로드 코드가 **Gmail·드라이브·캘린더·시트·슬라이드·독스 전체를 명령 한 줄로** 조종한다(무료). API/MCP를 서비스별로 따로 붙일 필요 없이 **만능 USB 포트**처럼 한 번에 — 장점은 **① 구글 API를 실시간 읽어 자동 업데이트 ② MCP 서버 내장 ③ 100+ 스킬 ④ 보안(모델 아머)**. 설치는 VS Code에 클로드 확장 → GWS 저장소 링크를 클로드에 주고 "설치 도와줘"(npm+gcloud+**OAuth 클라이언트 생성/로그인**). 실전: "30일 이메일 중요도 채점→읽음 처리·보고·뉴스레터를 독스에 요약", 유튜브 자막→독스 가이드(서식 스킬), **브랜드 가이드 참고 구글 슬라이드 생성**(클로드는 눈이 없어 스크린샷 스킬로 레이아웃 보정·반복 수정). 결국 **반복작업을 위임하는 1인 기업 시스템**.

## 1. 문제의식 + GWS CLI란 · [00:00](https://youtu.be/S99_UhOQjNw?t=0)
- **3줄 요약**
  - 3개 사업 혼자 운영 → 아침마다 탭 15개(Gmail·캘린더·뉴스레터·시트 정리). 진짜 문제는 시간이 아니라 **정작 중요한 일에 에너지가 없다는 것**.
  - 구글이 **자기 서비스 전체를 AI에 개방** → "안 읽은 이메일 중요도 채점, 낮은 건 읽음 처리, 중요한 건 보고, 뉴스레터는 독스에 요약"이 **명령 한 줄**(무료).
  - AI는 마우스 클릭은 못 하지만 텍스트 명령은 가능 → 구글이 서비스를 텍스트 명령어화한 것이 **GWS CLI(Google Workspace CLI)** = 워크스페이스 전체 리모콘.
- **핵심 인용**: "구글의 워크스페이스 전체를 한 줄의 명령어로 조종하는 리모콘."
- **내 팁**: 'AI는 텍스트만 친다 → 터미널이 문자창'이라는 설명은 앞 영상(인스타 자동화, 구글 연결)들의 공통 비개발자 눈높이 은유.

## 2. ★왜 API/MCP 대신 GWS — 4대 장점★ · [01:14](https://youtu.be/S99_UhOQjNw?t=74)
- **3줄 요약**
  - API/MCP는 Gmail·드라이브·캘린더를 **각각** 연결·인증·설정해야 함 → **GWS 하나면 전부**(만능 USB).
  - ① **자동 업데이트**(구글 API 목록을 실시간 읽어 명령어 자동 생성 → 구글이 기능 추가해도 별도 업데이트 불필요) ② **MCP 서버 내장**(명령어 하나로 클로드 코드가 구글 전체 사용) ③ **100+ 스킬**(이메일 요약·답장 초안·기간 파일 검색·시트 업데이트·문서 작성).
  - ④ **보안**: 구글의 **모델 아머**가 AI가 받는 응답을 자동 검사해 위험 차단.
- **핵심 인용**: "GWS 하나만 설치를 하면은 전부 다 됩니다. 만능 USB 포트 같은 거예요."
- **내 질문**: '서비스별 개별 연결 vs 통합 CLI'는 앞 영상(힉스필드 MCP 커넥터, 노션 커넥터)의 통합 지향과 같은 흐름 — 커넥터 파편화를 하나로 묶는 방향 아닐까?

## 3. 설치 — VS Code·클로드 확장·권한 모드·OAuth · [03:14](https://youtu.be/S99_UhOQjNw?t=194)
- **3줄 요약**
  - VS Code 확장에서 클로드 설치→로그인. (Git 필요 시 SCM 설치, 한글은 Korean Language Pack, 폴더 생성 후 3영역: 파일·작업·AI 패널.)
  - **권한 모드**: 기본은 매번 물어봄 → **Shift+Tab으로 Bypass Permission 모드**(설정에서 'bypass' 검색해 위험 권한 허용 체크)로 위임. 비개발자는 "네가 알아서 해 줘"로 진행.
  - GWS 저장소 링크를 클로드에 주고 "설치 도와줘" → npm 설치+gcloud+**OAuth**(클로드가 내 구글 접속 동의): 프로젝트 생성→OAuth 시작(외부)→**데스크탑 클라이언트 생성→JSON 다운→브라우저 로그인**. 오류 시 **에러 화면 캡처를 파일에 붙여 "왜 안 돼?"**.
- **핵심 인용**: "말로 해보고 안 되면 캡처를 통해서 처리를 하는 방식을 사용하시면 됩니다."
- **내 팁**: OAuth 클라이언트 생성·JSON·로그인은 사용자가 직접 다루는 자격증명 영역(앞 영상 인스타 토큰과 동일). 캡처→붙여넣기 디버깅은 이 배치의 공통 규칙.

## 4. 실전 — 이메일 자동 분류 + 유튜브→독스 가이드 · [09:32](https://youtu.be/S99_UhOQjNw?t=572)
- **3줄 요약**
  - "최근 30일 이메일 중요도 채점→낮은 건 읽음 처리, 높은 건 보고, 뉴스레터는 독스 요약" → 249개 분석: 즉시확인/낮은중요도 105개 읽음/뉴스레터 189개를 **구글 독스에 정리**(+내일 미팅 초대 확인 안내).
  - 유튜브 링크 → "이 영상 가이드 요약을 구글 독스에". **서식 개선 스킬**("볼드·서식 다르게 하는 스킬 있지 않아?")로 이모티콘·볼드·구분선 넣어 가시성 높은 문서.
  - 헛소리하면 "GWS 설치했다"를 다시 알려주면 됨.
- **핵심 인용**: "혹시 구글 독스 서식이나 볼드체 다르게 하는 스킬 있지 않아? 이런 식으로 질문을 해 주면."
- **내 질문**: '스킬이 있는지 클로드에 물어 적용'하는 방식은 앞 영상(GWS 100+ 스킬)처럼 도구 탐색 자체를 자연어로 하는 것 — 사용자가 스킬 목록을 외울 필요가 없는 구조 아닐까?

## 5. 구글 슬라이드 생성 + 클로드는 눈이 없다 + 철학 · [12:17](https://youtu.be/S99_UhOQjNw?t=737)
- **3줄 요약**
  - **브랜드 로고·가이드라인을 넣고** "유튜브 내용 슬라이드를 브랜드 가이드 참고해 구글 슬라이드로" → 감마/젠스파크 없이 무료로 브랜드 색감 슬라이드(12장).
  - **클로드는 눈이 없다**(코딩으로 만들어 결과물을 못 봄) → 로고 잘림·레이아웃 몰림 발생 → **스크린샷 스킬(get thumbnail)로 찍어 레이아웃 보정**, 마지막 잘림은 "이 부분 잘렸어"로 재수정.
  - 활용: 이메일 읽기 위임, 뉴스레터 주간 정리, 캘린더 알람(반죽 2시 발송), "오늘 할 일 말해 줘"로 컨설팅 메일 누락 방지. 철학: **자동화는 도구가 먼저가 아니라 브랜드·시스템 설계 후 반복작업을 AI에 위임하는 문제** → 1인 기업의 하루 3~4시간 시스템.
- **핵심 인용**: "자동화는 도구가 먼저가 아니라 내 브랜드와 시스템을 어떻게 설계하고 그중 반복 작업을 AI한테 맡길까? 이 위임의 문제다."
- **내 팁**: '클로드는 눈이 없어 스크린샷으로 보정'은 앞 영상(인스타 카드뉴스·롱폼 영상)의 '자기 결과물을 안 열어봄 → 사람 눈/캡처 검수 필수'와 정확히 같은 한계·해법.

## TL;DR (5줄)

1. **정체**: **GWS CLI** 하나로 클로드 코드가 Gmail·드라이브·캘린더·시트·슬라이드·독스 전체를 **명령 한 줄**로(무료).
2. **장점(★)**: ①구글 API 실시간 읽어 **자동 업데이트** ②**MCP 서버 내장** ③**100+ 스킬** ④**모델 아머 보안**. API/MCP를 서비스별로 붙일 필요 없음.
3. **설치**: VS Code 클로드 확장 → GWS 링크 주고 "설치 도와줘"(npm+gcloud+**OAuth 클라이언트 생성/JSON/로그인**). 오류는 캡처→붙여넣기.
4. **실전**: 30일 이메일 중요도 채점·읽음/보고/독스 요약, 유튜브→독스 가이드(서식 스킬), **브랜드 가이드 참고 구글 슬라이드**(스크린샷 스킬로 보정, 클로드는 눈이 없음).
5. **철학(★)**: 자동화는 도구가 아니라 **반복작업을 AI에 위임**하는 시스템 설계 → 1인 기업의 균형 있는 삶(하루 3~4시간 시스템).
